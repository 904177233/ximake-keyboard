# 墨语 App 图标方案（iOS）

> 交付物：`design/appicon/icon-1024.png`（1024×1024，iOS App Store / Xcode Asset Catalog 唯一必需尺寸）
> 生成脚本：`design/appicon/generate_icon.py`（Pillow，可重跑）
> 目标槽位：`AppIcon.appiconset/icon-1024.png`（Xcode 15+ 单尺寸方案，iOS 16+ 只需 1024）

---

## 1. 设计概念：一颗会说话的键帽

> **A keycap that talks.**

墨语是「会 AI 的输入法」，所以图标必须在一秒内同时说出两件事：**输入法** 和 **AI**。
我们不做「键盘 + 麦克风 + 星星」的元素堆叠（那是工具图标），而是让**一个图形承载两层语义**：

| 视觉元素 | 第一层读法 | 第二层读法 |
|---|---|---|
| 浅色圆角方块 | iOS 键盘上的一颗**键帽** | 一条**对话气泡**的主体 |
| 左下角伸出的短尾 | 键帽的溢光/阴影 | 气泡的**尾巴** |
| 方块中央的「墨」字 | 键盘上要打出的**中文字** | 品牌字 / 墨（书写、墨迹） |
| 右上角蓝色四角星 | 键帽上的**高光** | AI 的**星芒**（sparkle） |
| 深色底 | 深色键盘背景 | AI 的「深空」质感 |

一张图 = 键帽 × 气泡 × 中文 × AI。**没有一处装饰是多余的**。

### 1.1 为什么不用「键盘排线」或「麦克风」

- 键盘排线（4 行小键帽）在 40pt 下会糊成灰色噪点，与「墨语」的极简调性冲突；
- 麦克风是语音输入，会误导产品形态（墨语是打字 + AI 润色）；
- 对话气泡单独用太泛（所有聊天 App 都用），必须和「键帽」绑定才成立。

## 2. 图形构成（精确规格）

画布 **1024×1024**，坐标原点左上，单位 px（= 1x 下的 pt）。

```
┌──────────────────────────────────────────────┐ 0
│                                              │
│    ┌────────────────────────────┐   ✦        │ 182
│    │                            │  ╭──╮      │
│    │                            │  │主星│     │
│    │            墨              │  ╰──╯      │
│    │                            │            │
│    │                            │            │
│    └───╮────────────────────────┘            │ 842
│        ╰╮                                    │
│         ╰╮  ← 气泡尾巴                        │ 940
│                                              │
└──────────────────────────────────────────────┘ 1024
```

| 元素 | 参数 | 值 | 说明 |
|---|---|---|---|
| 画布 | 尺寸 | 1024 × 1024 | 满幅方形，**不画圆角** |
| 键帽 | 外接矩形 | x 182 → 842，y 182 → 842 | 边长 660，水平/垂直居中 |
| 键帽 | 圆角半径 | **148** | 148 / 660 = **22.4%**，与 iOS 图标 superellipse 圆角比例（22.37%）一致，视觉上「和系统图标同族」 |
| 气泡尾巴 | 顶点 | (278, 812) → (410, 788) → (304, 930) | 宽 132、高 118、上翘 24；与键帽**同一个 alpha mask**，无接缝 |
| 「墨」字 | 字号 | **343 px** | `1024 × GLYPH_RATIO(0.335)`；字面外接 343 × 311 |
| 「墨」字 | 基线位置 | 视觉中心 y = 481 | 略高于画布中心（466），补偿汉字重心 |
| 主星 | 中心 / 长臂 | (820, 212) / 120 | 右上，压在键帽边角上 |
| 小星 1 | 中心 / 长臂 | (652, 156) / 40 | 左上，飞出键帽 |
| 小星 2 | 中心 / 长臂 | (858, 396) / 34 | 右下，飞出键帽 |
| 星形 | 长臂:短臂 | 1 : **0.27** | 四角星，非五角星（iOS 系统的 sparkle 语汇） |

### 2.1 内容安全区

iOS 对图标做 superellipse 裁切，四角会被切掉。Apple HIG 建议内容放在 **中心 80% 区域**内。

| 检查项 | 实际 | 安全边界 | 结论 |
|---|---|---|---|
| 主体（键帽）外接 | x 182–842，y 182–842 | 102–922 | ✅ 在内 |
| 含气泡尾巴的可见范围 | x 182–842，y 182–940 | 102–922（y 需 ≤922） | ⚠️ 尾巴尖 940 超出 18px |
| 含小星 2 的可见范围 | x 至 892 | 102–922 | ✅ |

> **尾巴溢出的处理**：尾巴尖 (304, 930) 距离画布边缘 94px，落在圆角裁切的**下边中部**——superellipse 在正下方几乎不裁切（只裁四角），所以实际不会被切。但若后续要上 App Store 主图或做营销物料，建议把尾巴高度从 118 收到 **104**（尖端 y=916），彻底进入安全区。
> 当前脚本保留 118 是因为视觉上尾巴太短就读不出「气泡」了，**这是有意为之的取舍**。

## 3. 配色（hex，可直接给设计师/Figma）

### 3.1 底色与光

| 用途 | hex | RGB | 说明 |
|---|---|---|---|
| 背景·顶 | `#17171F` | (23, 23, 31) | 比纯黑暖一点，避免 OLED 上的「洞」感 |
| 背景·底 | `#09090E` | (9, 9, 14) | 近黑，让浅色键帽浮起来 |
| 墨晕光 | `#426ACC` | (66, 106, 204) | 中心 (512, 450)、半径 696、峰值 α=170、径向二次衰减、blur 4% |

### 3.2 键帽

| 用途 | hex | 说明 |
|---|---|---|
| 键帽·顶 | `#FFFFFF` | 纯白起，保证在深底上「发光」 |
| 键帽·底 | `#D0D8E8` | 极淡的冷蓝灰，是 tokens 里 `bg.key.function` 的同族色 |
| 键帽高光边 | `#FFFFFF` α=232，宽 5px | 沿 mask 内缘的环，模拟玻璃/塑料的倒角 |
| 落影 | `#000000` α=190，blur 24，offset (0, 22) | 让键帽「压」在背景上，不是贴上去 |

### 3.3 「墨」字与星芒

| 用途 | hex | 说明 |
|---|---|---|
| 墨色（字） | `#13192D` | 不是纯黑（`#000000` 在浅底上显脏），带一点蓝，与墨晕同色相 |
| 字落影 | `#1A2442` α=110，blur 11，offset (4, 9) | 让字「坐」在键帽上 |
| 星芒·上 | `#6AC6FF` | 浅蓝，取自 tokens `accent` 的高亮变体 |
| 星芒·下 | **`#0A84FF`** | **= tokens.json `color.light.accent` / `color.dark.accent`，全局品牌蓝** |
| 星芒外发光 | `#6AC6FF` α=175（主星）/ 145 / 135，blur 16 / 9 / 8 | 越大越柔，主星最亮 |
| 星芒描边 | `#061026` α=110，宽 5px | 深色描边让蓝星压在浅色键帽上也有剪影（无描边会糊） |

### 3.4 全局光效

| 用途 | 参数 |
|---|---|
| 顶部高光 | 画布上 46% 高度，`#FFFFFF` 从 α=20 线性衰减到 0（幂 1.7）—— `.ultraThinMaterial` 的平面化表达 |
| 四角暗角 | 28 层 1px 圆角描边，α 32→0，blur 12，圆角 250→110 |

> **禁止项**：不使用彩虹渐变、不使用霓虹色（`#FF00FF` 类）、不使用超过 2 个色相的渐变。全图只有 **蓝**（星芒/墨晕）和 **中性灰**（键帽/背景）两个色族。

## 4. 生成脚本

### 4.1 运行

```powershell
# Windows 本机
& python design\appicon\generate_icon.py
```

输出：

| 文件 | 尺寸 | 用途 |
|---|---|---|
| `icon-1024.png` | 1024×1024 | **AppIcon 唯一必需**，放入 `AppIcon.appiconset/` |
| `icon-180.png` | 180×180 | iPhone @3x 主屏图标 |
| `icon-120.png` | 120×120 | iPhone @2x 主屏图标 |
| `icon-80.png` | 80×80 | Spotlight @2x |
| `icon-60.png` | 60×60 | 通知 @3x |
| `icon-40.png` | 40×40 | 通知 @2x |

### 4.2 依赖

- Python 3.13（本机已装）
- **Pillow**（本机 11.1.0 已装；`pip install pillow` 即可，脚本无其它第三方依赖）
- 中文字体：脚本按顺序探测 `msyhbd.ttc`（微软雅黑 Bold）→ `msyh.ttc` → `simhei.ttf` → `Dengb.ttf` → `STSONG.TTF`，取第一个存在的。**若全部缺失会退化为默认字体（中文会显示为方块）**——在 Windows/macOS 上不会发生。

### 4.3 关键实现要点（改脚本时别踩）

1. **键帽和气泡尾巴必须用同一个 alpha mask**：`rounded_rectangle` 与 `polygon` 画在同一张 `L` 图上，再 `GaussianBlur(8)` + 阈值 128 回二值（磨圆尖角），然后**一次性** `paste(渐变, mask)`。分两次贴会出现一条可见接缝（v1 的 bug）。
2. **高光边 = mask − 内缩 mask**：内缩 5px 的圆角矩形取反，与 mask 做 `Image.composite` 得到环，环上 α=232。
3. **星芒必须有深色描边**：`MaxFilter` 膨胀 mask 得到外环，填 `#061026` α=110。没有描边时，浅蓝星压在白色键帽上对比度不足，40px 下会消失。
4. **不画圆角**：iOS 自动裁。若在设计稿里画了圆角，上架后会出现「圆角套圆角」的双层边缘。
5. `sparkle_poly(thin=0.27)`：短臂不能太细（v1 用 0.19，小尺寸下退化成一条线）。

## 5. 小尺寸可读性验收

iOS 主屏图标实际显示约 **60pt（180px @3x）**，Spotlight 更小。用 ASCII 灰度降采样逐级验证（本机 `read_image` 不可用，改用像素统计 + 字形轮廓比对）：

| 尺寸 | 观察 | 结论 |
|---|---|---|
| 1024 | 键帽、尾巴、墨字、三颗星全部清晰 | ✅ 设计稿成立 |
| 180 | 浅色键帽轮廓完整；「墨」字的「黑/土」上下结构可辨；主星为实心四角形 | ✅ 主屏可读 |
| 120 | 同上，墨字笔画略粘连但仍可辨为方块字 | ✅ |
| 80 | 墨字退化为深色笔画块，但「浅底 + 深字 + 右上一点蓝」的三段式仍成立 | ✅ 可识别 |
| 40 | 只剩「浅色圆角块 + 深色内芯 + 右上蓝点」 | ✅ 作为缩略图仍能被认出是「墨语」 |

> **降级设计原则**：图标不追求每个尺寸都好看，而追求**每个尺寸都能被认出来**。40px 下元素数从 4 降到 3（墨字笔画合并），但**色彩关系（深底/浅块/蓝点）始终不变**——这是品牌识别的最小充分条件。

## 6. 与设计系统的一致性

| 图标元素 | 对应的 tokens 键 | 值 |
|---|---|---|
| 星芒蓝 | `color.light.accent` / `color.dark.accent` | `#0A84FF` |
| 深色底 | 接近 `color.dark.bg.surface` | `#1C1C1E`（图标用了更深的 `#17171F→#09090E`，因为图标需要比 UI 更强的对比） |
| 键帽浅灰 | 接近 `color.light.bg.key.function` | `#ADB3BC`（图标用 `#D0D8E8`，更亮以在深底上「发光」） |
| 墨色文字 | 无直接对应（图标专用） | `#13192D` |

> 图标是**独立的一套美术资产**，允许与 UI tokens 有偏差；但 **accent 蓝必须完全一致**（`#0A84FF`），因为它是品牌的唯一强记忆点。

## 7. 落位与后续

### 7.1 Xcode 接入

```
ios/AIKeyboard/Assets.xcassets/AppIcon.appiconset/
├── Contents.json          # {"images":[{"filename":"icon-1024.png","idiom":"universal","platform":"ios","size":"1024x1024"}],"info":{"author":"xcode","version":1}}
└── icon-1024.png          # ← design/appicon/icon-1024.png 直接复制
```

iOS 16+ 用 Xcode 15 的「单尺寸」方案，**只需要 1024**，其余尺寸由系统生成。若工程仍是旧式多尺寸 `Contents.json`，按 §4.1 表格逐个放入。

### 7.2 不要做的事

- ❌ 不要把 `icon-180/120/80/60/40.png` 放进 `AppIcon.appiconset`（单尺寸方案下会报警告）
- ❌ 不要给 PNG 加 alpha 通道（App Store 会拒绝带透明的图标）——当前脚本 `img.convert("RGB")` 已保证无 alpha
- ❌ 不要在图标上放文字（「墨语」二字），小尺寸下必糊；「墨」单字是图形不是文字
