## 0. 速读：这次到底改了什么

用户真机反馈的原话是三件事：**候选栏常驻影响打字 / 前端丑 / 回车被占用而数字键没有**。三条都不是"再美化一点"能解决的，是结构问题。v2 只做四件事：

| # | 改动 | 一句话理由 |
|---|---|---|
| 1 | **候选栏 + AI 工具条 合并成一行 44pt「效用行」**，按状态换内容 | 两行 chrome 里，候选行在没候选时是空的（还占着品牌标语），工具行在打字时是干扰；合并后同一时刻只呈现"此刻唯一需要的东西" |
| 2 | **键盘总高 258 → 218** | 少 40pt，输入时看得见更多正文；这是合并两行的直接结果，不是砍功能 |
| 3 | **底行换成 123 / 空格 / emoji / 回车**，回车按 `returnKeyType` 变身 | 数字键是主流输入法标配；回车不该无脑抢主色，也不该在"发送"场景下显示"换行" |
| 4 | **材质与装饰收敛**：键盘内 0 处玻璃、0 个胶囊（除分页点）、阴影只留键帽 1pt 底边、主色只留 3 处 | v1 丑的主因不是配色，是"没有层级 + 满身胶囊 + 唯一的分层手段是玻璃" |

不变量（本文不推翻，继续有效）：`tokens.json` 七个基线组键名与值、`docs/02 §5` 契约、六套主题的色值、`Theme.swift` 现有常量、iOS 16.0 最低版本、键盘内字号不跟 Dynamic Type。

## 1. 设计方向

### 1.1 一句话定论

> **主风格：原生静默（Native Quiet）** —— 键盘上只有一种实体：**白色键帽**；除键帽与 0.5pt 发丝线之外，没有任何第二种材质、描边或渐变；AI 能力以"一行文字"出现，不以"一堆胶囊"出现。
>
> **唯一辅助手法：发丝分隔（Hairline）** —— 只用 0.5pt `separator` 线划分区域，不用阴影、不用玻璃、不用底色深浅来"分层"。

"借鉴其他输入法"借鉴的是**逻辑**（微信输入法 / 搜狗 / iOS 原生）：打字时候选优先、空闲时工具优先、回车随场景变文案、数字键在左下角。**不借鉴它们的像素值**，本文不引用任何竞品的具体尺寸，所有数字都是本仓库 390pt 画布上的推导结果。

### 1.2 气质词（三个，验收时用来反驳"还是丑"）

| 气质词 | 具体的可验收含义 | 反面（v1 的现状） |
|---|---|---|
| **安静** | 一屏之内彩色面积 ≤ 2 处；无动画元素常驻 | 84pt 玻璃 + 13 个胶囊 + 光晕 + 渐变遮罩 |
| **准确** | 每个间隙是 6 或 8，每个高度能整除到整数，底行横向四舍五入为 0 | 底行 382 ≠ 384，靠空格弹性吸收 2pt |
| **耐用** | 去掉一切"今年流行"的手法：玻璃、光斑、双色渐变、弹跳 | 键帽顶部 45% 白渐变 + ultraThinMaterial |

### 1.3 布局原则（网格）

1. **只有一套网格**：基线宽 390，左右 3pt → 内容宽 **384**；行距 **6**；纵向节距 = 键高 + 间距 = **39 + 6 = 45**。
2. **横向只有三个内缩值**：`3`（贴键区边缘）、`8`（条带内文字/图标）、`16`（面板内容）。出现 4、5、7、10、12、14 的横向内缩即为违规。
3. **纵向只有三个内缩值**：`4`（条带紧贴处）、`8`（面板四周）、`12`（卡片内）。出现 6、10、14、20 的纵向内缩即为违规。
4. **没有任何元素浮在别的元素之上**：v2 键盘内 0 个浮层、0 个 scrim、0 个阴影卡片。层级靠"顺序 + 0.5pt 线"表达。
5. **对齐**：所有左边缘对齐到 3/8/16 三条竖线之一；候选文字左 3（与第一列键帽对齐），工具 chip 左 8。

### 1.4 字体层级（键盘内只有 5 档）

| 档位 | 令牌 | 唯一用途 | 出现位置 |
|---|---|---|---|
| 22 / regular | `typography.key` | 字母、数字、符号 | 键帽 |
| 17 / regular | `typography.candidate` | 候选词（非首选） | 效用行候选态 |
| 17 / semibold | `typography.button` | **可点的动作文案**：回车标签、候选首选、生成按钮、结果卡标题 | 效用行 / 底行 / 面板 |
| 15 / regular | `typography.body` | 空格标签、面板说明、设置行标题、结果正文 | 底行 / 面板 |
| 13 / medium | `typography.chip` | 工具与语气 chip、脚注 | 效用行 / 面板 |
| 12 / regular | `typography.caption` | 候选序号、页码、状态提示（**仅此三类**） | 全键盘 |

规则：
- **禁止** 16 / 14 / 11 / 10 四个字号（v1 有 `.system(size: 10)` 两处，v2 清零）。
- 键盘内一律**固定字号**，不随 Dynamic Type（沿用 v1 §7 硬约束）。
- 字重只允许 regular / medium / semibold 三档；`semibold` **只给"点了会发生事"的文案**。

**为什么 v1 没有层级（实测证据）**：整个扩展 119 处 `.font(...)` 调用中，`Theme.fontCaption`（12pt）占 **47 处 = 39.5%**，`fontBody`（15pt）35 处，`fontChip`（13pt）11 处，17pt 合计 9 处，**22pt 键帽字号只出现 1 处**。也就是说：最该被看见的两层（键帽 22、候选 17）合计 10 次，而"细字说明"有 58 次。视觉结果必然是"满屏小字 + 一堆胶囊"，与配色无关。

### 1.5 有限色板（键盘内只用 7 个色）

| 用途 | 令牌 | 浅色 | 深色 | 出现次数上限 |
|---|---|---|---|---|
| 键区底 | `bg.keyboard` | #D1D3D9 | #2C2C2E | 1 |
| 键帽 | `bg.key` | #FFFFFF | #636366 | 26+4 |
| 功能键 | `bg.key.function` | #ADB3BC | #48484A | 5 |
| 效用行底 | `candidate.bar` | #FFFFFF | #3A3A3C | 1 |
| 主文字 | `text.primary` | #000000 | #FFFFFF | — |
| 辅助文字 | `text.secondary` | #3C3C4399 | #EBEBF599 | 仅 12pt 说明 |
| 主色 | `accent` / `accent.soft` | #0A84FF / #0A84FF1A | 同 | **3 处，仅此** |

**主色只允许出现在 3 个"动作位"**（比 v1 的 4 处再收一处，因为对话旋钮改成中性）：

1. **候选首选的底**（`accent.soft`，文字仍 `text.primary`）—— 它是"此刻最可能的动作"；
2. **发送态回车键的底**（`accent` 实底 + `text.onAccent`）—— 它是"提交且离开当前输入"的不可逆动作；
3. **面板主按钮**（生成 / 填入输入框，一屏最多 1 个）。

**选中态不用颜色，用字重**：工具 chip、语气 chip 的选中态 = 底色深一档 + `medium→semibold`，**不加主色、不加描边、不加外环**。这条是 v2 颜色收敛的关键——v1 的"选中就变蓝"制造了 13 处色块。

### 1.6 材质策略

**键盘内玻璃 0 处。** 证据：全扩展的三种材质只实现在 `KMGlassSurface.swift:77/79/81` 一个文件里，被引用 2 处——`KeyboardRootView.swift:134`（84pt chrome）与 `AIResultCardView.swift:45`（结果卡）。v2 的处理：

| 位置 | v1 | v2 | 理由 |
|---|---|---|---|
| 84pt chrome | `KMGlassSurface(level:.bar)` + ultraThinMaterial | **删除整个组件调用**，效用行用 `candidate.bar` 实色 + 底部 0.5pt 线 | 键盘背后是任意 App 内容，玻璃只会让候选字对比度随背景漂移（在白色文档上白字变灰、在深色视频上又发亮）；实色才可控 |
| 结果卡 | `KMGlassSurface(level:.card)` + thinMaterial | `bg.surface` 实色 + `radius.card` + **无阴影** | 卡片在页面内不浮起，玻璃的"透"没有层级可表达 |
| `KMGlassSurface` 组件 | 3 个 level 都在用 | 标记 **deprecated**：键盘内保留 API 但 0 调用；主 App 的 `GlassSurface.swift` 不受本文约束 | 少一个能用错的旋钮 |

**高光渐变清零**：v1 §8 允许键帽顶部 45% `#FFFFFF40→#FFFFFF00` 高光。v2 **删除**——真实 iOS 键帽是纯色平片，高光是 v1"塑料感/廉价感"的主要来源之一。`material.highlight` 令牌保留（主 App 卡片的 hero 图仍可用），键盘内 0 引用。

**阴影**：键盘内只保留 **键帽的 1pt 底边**（`shadow.key`: y=1, blur=0, opacity=0.18）。它渲染出来是一条 1pt 暗边而不是投影，作用是让密集网格里相邻键帽之间有一条"缝"。`shadow.card` / `shadow.glass` 键盘内 0 引用。

### 1.7 图形语言

1. **符号优先、图标退后**：键盘内的可识别语义一律用**汉字**表达（123 / 空格 / 换行 / 发送 / 搜索 / 前往 / 完成 / 润色 / 扩写 / 翻译 / 回复 / 生图）。只有 4 个例外用字形：`⌫` 退格、`⇧` 上档、`🙂` emoji、`🎤` 语音。
2. **不用 SF Symbols 的描边图标做主要语义**（v1 的 `globe`、`face.smiling`、`return` 三个 symbol 全部换成上述字形/汉字）。
3. **不用图形做装饰**：没有光点、光斑、粒子、飘浮小形状、渐变环。唯一的"呼吸"动画属于真实状态（AI 请求中）。
4. **圆角只有三档**：键帽 `radius.key 8`、面板/卡内元素 `radius.control 10`、卡片 `radius.card 16`。键盘内 **0 个 `Capsule`**（v1 实测 13 处，分布 7 个文件）。

### 1.8 禁止项清单（违反即打回）

1. 键盘内出现 `.ultraThinMaterial` / `.thinMaterial` / `.regularMaterial`（含通过 `KMGlassSurface` 间接出现）。
2. 键盘内出现 `Capsule()` / `radius.capsule`（唯一例外：主 App 的 `SegmentedTabs`）。
3. 任何元素使用 `LinearGradient` / `RadialGradient` / `AngularGradient`（含键帽高光、边缘渐隐遮罩）。
4. 任何"浮层"：overlay 面板、半透明 scrim、位置偏移的气泡。短语面板也不例外（见 §3.5）。
5. 任何 `blur` 阴影（`blur > 0`）用于键盘内元素。
6. 弹跳/回弹动画（spring 的 `dampingFraction < 0.8`）、`autoreverses` 装饰动画、无限旋转的 `ProgressView`。
7. 主色出现在 §1.5 三个动作位之外（含"选中就变蓝"、图标着色、分隔线着色）。
8. 16 / 14 / 11 / 10 号字（含 `.system(size:)` 直写）。
9. 底行出现第 5 个元素（小形象格已删除，见 §4.5）。
10. 候选栏与工具条的**高度不一致**、或切态时出现**纵向位移**（只允许交叉淡入淡出）。
11. 回车键文案固定写死为"换行"或"⏎"（必须按 `returnKeyType` 渲染，见 §4.4）。
12. 任何"品牌标语"占用效用行（v1 的「墨语 · 会 AI 的输入法」不再出现在键盘上）。

### 1.9 v1 为什么丑（诊断，附证据）

| 现象 | 证据 | 结论 |
|---|---|---|
| 没有层级 | 119 次 font 调用里 12pt 占 39.5%、22pt 仅 1 次 | 用户看到的是"一片小字"，视线没有落点 |
| 唯一的分层手段是玻璃 | 材质只在一个文件里实现，被 84pt chrome 独占 | 所有内容被迫挤进同一条玻璃带：44 候选 + 40 工具叠在一个高度里 |
| 胶囊泛滥 | 13 处 `Capsule` 分布在 7 个文件 | 圆角容器一个接一个，视觉噪声大、横向空间被吃掉 |
| 几何不闭合 | 底行 `42+42+156+88+30+6×4 = 382`，比 384 少 2pt，注释自认"由空格弹性吸收" | 网格在最后一行失守，底部三行右边缘对不齐，肉眼可察 |
| 数字键缺失 | `design/05 §3.2` 写的是 5 键底行（123 + 🌐 + 空格 156 + ⏎ + 形象格 = 384），代码与 `键盘布局规范 §2.4` 都是 4 键只有 🌐 | 文档级根因：05 的方案从未被实现，却被当成"已完成" |
| 面板页留白 | `.aiPanel` 把键区换成 168pt 面板，总高却按 258+168 报，`KeyboardShell` 的 `ZStack(.top)` 使内容顶对齐 | 结构上必然在面板下方留下 174pt 空白灰块（真机需复核），打开 AI 面板 = 键盘下沿一大片空 |
| 回车抢主色 | 无条件 `KeyStyle.accent` + `⏎` 字形 | 在微信里看到蓝色的"⏎"、在搜索框里也看到蓝色"⏎"，既不可读也不对 |

## 2. 新几何与高度算式

> 所有数字均为整数；每个数字后面写出算式；**任何一页的总高必须能由分项相加得到，不得出现"约"和"弹性吸收"**。

### 2.1 基线（三条，v2 全部几何由它们派生）

```
内容宽 384   = 390 − 3×2                     （screenPadding = keyHorizontalPadding = 3）
键高   39    = (174 − 6×3) / 4               （唯一解，v1 同）
行距   6     = keyGap                        （令牌）
```

### 2.2 效用行：44

```
效用行高 44 = 7 + 30 + 7        // chip 高 30 居中，上下各 7
          = 11 + 22 + 11        // 候选 17pt / 行高 22 居中，上下各 11
          = candidateBarHeight  // 复用 v1 令牌，不新增
```

44 同时是 `minTapTarget`，所以效用行内任何可点元素的命中高度天然达标。

### 2.3 键区：174

```
键区高 174 = 39×4 + 6×3 = 156 + 18
底行（第 4 行）同高 39，与字母行一致 —— 底行不是"特殊高的一条"
```

### 2.4 竖屏总高：218

```
键盘内容高 218 = 效用行 44 + 键区 174
```

对比 v1：`258 = 44 + 40 + 174`。**减掉的 40 是整条 AI 工具条**，它被折叠进效用行的第二个状态，没有丢功能。

含安全区（沿用 v1 规则：安全区另加，不并入内容高）：

```
iPhone 15 竖屏实际占用 = 218 + 34 = 252
iPhone 15 横屏实际占用 = 200 + 21 = 221
```

### 2.5 底行横向分配：精确 384，零弹性

```
384 = 42(123) + 194(空格) + 42(emoji) + 88(回车) + 6×3(间距)
    = 42 + 194 + 42 + 88 + 18
空格 194 = 384 − 42×2 − 88 − 18
```

**这是 v2 唯一一处"恰好闭合"的分配**：42+194+42+88+18 = 384，余 0。v1 是 382（余 2 丢给空格当弹性），v2 不允许。

### 2.6 效用行横向分配

**候选态**（与第一列键帽对齐）：

```
384 = 3(左) + 299(候选区) + 24(页码) + 6 + 44(旋钮) + 8(右)
299 = 384 − 3 − 24 − 6 − 44 − 8
```

**工具态**（左 8 起，图标贴右）：

```
384 = 8(左) + 272(5 个 chip) + 8(最小弹性) + 44(设置) + 44(语音) + 8(右)
272 = 5×48 + 4×8
48  = 26(2 字 × 13pt) + 11×2(左右内边距)
```

44 + 44 是**命中区宽**，不是视觉宽；设置/语音是"无底图标按钮"，视觉只有 17pt 字形。

### 2.7 各页总高（逐页算式）

| 页面 | v2 总高 | 算式（逐项） | v1 总高 | 差值 |
|---|---|---|---|---|
| `.letters` | **218** | 44 + 174 | 258 | −40 |
| `.numbers` | **218** | 44 + 174 | 258 | −40 |
| `.symbols` | **218** | 44 + 174 | 258 | −40 |
| `.emoji` | **218** | 44 + 174 | 258 | −40 |
| `.aiPanel` | **386** | 44 + 168 + 174 | 426 | −40 |
| `.result` | **398** | 44 + 180 + 174 | 438 | −40 |
| `.settings` | **386** | 44 + 168 + 174 | 426 | −40 |
| `.aiChat` | **442** | 44 + 180 + 44 + 174 | 438 | **+4** |
| `.voice` | **442** | 44 + 180 + 44 + 174 | 438 | **+4** |

三条必须背下来的规则：

1. **面板页永远"插在效用行与键区之间"**，键区保持可见、可用。v1 文档 §4.1 写"键区：未显示（被面板覆盖）"却又按 `258+168` 报总高，自相矛盾；v2 定为**插入**，矛盾消失。
2. **对话页与语音页是"原地换带"**：效用行 44 被同高的标题条 44 替换（内容淡入，无位移），所以顶边不动；多出来的 180+44 是消息区与输入行。
3. **`.aiChat` / `.voice` 的 442 比 v1 的 438 多 4**，因为标题条从 40 提到 44，与效用行严格等高——这是"换带不跳"的代价，4pt 值得。

### 2.8 面板与卡片的内部算式

**AI 面板（`.aiPanel` 的 168）**：

```
168 = 4(上) + 16(上下文条) + 4 + 44(输入框) + 4 + 44(语气行) + 4 + 44(生成按钮) + 4(下)
16  = typography.caption.lineHeight   // 恰好一行 12pt，不再"有时出现有时不出现"
44  = minTapTarget
```

**这是 v1 的真 bug 修法**：v1 的上下文预览行是**条件显示**的（`contextPreviewRow` 仅在非空时插入，高 20），同时把输入框从 44 压到 32 试图保持 168 —— 但 44→32 只省 12，加 20 反而净增 8，实测 `8+20+34+52+52+12 = 178`，被 `frame(height:168)` 裁掉 10pt。v2 用**槽位恒在**消除：上下文条永远占 16（无选中文本时显示"将处理光标前的整句"），输入框永远 44，任何状态都不改高度。

**结果页（`.result` 的 180）**：

```
180 = 8(上) + 164(卡片) + 8(下)
164 = 28(标题行) + 92(正文) + 44(动作行)
92  = 12(上内边距) + 4×20(四行 15pt/行高 20)
```

**设置页（`.settings` 的 168）**：

```
168 = 44(标题条) + 124(列表可视区)
124 = 44×2(两整行) + 36(第三行露出 36，提示可滚)
```

**对话页（`.aiChat` 的 442）**：

```
442 = 44(标题条) + 180(消息区) + 44(输入行) + 174(键区)
180 = 60×3   // 三组消息
60  = 10(上留白) + 40(两行气泡) + 10(下留白)   // 40 = 2×20
```

**语音页（`.voice` 的 442）**：

```
442 = 44(标题条) + 180(主区) + 44(操作行) + 174(键区)
180 = 8 + 84(波形) + 8 + 80(转写预览) + 0
80  = 4×20   // 四行 15pt
```

设置页与 AI 面板**同为 386**，因此"打开设置"与"打开 AI 面板"键盘不跳高度；结果页单独到 398，作为"结果比面板更重要"的 12pt 提示。

### 2.9 横屏：200 不变

```
横屏内容高 200 = 44(效用行) + 156(键区)
156 = 34.5×4 + 6×3 = 138 + 18
横屏面板总高 200 = 44 + 156   // 面板替换键区，不增加高度
```

**横屏为什么不涨**：竖屏 258→218 省下的 40 在横屏本来就不存在（v1 横屏只有一条 44 的候选行，没有 AIBar）。所以横屏总高保持 200、所有面板页也保持 200 —— 横屏垂直空间稀缺（可用高约 390pt），把面板做成"替换键区"比"顶起键盘"更合理。横屏 0.5pt 规则、圆角、阴影与竖屏一致。

### 2.10 响应式（三档宽度 + 横屏）

| 宽度 | 内容宽 | 键宽 | 底行 | 工具态 |
|---|---|---|---|---|
| 390（基线） | 384 | 33 | 42 + 194 + 42 + 88 + 18 = 384 | chip 48 / 间距 8 |
| 375 | 369 | 31.5 = (369−54)/10 | 42 + 179 + 42 + 88 + 18 = 369 | chip 44 / 间距 6：`8 + 244 + 21 + 44 + 44 + 8 = 369` |
| 320 | 314 | 26 = (314−54)/10 | 42 + 124 + 42 + 88 + 18 = 314 | chip 44 / 间距 6 / **隐藏语音键**：`8 + 244 + 10 + 44 + 8 = 314` |

- 375 的 chip：`244 = 5×44 + 4×6`，弹性 21 补在 chip 与图标之间；
- 320 的语音键隐藏后语义仍在（面板内仍有语音入口），且 `10` 是弹性，最小 8；
- 横屏键宽 = `(W×0.76 − 54)/10`（沿用 v1，844 → 58.7）。

### 2.11 高度只在一处算

`KeyboardViewController.updateHeight(for:)` 仍是**唯一**写高度的地方。v2 的改动只是把常量从 `258 + extra` 换成 `218 + extra`，并新增"面板页插入而非替换"的语义。`KMLayout.keyboardHeight(isLandscape:page:safeAreaBottom:)` 的返回值表在 §2.7 已给全。

## 3. 效用行（Utility Row）两态规格

### 3.1 共同骨架

```
高度 44（恒定，两态完全一致）
底色 candidate.bar（恒定，切态**不换底色**）
下沿 0.5pt separator（唯一的分隔手段）
横向 padding：候选态 3 / 8，工具态 8 / 8
```

**为什么底色恒定**：两条状态若连底色都变，切态就会"闪一下"，比位移更刺眼。只有内容交叉淡入，底色与高度不动，视觉上像"同一块屏幕换了内容"。

### 3.2 候选态（组字中，有候选）

| 元素 | 规格 |
|---|---|
| 左内边距 | 3（与第一列键帽左边缘对齐） |
| 候选区 | 横向滚动，无滚动指示器；项最小宽 48、项间距 20 |
| 候选字 | 17 regular `text.primary`；**首选**：17 semibold `text.primary` + `accent.soft` 底（radius 8，内边距 6，仅在文字后 8pt 处结束） |
| 序号 | 12 regular `text.tertiary`，仅当候选数 ≥ 3 时显示 |
| 页码 | 宽 24，仅 `pageCount > 1` 时出现；点 6×6、间距 5、最多 5 个；当前页 `text.secondary`，其余 `text.tertiary` |
| 对话旋钮 | 命中区 44×44，视觉圆 34，`radius.capsule` 禁用 → 用圆形 `Circle`（唯一允许的圆形，因为它是"旋钮"这一物理隐喻）；环 1.5pt `separator`，中心字形 16pt `text.primary` |
| 右内边距 | 8 |

旋钮状态：`idle` 中性环 / `active` 环 1.5pt `text.primary`（不加主色）/ `busy` 环 12% 呼吸 / `disabled`（无完全访问 / 未配置 / 离线）环与字形 `text.tertiary`。

### 3.3 工具态（空闲，无候选）

| 元素 | 规格 |
|---|---|
| 左内边距 | 8 |
| 能力 chip | 5 个：润色 / 扩写 / 翻译 / 回复 / 生图；48×30；radius 8；底 `bg.surfaceElevated`；13 medium `text.primary`；**无图标** |
| chip 选中 | 底 `bg.key.pressed`，13 semibold；无主色、无描边、无外环 |
| 弹性 | chip 与图标之间 ≥ 8，多余宽度全给这里（右侧图标贴右） |
| 设置 | 44×44 命中区，17pt `slider.horizontal.3` 字形（唯一允许的 SF Symbol 之一），`text.primary` |
| 语音 | 44×44 命中区，🎤 20pt 字形 |
| 右内边距 | 8 |

**为什么 chip 不带图标**：5 个"图标 + 2 字"chip 需要 `72×5 + 32 = 392 > 284`（可用宽），必然横向滚动 + 边缘渐隐遮罩（v1 的做法）；纯文字 5 个只要 272，**不需要滚动，也就不需要渐变遮罩**。这是"删一个装饰，同时修一个几何"的例子。

### 3.4 切态规则（何时换内容）

| 条件 | 状态 | 判定时机 |
|---|---|---|
| `composingText` 非空 且 候选数 ≥ 1 | 候选态 | 立即（下一帧） |
| `composingText` 为空（上屏/取消） | 工具态 | 延迟 500ms（防止"打一个字→上屏→闪回工具条"的抖动） |
| `composingText` 非空 但 候选数 = 0 | 候选态（空态） | 立即 |
| 面板打开（`.aiPanel`/`.result`/`.settings`） | 工具态，且对应 chip 选中 | 立即 |
| `.aiChat` / `.voice` | 该行被同高标题条**替换** | 立即 |

500ms 延迟是 v2 唯一一个"刻意等待"，理由是**因果**：用户按下空格上屏后 500ms 内极可能继续打下一个字，此时若已经切成工具条再切回候选，会出现两次淡入淡出（0.15 + 0.25），比"晚 500ms 出现工具条"更烦。

### 3.5 空态与降级

| 场景 | 候选态空态 | 工具态降级 |
|---|---|---|
| 无候选、无联想 | 「无匹配 · 长按退格清空」12 regular `text.secondary` | — |
| 完全空闲（v1 的品牌标语位） | — | 正常显示 5 个能力 chip（**不再显示品牌标语**） |
| 无完全访问 | 正常（候选不联网） | chip 全部 `opacity 0.4` + 点按弹「需要在"设置 › 键盘"中开启"允许完全访问"，AI 才能联网」 |
| 未配置服务商 | 正常 | chip 可用，点按弹「还没有配置 AI 服务 · 点此设置」 |
| 离线 | 正常 | chip 可用，点按弹「当前离线 · 联网后可用」 |
| 短语面板打开 | — | **键区原位替换**（不浮层、不加 scrim），效用行保持工具态 |

三条文案必须逐字复用（v1 §5 已定，v2 不改）：上文表格中的三句。

## 4. 底行新规格

### 4.1 123 键（替换 v1 的地球键）

| 项 | 规格 |
|---|---|
| 位置/尺寸 | 最左，42 × 39，radius 8 |
| 底色 | `bg.key.function` |
| 标签 | `123`，15 regular `text.primary`；进入数字页后同键位显示 `ABC` |
| 点按 | 切 `.numbers`；数字页里点 `ABC` 切回 `.letters` |
| 长按（0.35s） | 弹出**输入法切换**（等价 `handleInputModeList(from:with:)` 的系统菜单）；触感 `.medium` |
| 角标 | 仅当 `needsInputModeSwitchKey == true` 时，键右上角 6pt 处一个 10pt `globe` 字形、`text.tertiary`，**不占宽、不可单独点** |

**为什么这么做**：主流输入法左下角是数字键，切换输入法是低频动作；把低频动作降级为长按，换来一个高频键位。`needsInputModeSwitchKey == true` 时用 10pt 角标提示"这个键还能长按切输入法"，解决可达性发现成本；`false` 时角标不出现（不需要切换就不提示）。

**备选（仅当审核或真机反馈要求独立 globe 时启用，不默认实现）**：

```
384 = 42(123) + 144(空格) + 44(globe) + 42(emoji) + 88(回车) + 24(4×6)
空格 144 = 384 − 42 − 44 − 42 − 88 − 24
```

代价是空格从 194 掉到 144（−26%），所以**默认不采用**。

### 4.2 空格键

| 项 | 规格 |
|---|---|
| 尺寸 | 横向弹性，390 宽时 194 × 39，radius 8 |
| 底色 | `bg.key`（白） |
| 标签 | `空格`，15 regular **`text.primary`**（v1 是 `text.secondary`，在白底上只有 3.45:1，不达 AA，v2 改主文字） |
| 点按 | 插入空格；长按不定义（沿用 v1） |

### 4.3 Emoji 键

| 项 | 规格 |
|---|---|
| 尺寸 | 42 × 39，radius 8 |
| 底色 | `bg.key` |
| 图形 | 🙂 20pt（emoji 自渲染，不用 SF Symbol） |
| 点按 | 切 `.emoji`；emoji 页内同键位显示 `ABC` |

### 4.4 回车键：按 `returnKeyType` 变身

| `returnKeyType` | 标签 | 底色 | 字色 | 语义 |
|---|---|---|---|---|
| `.send` | 发送 | `accent` | `text.onAccent` | 提交（不可逆） |
| `.search` | 搜索 | `accent` | `text.onAccent` | 提交（不可逆） |
| `.go` | 前往 | `accent` | `text.onAccent` | 提交（不可逆） |
| `.done` | 完成 | `accent` | `text.onAccent` | 提交（不可逆） |
| 其余（`.default` / `.next` / `.continue` / `.join` / `.route` / `.emergencyCall` / `.yahoo` / `.google` / `.line`） | 换行 | `bg.key.function` | `text.primary` | 可逆（只是插入一个换行） |

| 项 | 规格 |
|---|---|
| 尺寸 | **88 × 39 恒定**（宽度不随文案变，避免底行跳动），radius 8 |
| 字号 | 17 semibold（`typography.button`） |
| 长按（0.35s） | 无论哪个状态都插入换行 `\n`（v1 的逃生通道保留） |
| 触感 | 点按 `.rigid`，长按 `.medium` |

**为什么只有 4 个状态用主色**：`send / search / go / done` 的共同点是"离开当前输入"——按下去焦点会走、内容会提交，用户需要一次"这是终点"的确认；`换行` 只是插入一个字符，可撤销、不离开，用中性键帽色即可。v1 无条件用蓝色 + `⏎` 字形，等于对两种情况说同一句话。

**对比度**：`text.onAccent`(#FFFFFF) 在 `accent`(#0A84FF) 上 3.65:1。17pt semibold 属 WCAG 大字号（≥14pt bold），阈值 3:1，**达标**；若实现方把标签降到 15 regular，必须改用 `accent.pressed`(#0070E0, 4.79:1)。六套主题的实测值见 §5.5。

### 4.5 小形象角落格：**删除**

结论：**删掉底行的小形象格（宽 30/26），小形象迁到"键盘内设置页顶部"与"主 App 主题页"。**

| 理由 | 量化 |
|---|---|
| ① 挤占输入面积 | 它在场时空格被压到 156，删除后回到 194：**+38pt = +24%** 的空格宽度 |
| ② 破坏几何闭合 | `42+42+156+88+30+24 = 382 ≠ 384`，v1 靠"空格弹性吸收 2pt"掩盖；删除后 `42+194+42+88+18 = 384` 恰好闭合 |
| ③ 命中不达标且不可访问 | 视觉 30×39、`accessibilityHidden`，低于 `minTapTarget 44`，屏幕阅读器读不到——它是装饰占了一个键位 |
| ④ 用户从未提及 | 用户明确列出的是"数字键缺失 / 回车被占用"，小形象是 v1 的自选动作；v2 的原则是"装饰不得挤占输入通路" |

迁移方式（视觉与品牌不丢）：
- 键盘内 `ExtensionSettingsSheet` 顶部 44pt 行：左 22pt 形象 + 右「墨语 · <当前主题名>」，静态无动画；
- 主 App `ThemeSettingsView` 的预览卡（320×212）继续展示形象与主题；
- `KMMascot` 组件与 8 个符号保留，仅从底行撤出。

### 4.6 数字页 / 符号页的底行（同构）

```
数字页：384 = 42(ABC) + 194(空格) + 42(⌫) + 88(回车) + 18
符号页：384 = 42(123) + 194(空格) + 42(⌫) + 88(回车) + 18
```

数字/符号页把 emoji 键换成退格（`⌫` 17pt `text.primary`，底 `bg.key.function`），因为这两页的键区里没有多余列放退格。**底行 4 键、回车 88、空格 194 三页完全一致**，用户在三页之间切换时底行不重排。

### 4.7 命中区（不变式）

```
视觉高 39 + 上下各 2.5 = 44（keyHitHeight）
行节距 45 = 39 + 6，相邻行命中区不重叠
```

底行左右两端的 42 宽键，命中区横向仍按 42（不做 44 外扩，否则会压到 3pt 屏幕边距外的空白）。

### 6.2 明确不做（v1 有 / 或容易被加回来）

1. **不做弹性回弹**：`dampingFraction ≥ 0.8`，不允许 0.6 以下的"果冻"。
2. **不做位移式面板展开**：面板从上方滑入再配合高度动画 = 两个方向的运动叠加，视觉上"抖"。只做高度 + 内容淡入。
3. **不做候选横向滚动动画**：候选变化只改 opacity，不许 `scrollTo` 带 spring。
4. **不做旋钮光晕**：v1 的 `ai.glow` 键盘内 0 引用。
5. **不做骨架屏**：键盘内请求 < 300ms 不显示任何加载态（沿用 v1 §5）；> 300ms 用旋钮 busy 环，不加全屏 loading。
6. **不做礼花/成功动效**：上屏成功只给 `.success` 触感，不动画。
7. **不做视差/背景模糊跟随**：keyboard 背后是别人的 App，不做任何取样。

### 6.3 Reduce Motion 规则

```
开启后：
  · 所有高度变化 → 0.15s ease-out 直接到位（不做 spring）
  · 所有 offset 位移 → 取消（只保留 opacity）
  · 错列 → 0
  · 循环动画（#8 光标、#10 呼吸）→ 静态终态
  · 按压缩放 → 取消，仅保留底色变化
```

判定入口只有一个：`UIAccessibility.isReduceMotionEnabled`，不允许各视图自己判断。
