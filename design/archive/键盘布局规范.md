# 键盘布局规范 · 26 键 QWERTY / 9 键 / 全层 Layout Spec

> 版本 v1.0 ｜ 适用：`ios/AIKeyboardExtension/`（keyboard-ui）
> 依据：`docs/01` PRD §4.1、`docs/02` §4.5/§4.7 高度契约、`design/tokens.json`
> 画布基线：iPhone 390×844pt（iPhone 12/13/14 逻辑分辨率），竖屏
> **本文所有数字都能用公式复算，实现时禁止「目测微调」。**

## 1. 总高度拆解（先记住这张表）

### 1.1 竖屏基础态 = 258pt

| 区块 | 高度 | tokens 键 | 说明 |
|---|---:|---|---|
| 候选栏 CandidateBar | **44** | `sizing.candidateBarHeight` | 固定，永不伸缩 |
| AI 工具条 AIBar | **40** | `sizing.aiBarHeight` | 签名元素，固定 |
| 字母区（4 行） | **174** | 推导值 `4×39 + 3×6` | 见 §3 |
| **合计** | **258** | `sizing.keyboardHeightPortrait` | ≈ docs/02 的 258 |

```
258 = 44 + 40 + (4 × 39 + 3 × 6)
    = 44 + 40 + 174
```

**行高推导（唯一的解）**：字母区 174pt 要放 4 行 + 3 条 6pt 行距，
`rowHeight = (174 − 3×6) ÷ 4 = (174 − 18) ÷ 4 = **39**`。

> ⚠️ 与 docs/02 `sizing.keyHeight = 42` 的关系：**42 是契约里的「键帽标称高度」，不改**，用于 9 键布局、横屏、主 App 内的键帽示意；26 键竖屏的**实际行高是 39**，因为 258 的总高已经锁死（44+40 之后只剩 174）。两者都保留在 tokens 里（`keyHeight:42` 与扩展键 `letterRowHeight:39`），实现时 26 键用 `letterRowHeight`，9 键用 `keyHeight`。

### 1.2 展开态高度（不得抖动，必须整块 `UIView.animate`）

| 状态 | 追加高度 | 总高 | tokens 键 | 触发 |
|---|---:|---:|---|---|
| 基础（字母/数字/符号/表情） | 0 | **258** | — | 默认 |
| AI 输入面板 `.aiPanel` | **+168** | **426** | `sizing.aiPanelExtraHeight` | 点 AIBar 任一能力 chip |
| AI 结果页 `.result` | **+180** | **438** | `sizing.resultExtraHeight` | 发出请求 / 收到首个 delta |
| 键盘内设置 Sheet `.settings` | **+168** | **426** | `sizing.aiPanelExtraHeight` | 点 AIBar 的 ⚙️ / 长按地球 |
| 生图「绘制中」 | **+180** | **438** | `sizing.resultExtraHeight` | 生图请求发出即进入 |

> 展开时**候选栏与 AI 工具条的位置完全不动**（它们是视觉锚点），新增高度从工具条下方向上「挤出」面板。收起时面板向下移出。
> 高度计算只发生在 `KeyboardViewController.updateHeight(for:)` 一处，`KeyboardViewModel` 只发布 `page`，不允许各 View 自己改高度。

### 1.3 横屏 = 200pt（AI 工具条折叠）

| 区块 | 高度 |
|---|---:|
| 候选栏（右侧内嵌一个 ✨ 按钮） | **44** |
| 字母区 4 行 | **156** = 4×34.5 + 3×6 |
| **合计** | **200** |

横屏规则（`tokens.sizing.letterRowPitchLandscape = 34.5`）：
1. **隐藏独立 AIBar**，把它折叠成候选栏最右侧一个 32×32 的 ✨ 玻璃圆钮（`AIBar.compact` 变体），点击后进入 `.aiPanel`，横屏面板高度 `200 → 200+140 = 340`。
2. 横屏键宽：`keyW = (W − 2×3 − 9×6) ÷ 10`，W=844 时 = `(844−6−54)÷10 = 78.4`；键高 34.5，宽高比过大，因此**横屏在左右两侧各留 12% 空白**（`keyboardHorizontalInsetLandscape = max(3, W×0.12)`），键宽 = `(W×0.76 − 54) ÷ 10`，844 时 = `(641.4−54)/10 = 58.7`，观感正常。
3. 横屏不显示 AI 结果内联卡片，改为**浮层卡片**（宽 420，居中，`.glass`，距顶 12），避免挤压键区。

## 2. 390pt 宽 · 26 键逐行数学（核心，必须能复算）

### 2.1 基础常量

| 常量 | 值 | tokens 键 |
|---|---:|---|
| 屏幕宽 W | 390 | `meta.canvas.width` |
| 左右边距 padding | **3** | `sizing.keyHorizontalPadding` |
| 键间距 gap | **6** | `sizing.keyGap` |
| 可用内容宽 contentW | `390 − 2×3 = **384**` | 推导 |
| 字母键宽 keyW | `(384 − 9×6) ÷ 10 = **33.0**` | `sizing.letterKeyWidth` |
| 圆角 keyRadius | 8 | `radius.key` |

> keyW 的推导逻辑：第 1 行 10 个键之间只有 **9 条缝**，
> `10 × keyW + 9 × 6 = 384` → `keyW = (384 − 54) ÷ 10 = 33.0`（整数，无余数，这是选 6pt 间距的原因）。

### 2.2 行 1 —— 10 键，左右边距 3

```
[q] [w] [e] [r] [t] [y] [u] [i] [o] [p]
```
- 键宽 **33.0**，键高 39，间距 6，左右边距 3。
- 总宽校验：`10×33 + 9×6 + 2×3 = 330 + 54 + 6 = **390** ✓`
- 行内竖向内边距 0（键高占满行高 39）。

### 2.3 行 2 —— 9 键，同键宽，居中

```
[a] [s] [d] [f] [g] [h] [j] [k] [l]
```
- 键宽 **33.0**（与行 1 完全对齐，形成竖向视觉列），间距 6。
- 行宽 `9×33 + 8×6 = 297 + 48 = **345**`。
- 左右边距 `(384 − 345) ÷ 2 = **19.5**`（每侧）。
- 校验：`345 + 39 + 6 = 390` ✓
- **禁止**为了「填满」把行 2 的键拉宽——iOS 原生也是留白，键宽不一致会立刻被看出不是原生键盘。

### 2.4 行 3 —— Shift + 7 键 + 退格

```
[⇧ 42] [z] [x] [c] [v] [b] [n] [m] [⌫ 42]
```
- 字母键 7 × 33.0；功能键（Shift / 退格）宽 **42**（`sizing.functionKeyWidth`），高 39。
- 行宽 `42 + 33×7 + 42 + 8×6 = 42+231+42+48 = **363**`。
- 左右边距 `(384 − 363) ÷ 2 = **10.5**`。
- 校验：`363 + 21 = 384`，`+ 2×3 = 390` ✓

### 2.5 行 4 —— 底部功能行

```
[🌐 42] [空格 194] [🙂 42] [⏎ 88]
```
- 地球 42 / 空格 **194** / 表情 42 / 回车 **88**（`sizing.returnKeyWidth`、`sizing.spaceBarWidth`）。
- 间距 6 × 3 = 18，左右边距 3。
- 校验：`42 + 194 + 42 + 88 + 18 + 6 = **390**` ✓
- 若工程决定省略「表情键」（PRD 未强制）：**空格自动扩为 242**（`384 − 42 − 88 − 12 = 242`），其余不变；两种都合法，但**全局只用一种**，写在 `LayoutMetrics.bottomRowHasEmojiKey` 常量里，别一屏一个样。
- 回车键样式 `KeyStyle.accent`（accent 底 + 白字），图标 `return`（fallback `⏎`），长按=换行。
- 地球键：点=切下一输入法（`advanceToNextInputMode()`），长按=键盘列表 Sheet。
- 空格键：显示「空格」12pt `text.tertiary`（或对应语言提示），长按=移动光标（iOS 13+ 的 `textDocumentProxy` 光标拖动需自行实现，P0 可不做，标注灰）。

```

│ ⇧44?   │ 候选栏 44pt                        │    │  44

├──────────────────────────────────────────────────┤
```

### 2.7 触控区与实际视觉的分离（重要）

键帽视觉高 39，**点击区必须 ≥ 44**（`sizing.minTapTarget`）。做法：

```swift
// 行的实现（伪代码，交给 keyboard-ui 落地）
HStack(spacing: 6) { ... }
  .frame(height: 39)                 // 视觉
  .contentShape(Rectangle())          // 命中整个 39 高
  .padding(.vertical, 2.5)            // 39+5 = 44 命中高，行距 6 被吃掉 5
```
即：每行上下各外扩 2.5pt 作为命中区，行与行之间视觉 6pt 间距中 5pt 属于命中区，**相邻两键的命中区不重叠**（39+2.5+2.5=44，行 pitch 45，间隙 1）。行 1 顶部 2.5pt 命中区允许侵入 AIBar 下沿（AIBar 的 chips 高 30 居中于 40，底部留白 5，不会误触）。

## 3. 9 键拼音布局

| 项 | 值 |
|---|---|
| 触发 | 键盘内设置「键盘布局：九宫格」，或候选栏左侧布局切换按钮 |
| 总高 | **258**（与 26 键一致，切换时键盘不抖动） |
| 候选栏 / AI 工具条 | 同 26 键（44 / 40） |
| 键区 | 4 行：3 行主键 + 1 行功能键 |
| 主键行高 | **39**（4×39 + 3×6 = 174，与 26 键完全相同） |
| 主键宽 | `(384 − 2×6) ÷ 3 = **124**` |
| 主键布局 | 行1 `[1 空格?]` 实为：`[ABC][DEF][GHI]` / `[JKL][MNO][PQR]` / `[STU][VWX][YZ ]`（2 行 3 列 = 9 键，第 9 键为 `YZ`） |
| 键内排版 | 主字符 22pt regular 居中；下方一行 `拼音候选提示` 10pt `text.tertiary`（如 `ABC`）；右上角小数字「1/2/3」用于选候选（可选） |
| 功能行 | `[123 42] [空格 194] [⌫ 42]`，间距 8，剩余用 `flexible` 吸收（`384−42−194−42−16 = 90` 由两侧 45 平分）→ 实际：左右边距 45，间距 8 |
| 切换回 26 键 | 右下角 `[ABC]` 键（长按切换布局） |

9 键键态：主键白底、圆角 8、同 26 键阴影；`YZ` 键与 `1` 键保留 44 命中区。

## 5. 状态矩阵（必须逐格实现，QA 会对照）

> 列说明：候选栏 / AI 工具条 / 键区 / 追加区 / 高度 / 用户可见文案。`—` 表示无变化。

| 状态 | 触发条件 | 候选栏 | AI 工具条 | 键区 | 追加区 | 高度 | 备注文案 / 交互 |
|---|---|---|---|---:|---:|---:|---|
| **① 空闲** | 无输入、无 focus | 显示「墨语 · 会 AI 的输入法」12pt tertiary | 正常（可滚动） | 正常 | 无 | 258 | 地球/空格/回车可点；长按空格移动光标（P1） |
| **② 输入中** | `composing != ""` 或已有候选 | 候选横向滚动，首候选 semibold+accent，分页点按需 | 正常 | 正常，Shift/CapsLock 态生效 | 无 | 258 | 退格长按连删；候选长按菜单 |
| **③ 加载中** | 点生成、首字未到（≤1.5s） | 冻结当前候选（不清空，避免视觉跳动） | 被点 chip 变 `isSelected` 且显示 3 点进度 | 正常可点 | `.aiPanel` → 切换为结果卡骨架 | 426→438 | 面板内文案「正在连接…」+ 骨架条动画；>3s 显示「网络较慢，仍在等待」 |
| **④ 流式生成中** | 收到首个 delta | 冻结 | 对应 chip 高亮 | 正常可点（允许边生成边改） | 结果卡 body 逐字 + 光标闪烁 | 438 | 动作条：仅「取消」；文案 16pt 正文；底部状态「正在生成…」 |
| **⑤ 成功（文本）** | stream 结束 | 解冻 | chip 恢复 | 正常 | 结果卡「插入/复制/编辑/重试/关闭」 | 438 | header「已完成 0.8s」；插入后自动回到 `258` 并 `proxy.insertText` |
| **⑥ 成功（生图）** | 图片数据到达 | 解冻 | chip 恢复 | 正常 | 缩略图 160×120 + 「复制图片」「在 App 查看」 | 438 | 提示「已复制，回聊天窗口长按输入框粘贴」；`UIPasteboard.general.image = img` |
| **⑦ 生图绘制中** | 生图请求在途（5–20s） | 冻结 | chip 高亮 | 正常 | 进度环 48 +「绘制中… 已等待 N 秒」+「预计 5–20 秒」+ 取消 | 438 | **N 每秒 +1**（`TimelineView(.periodic by:1)`）；阶段文案：排队中/正在绘制/正在优化提示词/正在下载；>20s →「仍在绘制，可继续等待」 |
| **⑧ 错误** | `AIError`（401/429/超时/网络/解析/内容拒绝） | 解冻 | chip 恢复 | 正常 | 结果卡 → `ErrorBanner`（≤72）+「重试」「关闭」 | 438 | 标题=中文一句话；副文案=`recoverySuggestion` 一行；401→「去设置」跳 `.settings`；429→「请求太频繁，请稍后再试」 |
| **⑨ 错误（无完全访问权限）** | 进入 AI 前检测 `hasFullAccess == false` | 正常 | **整条禁用**：chips opacity .55，居中提示「开启完全访问后可用 AI ›」 | 正常 | 无（不进入面板） | 258 | 点提示 → 弹说明卡「设置 › 通用 › 键盘 › 墨语 › 允许完全访问」；**不得**发起任何网络请求 |
| **⑩ 未配置 Provider** | 配置快照为空/无默认 Provider | 正常 | **整条禁用**：居中「还没有配置 AI 服务 · 点此设置 ›」 | 正常 | 无（不进入面板） | 258 | 点提示 → `.settings` 的 Provider 空态（「去 App 添加」，用 `PasteboardBridge` 导入） |
| **⑪ 离线** | `NWPathMonitor` 判定无网络 | 正常 | 整条禁用：居中「网络未连接 ›」 | 正常 | 无 | 258 | 点提示重试探测；恢复自动解除 |
| **⑫ 无候选（拼音无匹配）** | 输入串无候选 | 显示 1 个「无匹配 · 长按退格清空」12pt tertiary | 正常 | 正常 | 无 | 258 | **不得**让候选栏高度变化；不得震动 |

**状态优先级**：⑨ 完全访问 > ⑩ 未配置 > ⑪ 离线 > ① 空闲。（即同时满足多条时，展示最高优先级那一条。）

**必须复用的中文文案（逐字，不许改写）**：
- 未配置：「还没有配置 AI 服务 · 点此设置」
- 无完全访问：「需要在“设置 › 键盘”中开启“允许完全访问”，AI 才能联网」
- 生图提示：「复制后在聊天窗口长按输入框粘贴」

## 7. 安全区、边距与不可退让项

| 项 | 规则 |
|---|---|
| 底部安全区 | 键盘 `inputView` **不含** Home Indicator 区域（系统在键盘下方追加 34pt 安全区），我们的 258 是纯键盘高度；若用 `allowsSelfSizing` 且系统添加了额外安全区，需在 `viewDidLayoutSubviews` 里 `height = 258 + view.safeAreaInsets.bottom`，**只在竖屏、且底部有 home indicator 的机型**上生效 |
| 顶部 | 键盘顶部无圆角、无阴影，但有一道 0.5pt `keyboard.topShadow`（深色模式下更明显）用于与宿主内容分层 |
| 左右 | 严格 3pt；**不得**为了美观加宽到 4/5，因为键宽公式正好整除 |
| 最小点击区 | 44×44（`minTapTarget`）——所有 chip 高 30 但命中高 44（上下各留 7） |
| Dynamic Type | 键盘内**全部固定字号**；系统字号放大到 AX5 时键盘布局不变（这是 iOS 键盘的既有行为，Apple 原生键盘也不随字号变） |
| 宽度适配 | 375pt：`keyW = (375−6−54)/10 = 31.5`；320pt：`keyW = (320−6−54)/10 = 26`（iPhone SE 一代，仍可用）；iPad 不做专门布局（`TARGETED_DEVICE_FAMILY=1,2` 但键盘按 iPhone 宽度居中，最大宽 414） |
| 抖动禁令 | 候选变化、AI 状态变化、行高变化、字号变化、分页点出现，**都不得改变 258/426/438 中的任何一个高度值** |

## 8. 视觉实现要点（给 keyboard-ui 的 5 条硬约束）

1. **键帽玻璃感**：只允许顶部 45% 高度叠 `LinearGradient(#FFFFFF40 → #FFFFFF00)`（`material.highlight`），**不要**用 `.ultraThinMaterial` 做单个键帽（每次按键重绘代价高，且深色模式下会变灰）。
2. **阴影**：键帽 `y:1 blur:0 opacity:0.18`（`shadow.key`）；深色模式几乎不可见是正常的，不要加大。
3. **渲染层级**：背景色块（无离屏渲染）＜ 键帽 ＜ 按压高亮 ＜ 面板。所有 `shadow` 用 `.shadow(color:radius:x:y:)` 的组合，避免 `.compositingGroup()` 滥用。
4. **候选栏与 AIBar 的玻璃**：两者共用一条 `GlassSurface(.bar)` 连续背景（先铺一条 84pt 高的玻璃底，再放 44 和 40 两行内容），避免两段玻璃叠出「双边框」。
5. **AI 面板顶部**：面板与 AIBar 之间**没有分隔线**（视觉上是一张从工具条下方滑出的纸），但面板底部靠近键区位置有 0.5pt separator。

## 9. 交互流（三条主链，逐步状态）

### 9.1 润色上屏（S1）
```
用户输入「今天天气真不错啊」→ 点 [✨ 润色]
 → 高度 258→426（spring 0.35/0.82），面板从底部滑入
 → 上下文预览行显示「今天天气真不错啊」
 → 点 [✨ 生成] → 高度 426→438，结果卡骨架出现
 → 首 delta → 流式卡片（④），光标闪烁
 → 完成（⑤）→ 点 [插入] → proxy.insertText(结果) → 高度 438→258（spring 0.28/0.9）→ Toast「已插入」2s
```
### 9.2 回复建议（S2）
```
宿主输入框里有对方消息（documentContextBeforeInput）
 → 点 [🧠 回复] → 若上下文 > 80 字：面板顶部出现「仅取最近 200 字作为上下文」小字
 → 生成中 → 结果卡 body 显示 3 条候选（每条 1 行，15pt，可点）
 → 点某条 → 直接 insertText → 收起
（3 条候选的拆分规则：按换行 > 分号 > 「1./2./3.」正则，最多 3 条，每条 ≤30 字）
```
### 9.3 生图（S4）
```
点 [🎨 生图] → 面板 → 输入描述「一只在打字的橘猫」
 → 点生成 → 高度 438，进入 ⑦ 绘制中：进度环 + 「排队中…」
 → 每 250ms 更新阶段；每秒更新「已等待 N 秒」
 → 到达 → 缩略图 + 「复制图片」
 → 点复制 → UIPasteboard.general.image = img → 结果卡底部提示「复制后在聊天窗口长按输入框粘贴」
 → 用户回宿主 App 长按粘贴（输入法无法直接插图，这是系统限制 → 写进 UI 已知限制）
```
