## 1. 需求还原与三个设计判断

### 1.1 用户原话（2026-10-25，经 Lead 转述，逐字）

> 手机可以打开app了，但是现在我人在外面，我需要你帮我完成几个事情／我需要中文输入，而且联想词我想有非传统方式提供联想词／以及现在导航栏没有任何东西，我觉得导航栏，可以做一个AI对话的旋钮，仅logo或图表，点击后有个输入框可以进行对话，思考方式将整个键盘新文本框进行对话

拆成三条：
1. **中文输入要能用**（bug 侧，不在本文范围）。
2. **联想词要「非传统方式」**——不是词库 n-gram 的下一个词，而是 AI 结合「当前输入框上下文 + 已输入内容」给的**下一句 / 短语**。
3. **导航栏区（候选栏 44 + AI 工具条 40 = 84pt）加一个 AI 对话旋钮**，**只要图标不要文字**；点击后**整个键盘区域切换成一个完整对话框**，能打字、能看回复、能把结果上屏。

### 1.2 三个设计判断（决定了后面的所有数字）

| # | 判断 | 理由 | 反面做法（明确否掉） |
|---|---|---|---|
| J1 | **旋钮是「模式开关」，不是「功能按钮」** | 点它之后键盘整个换页，用户预期是「进/出一个房间」，所以必须有明确的开态（反色 + 可一键退出），不能点完没反馈 | 做成一个普通 chip 弹小窗——用户会说"点了没反应" |
| J2 | **对话框里必须保留 174pt 标准键区** | 键盘扩展**无法可靠唤起系统键盘**（`AIPanelView` 已有注释说明），中文输入必须靠自身键区；若把键区藏掉，用户就"只能看不能说" | 做一个占满 438 的纯聊天界面 + 一个点击弹系统键盘的 TextField——在扩展里这是**不可用**的 |
| J3 | **联想 = AI 生成，不是词库查询** | 用户要的是"非传统"；词库联想（`predictNext`）只能给下一个词，给不出「下一句话」 | 继续用 `engine.predictNext` 填候选栏——这正是要改造的对象 |

### 1.3 为什么不做成弹窗 / 半屏卡片

- 键盘总高 258，屏幕上留给键盘的空间本就紧张；弹窗会盖住 174 键区，等于逼用户"看完再说"，打断输入。
- 全场模式下"看回复 → 按上屏 → 继续打字"是一条连续动作，弹窗会让这条动线断掉。
- iOS 惯例：键盘内的模式切换（表情、emoji、手写）都是**整块换页**，不是弹窗。

## 2. 旋钮（AI Chat Knob）

内部名：`aiChatKnob`；组件名：`KMChatKnob`（扩展侧，`KM` 前缀）；图标组件：`KMKnobGlyph`。

### 2.1 位置与尺寸（四种组合）

旋钮固定在**候选栏（chrome 第一行，44pt）的右端**，垂直居中。

| 组合 | 旋钮命中区 | 视觉圆 | 右边距 | 候选栏剩余可滚动宽度 | 说明 |
|---|---:|---:|---:|---:|---|
| 26 键 · 竖屏 | 44 × 44 | 34 × 34 | 8 | **330**（无分页）/ **306**（有分页） | 主场景 |
| 9 键 · 竖屏 | 44 × 44 | 34 × 34 | 8 | 同上 | 9 键候选栏与 26 键完全一致 |
| 26 键 · 横屏 | 44 × 44 | **32 × 32** | 8 | 同上 | 沿用既有 `AIBar.compactButton` 尺寸族 |
| 9 键 · 横屏 | 44 × 44 | 32 × 32 | 8 | 同上 | 同上 |

**宽度推导（390pt 基准）**：

```
候选栏可用宽 = 390 − 3(左屏边距) − 8(右内边距) = 379
无分页：候选滚动区 = 379 − 44(旋钮) − 5(间隙) = 330
有分页：候选滚动区 = 330 − 24(分页点) − 5(间隙) = 301   ← 见 2.2 修订为 306
旋钮左边界 x = 390 − 8 − 44 = 338
旋钮视觉圆左边界 x = 338 + 5 = 343，右边界 = 377
```

> 以最终实现常量 `knobTrailingInset=8`、`knobHitSize=44`、`paginationWidth=24`、`itemGap=5` 为准；候选滚动区宽度由 `HStack` 自动撑开，**不要在代码里写死 330/306**，用 `Spacer(minLength: 0)` + 固定宽度尾部即可。

### 2.2 与候选栏既有元素的避让（重要，必须按此改 `CandidateBar`）

`CandidateBar` 现有结构是：

```
HStack(spacing: 0) {
    候选滚动区（flex）
    paginationIndicator   // pageCount > 1 时 24 宽，否则 8 宽 Color.clear
}
```

改为：

```
HStack(spacing: 0) {
    候选滚动区（flex）
    paginationIndicator   // pageCount > 1 时 24 宽；否则 0 宽（不再是 8 的占位）
    Spacer().frame(width: 5)          // 新增：与旋钮的间隙
    KMChatKnob(...) .frame(width: 44, height: 44)   // 新增
}
.padding(.leading, 3)                  // keyHorizontalPadding
.padding(.trailing, 8)                 // 新增：右内边距
```

| 约束 | 值 | 理由 |
|---|---:|---|
| 分页点与旋钮间隙 | 5 | 视觉呼吸，不与 24 宽分页按钮粘连 |
| 旋钮与右屏缘 | 8 | 与 `aiBarInset` 一致，形成统一右缘 |
| 分页点无候选时 | **宽度 0** | 原实现留 8 会在旋钮左边多出一条空隙，看起来像"旋钮没贴边" |

> ⚠️ 分页点按钮原 `frame(width: 24, height: 44)`，命中区 24 × 44 **小于 44**，属于历史遗留；本次不改（避免动到既有交互），但在文档里记录为已知项。

### 2.3 图标方案三选一

| 方案 | 图形 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A | ✨ 纯星芒 | 一眼 AI，和横屏现有 `compactButton` 一致 | 与 AI 工具条「✨ 润色」撞车，用户分不清"润色"和"对话"；且太泛，不像品牌符号 | 否 |
| B | 「墨」字 | 品牌感最强 | 16pt 下汉字不可辨，会糊成一团黑块 | 否 |
| C | **对话气泡 + 四角星芒** | 同时表达"对话"和"AI"；与工具条 ✨ 明确区分；矢量绘制，无字体/符号依赖 | 需要自绘 Path（一次性成本） | ✅ **选定** |

**选定方案 C**：一个开口朝左下的圆角气泡轮廓（代表"说"），右上角一颗四角星（代表"智能"）。整体是**单色描边 + 局部实心**，在 16pt 下依然可辨；深色模式下不依赖渐变，缩到 34pt 视觉圆里也不脏。

### 2.4 图标绘制规格（`KMKnobGlyph`，16 × 16 绘制框）

| 图元 | 路径 | 描边/填充 | 线宽 |
|---|---|---|---|
| 气泡主体 | `RoundedRectangle(cornerRadius: 4)`，rect = (0.6, 1.2, 11.4, 9.6) | 描边 | 1.6 |
| 气泡尾巴 | 三角形 (3.2, 10.6) → (4.9, 10.6) → (3.4, 13.2) 闭合 | 填充 | — |
| 星芒 | 四角星，中心 (12.3, 3.7)，外径 3.7，内径 1.15（内/外 = 0.31） | 填充 | — |
| 颜色 | `.idle` = `accent`；`.active` = `text.onAccent`；`.disabled` = `text.tertiary` | | |

- 全部用 `Path` + `stroke(lineWidth: 1.6, lineCap: .round, lineJoin: .round)` / `fill`，**不要用 emoji、不要用 SF Symbol**（`bubble.left.and.sparkles` 在 iOS 16 不存在，会掉成空白）。
- **降级**（若 UI 智能体判断自绘成本过高，允许但需登记）：`KMIconGlyph(symbol: "bubble.left", fallback: "💬", size: 15, tint: …)` + 右上角叠一颗 6pt 的 `sparkles` 符号。此降级版**必须**保留右上角星，否则与"回复"图标撞车。

### 2.5 五态外观

| 状态 | 圆形填充 | 描边 | 图标色 | 额外 | 触发条件 |
|---|---|---|---|---|---|
| `.idle` | `chip.bg`（半透明） | `chip.border` 1pt | `accent` | 无 | 常态 |
| `.pressed` | `chip.bg.pressed` | 同 idle | `accent` | `scaleEffect(0.92)` | 按下瞬间（0.08s） |
| `.active` | `accent` | 无 | `text.onAccent` | 无 | `page == .aiChat` |
| `.busy` | `chip.bg` | `chip.border` | `accent` | 外环 1.5pt `accent` 不完整圆弧，1.2s/圈 匀速旋转 | 对话流式中 |
| `.disabled` | `chip.bg` | `chip.border` | `text.tertiary` | 整体 `opacity(0.45)` | `availability != .ready` |

- **光晕**：`.active` 态不加光晕（AI 工具条已经够亮，再加会显廉价）；仅在"有未读新回复且面板已收起"时，`.idle` 圆外 6pt `ai.glow` 呼吸（2s 一循环，幅度 opacity 0→0.35）。**此光晕可以不做**，属于 P2 加分项。
- **点击 `.disabled` 时**：不进入面板，弹出 `KMToast`（沿用既有 toast），文案按 `AIAvailability` 三分支：
  - `.noFullAccess` →「开启完全访问后可用 AI」
  - `.notConfigured` →「还没有配置 AI 服务 · 点此设置」（点 toast 跳 `.settings` 页）
  - `.offline` →「网络未连接」

### 2.6 动效

| 动作 | 曲线 | 时长 | 备注 |
|---|---|---:|---|
| 按下 | `easeOut` + `scale 1 → 0.92` | 0.08 | 与键帽一致（`motion.keyPress`） |
| 抬起 | `spring(response: 0.25, dampingFraction: 0.82)` | 0.25 | 回弹一次，不过冲 |
| 进入对话（旋钮反色 + 键高 258→438） | `spring(response: 0.35, dampingFraction: 0.82)` | 0.35 | **键盘高度必须走 `UIViewPropertyAnimator` + `heightAnchor`**（见 `docs/03 §10.3`），不能交给 SwiftUI 隐式动画 |
| 退出对话（438→258） | `spring(response: 0.28, dampingFraction: 0.9)` | 0.28 | 更快更"收"，避免拖沓 |
| 旋钮 idle↔active 反色 | `easeInOut` | 0.15 | 与高度动画并行，不单独延迟 |

- **Reduce Motion 开**：高度直接切换（0 时长），旋钮反色保留 0.15s 淡化；外环旋转改静态。
- 进入时对话内容额外做 `opacity 0 → 1`（0.25s，delay 0.08）+ `offset(y: 8 → 0)`，避免内容突然"蹦出来"。

## 3. AI 对话面板（全场模式）

页枚举：`KeyboardState.Page.aiChat`。**注意**：`Page`、`KMLayout.keyboardHeight`、`Page.isExpanded`、`Page.accessibilityTitle` 共 4 处 switch 必须同时补分支，Swift 穷尽检查漏一个就编译失败。

### 3.1 进入 / 退出

| 动作 | 结果 |
|---|---|
| 点旋钮（`availability == .ready`） | `model.page = .aiChat`；键盘高度 258 → 438；首次进入且无历史消息时发一条开场白（见 §3.11） |
| 点标题条左侧 ✕ | 关闭对话，`page = .letters`，高度 438 → 258；**保留**本次会话消息（下次进入继续） |
| 从标题条向下拖 > 40pt | 同上（交互可选，P2） |
| 点键盘区右下「⌨」（可选） | 收起对话回到 `.letters`，同时把 `chatDraft` 内容上屏到宿主 |
| 用户在对话里连点宿主输入框 | 不响应（扩展不接管宿主焦点） |

### 3.2 总高度与分区（竖屏）

```
438 = 40（对话标题条）
    + 180（消息列表）
    +  44（输入行；拼音组合中切换为候选行）
    + 174（标准键区，4 行 × 39 + 3 × 6，与字母页完全一致）
```

- **438 = `keyboardHeightPortrait(258) + resultExtraHeight(180)`**，复用既有令牌，`KMLayout.keyboardHeight` 里 `.aiChat` 与 `.result` 同分支即可，**不新增高度常量**。
- **chrome 的 84pt（候选栏 44 + AI 工具条 40）在 `.aiChat` 页整体隐藏**——因为对话标题条 40 已经承担了"这是一块独立界面"的语义，再叠一条候选栏会让顶部变成 124pt 的双层导航，非常笨重。
- 拼音候选不丢：输入行在 `composing` 非空时**原地切换**为候选条（§3.8）。
- Home Indicator 安全区照旧叠加：`height = 438 + safeAreaBottom`。

### 3.3 对话标题条（40pt）

| 位置 | 元素 | 规格 |
|---|---|---|
| 左 | 关闭按钮 | 44 × 40 命中区，`xmark` 15pt `text.secondary`，居中 |
| 中 | 标题 | 「墨语 AI」`fontHeadline`(17 semibold) `text.primary`，单行 |
| 中（标题右侧 6pt） | 状态点 | 6 × 6 圆，`success` = 已连接 / `warning` = 生成中 / `danger` = 出错 / `text.tertiary` = 未知 |
| 右 | 新对话 | 44 × 40 命中区，`square.and.pencil`（降级 `↻`）15pt `text.secondary`；有消息时点击弹 `KMConfirmation`「清空当前对话？」 |
| 背景 | — | `keyboardBackground` |
| 分隔 | 底部 0.5pt `separator` | 与消息区分界 |

- 副标题（provider 名）**不显示**，避免 40pt 里挤两行；provider 名称放在空态里和错误文案里。
- 标题条不参与滚动，常驻。

### 3.4 消息列表（180pt）

| 项 | 规格 |
|---|---|
| 高度 | 180 固定；内容超出一律纵向滚动（`ScrollView` + `ScrollViewReader`，新消息自动滚到底） |
| 左右内边距 | 12（`spacing.lg`） |
| 上内边距 | 8 |
| 下内边距 | 8 |
| 消息间距 | 同一说话人 6，换人 12 |

| 背景 | `keyboardBackground`（与标题条同底，无独立卡片） |

### 3.5 消息气泡规格

| 属性 | 用户消息（右） | AI 消息（左） |
|---|---|---|
| 最大宽度 | `消息区可用宽 − 64`（390 场景 = 302） | 同 |
| 圆角 | 16，**右下角 6** | 16，**左下角 6** |
| 内边距 | 水平 12 / 垂直 8 | 同 |
| 底色 | `accent` | `bg.surfaceElevated` |
| 文字色 | `text.onAccent` | `text.primary` |
| 字号 | `fontBody`（15 / 行高 20） | 同 |
| 对齐 | `.trailing` | `.leading` |
| 阴影 | 无 | 无（键盘内不用卡片阴影） |
| 长按 | 复制该条文本 + `selection` 触感 + `KMToast`「已复制」 | 同 |

- 圆角实现：`UnevenRoundedRectangle` 是 iOS 17 API，**iOS 16 用 `.clipShape(RoundedRectangle(cornerRadius: 16))` 统一圆角**即可，尾角差异属视觉加分，不做也合格。

## 4. AI 智能联想（非传统联想词）

### 4.1 定位

**不是**"下一个词"，**是**"你可能想说的下一句 / 短语"。输入位置：**候选栏**。不新增任何高度。

### 4.2 呈现位置与优先级

候选栏内部的优先级（高 → 低），同一时刻只显示一档：

| 优先级 | 条件 | 候选栏显示内容 |
|---:|---|---|
| 1 | `composing` 非空 | 拼音候选（现状，不变） |
| 2 | `composing` 空 且 AI 联想就绪 | **3 个 AI 联想胶囊**（本节） |
| 3 | `composing` 空 且 AI 联想为空/未就绪 | 传统词库联想（现状 `predictNext`，作兜底） |
| 4 | 全部为空 | 空态：`输入中`→「墨语 · 会 AI 的输入法」；`无匹配`→「无匹配 · 长按退格清空」 |

- 旋钮与分页点**始终存在**，不受上述切换影响。
- AI 胶囊从**候选滚动区最左端起排**（leading），不居中，不右对齐。

### 4.3 视觉规格

| 属性 | 值 |
|---|---|
| 组件 | `KMPillChip(style: .tag)` 变体，新增 `style: .suggest`（或复用 `tag` + 自定义描边） |
| 尺寸 | 高 **30**，水平内边距 12，圆角 `capsule` |
| 底色 | `chip.bg` |
| 描边 | 1pt `accent.opacity(0.35)`——**这是它和普通候选唯一的强区分** |
| 前缀图标 | `sparkles` 11pt `accent`（降级 `✨` 11pt），与文字间距 4 |
| 文字 | `fontChip` 13 medium `chip.text` |
| 条数 | ≤ **3** |
| 每条字数 | ≤ **12** 字，超出尾部省略号 |
| 间距 | **8** |
| 点击 | 立即上屏（`model.insertText(suggestion)`）+ `selection` 触感 + 候选栏清空 |
| 出现动效 | `opacity 0→1` + `offset(x: -4→0)`，0.2s（`normal` 0.25 也可） |
| 消失 | 直接移除，不做退场动画（避免延迟感） |

> 为什么用"胶囊 + 描边"而不是"和普通候选一样的纯文字"：用户要的是"**非传统**"，视觉必须一眼看出这是 AI 给的。用胶囊是最低成本的语义标记。

### 4.4 触发规则（精确）

**发起条件（全部满足才请求）**：

1. `aiAvailability == .ready`（有完全访问 + 已配置 + 有网）
2. `composing.isEmpty`
3. `lastCommittedText` 非空，且长度 ≥ 6 个字符（**或**上屏内容以 `。！？!?` 结尾）
4. 距上次联想请求 ≥ **3 s**（节流）
5. 当前 `page ∈ {.letters, .numbers}`（`.aiChat`/`.aiPanel`/`.result`/`.settings` 不触发）
6. 用户已停止输入 **0.35 s**（防抖）

**触发时机**：

- A. 用户上屏（`commit`）一条非空文本后 → 启动防抖
- B. 宿主输入框文本变化（`textDidChange` 回调有上下文时）→ 同上
- C. 用户删空输入框 → 立即清空联想，不发请求

**请求内容**：

```
系统提示词（固定，见下）+ 最近上下文（≤200 字，model.contextCharacterLimit）
返回：JSON 数组，3 个字符串，每个 ≤12 字
```

系统提示词（新增 `PromptTemplate`，id = `suggestion.next_phrase`）：

> 你是中文输入法的联想助手。根据用户正在写的这段话，给出 3 个"用户接下来最可能输入的短句"，直接可上屏。要求：每条不超过 12 个字；口语化、自然；三条之间要有差异（不要同义重复）；只返回 JSON 数组，不要任何解释。

**返回解析**：

- 只接受 `["…","…","…"]` 形态；解析失败 → 静默丢弃。
- 过滤：空串、长度 > 12、重复项；不足 3 条则有几条显示几条（≥1 才显示）。
- 总耗时 > **1.5 s** → 放弃本次（不显示 loading，不显示错误）。

### 4.5 失败与降级（**必须完全静默**）

| 情况 | 表现 |
|---|---|
| 网络/鉴权/限流错误 | **什么都不显示**，不弹 toast，不显示错误图标；候选栏退回传统联想 |
| 超时 1.5s | 同上 |
| 无完全访问 / 未配置 | **整块功能不出现**，候选栏高度不变（44），不做任何占位 |
| 解析失败 | 同上，且 5s 内不再重试 |

> 核心原则：**联想是锦上添花，绝不能因为它在候选栏里闪一下错误图标而打断打字**。这条比"让用户知道 AI 挂了"更重要。

### 4.6 生命周期

| 事件 | 行为 |
|---|---|
| 上屏新文本 | 清空旧联想 → 防抖 0.35s → 新请求 |
| 进入拼音组合 | 隐藏（数据保留，最多 10s） |
| 拼音组合结束且数据 < 10s | 重新显示 |
| 用户切页 / 关闭键盘 | 清空 |
| 对话面板打开 | 不触发、不显示 |
