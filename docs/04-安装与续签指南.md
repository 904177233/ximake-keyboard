# 04 · 安装与 7 天续签指南（Windows 全流程版）

> **适用人群**：手上只有 **Windows 电脑**、有一台 iPhone、没有 $99/年 Apple 开发者账号的普通用户。
> **本文目标**：从零把「墨语」装进你的 iPhone，并在 7 天签名过期后能自己续上，全程不需要 Mac。
> **阅读方式**：先看第 0 章决策树判断你走哪条路；绝大多数人走 **路线 A**，照着第 1～6 章一步步做即可。
> **预计耗时**：第一次约 **60～90 分钟**（含注册 GitHub、装 iTunes、等云端编译）；之后每 7 天续签约 **5～10 分钟**。

---

## 0. 先做决定：你有 Mac 吗？

| 你的情况 | 走哪条路 | 成本 | 难度 | 说明 |
|---|---|---|---|---|
| **只有 Windows**（绝大多数人） | **路线 A：GitHub Actions 云编译 + Windows 上 Sideloadly 签名安装** | ¥0 | ★★☆ | 本文主线，第 1～6 章 |
| 能借到 / 租到 Mac（朋友、公司、MacinCloud、MacStadium） | **路线 B：直接在 Mac 上用 Xcode 编译运行** | 借：人情；租：约 $1/小时起 | ★☆☆ | 最省事，第 7 章 |
| 想在自己 Windows 上装 macOS 虚拟机 | **路线 C：黑苹果 / 虚拟机** | ¥0～几百 | ★★★★★ | **不推荐**：违反 Apple 许可协议、性能差、Xcode 版本受限、驱动难搞。仅作最后手段 |

```text
              ┌─────────────────────────┐
              │ 你手上有没有一台 Mac？   │
              └───────────┬─────────────┘
                          │
        ┌─────────────────┴──────────────────┐
        │ 有（自己/借/租）                     │ 没有（只有 Windows）
        ▼                                     ▼
 ┌──────────────┐                    ┌──────────────────────────┐
 │ 路线 B        │                    │ 路线 A（推荐）            │
 │ Xcode 直接 Run│                    │ GitHub Actions 云编译     │
 │ 5 分钟装好    │                    │ → 下载 unsigned IPA       │
 │ 7 天重连 Mac  │                    │ → Windows Sideloadly 签名 │
 └──────────────┘                    └──────────────────────────┘
                                              │
                                    7 天后过期怎么办？
                                              ▼
                              ┌───────────────────────────────┐
                              │ 路线 A 重做一次（5～10 分钟）  │
                              │ 或考虑 $99/年开发者账号（1 年）│
                              └───────────────────────────────┘
```

> **先理解三个残酷事实，能省你很多时间：**
> 1. **iOS 应用只能在 macOS 上编译（官方工具链）**。Windows 上哪怕装了 Xcode 也打不开。所以「云端 macOS 编译 + Windows 本地签名」是唯一零成本方案。
> 2. **免费 Apple ID 签名的 App 只有 7 天有效期**，第 8 天点开就闪退/提示「无法验证 App」。这不是 bug，必须重签。**iOS 输入法扩展同样受 7 天限制**，而且扩展失效后键盘会直接从列表里消失或点了没反应。
> 3. **免费账号不能开 App Group**（App 与键盘扩展共享数据的官方机制）。所以本项目的「App 里配置 → 同步到键盘」用的是**剪贴板搬运**，不是 App Group。详见第 8 章。

## 1. 路线 A · 第 1 步：准备账号与网络

| 要做的事 | 操作路径 | 你会看到什么 | 备注 |
|---|---|---|---|
| 1.1 注册 GitHub 账号 | 打开 <https://github.com> → Sign up | 邮箱验证邮件 | 免费。仓库 Private / Public 都能用，见下方对比 |
| 1.2 在 GitHub 建一个空仓库 | 右上角 **+** → New repository → 名字填 `ximake-keyboard` → Private 或 Public → Create | 一个只有 `README` 的空仓库页面 | **不要**勾选 Add .gitignore / license，保持空仓库 |
| 1.3 装 Git（如果没装） | <https://git-scm.com/download/win> → 一路 Next | 右键菜单出现「Git Bash Here」 | 用于把本地代码推上去。也可 `winget install --id Git.Git -e` |
| 1.4 装 GitHub Desktop（更简单，可选） | <https://desktop.github.com> | 图形化提交/推送 | 完全不想碰命令行就用这个；装完会自动帮你登录并缓存凭据 |

> **Private 还是 Public？两者都能跑通，区别只在这两处**
> - **Private**：代码只有你能看。代价是每月只有 **2000 分钟**免费 macOS 编译额度（够用：一次编译约 **1 分钟**，7 天一次 ≈ 每月 4～5 分钟）。
> - **Public**：macOS 编译**完全免费、不限时长**，代价是代码公开。你的 API Key **不在代码里**（只存在手机 Keychain），公开也不泄露，介意就选 Private。
> - 本文档后续所有步骤**对两种仓库完全一致**，唯一的区别是下载 Artifact 时必须登录 GitHub（Private 仓库匿名下载会 404，Public 仓库匿名可下）。

## 2. 路线 A · 第 2 步：把代码推到 GitHub

### 2.1 确认仓库里有 workflow 文件

云端编译靠的是仓库里的自动化流水线文件：**`.github/workflows/build.yml`**。本项目已内置（由工程负责人生成）。

**你在 Windows 上可以这样确认它存在**（文件资源管理器）：

```text
输入法\
├── .github\
│   └── workflows\
│       └── build.yml        ← 必须有这个文件
├── ios\
├── design\
├── docs\
└── README.md
```

> ⚠️ **`.github` 是隐藏文件夹**。Windows 资源管理器需要勾选「查看 › 显示 › 隐藏的项目」才能看到。
> 也可以用 PowerShell 确认：
> ```powershell
> cd "C:\你的路径\输入法"
> Test-Path .github\workflows\build.yml     # 应输出 True
> ```

`build.yml` 实际做这些事（文件名 `.github/workflows/build.yml`，name `Build Unsigned IPA`）：

| 步骤 | 作用 | 失败会怎样 |
|---|---|---|
| `actions/checkout@v4` | 拉取代码 | — |
| `Show Xcode version` | 打印 Xcode / macOS / Python 版本 | runner 镜像异常时先看这一步 |
| `Preflight - extension sources exist` | 检查 `ios/AIKeyboardExtension/` 里有 `.swift` 且有 `class KeyboardViewController` | 直接报 `::error::`，提示"键盘扩展没有源码" |
| `Regenerate Xcode project from source tree` | 跑 `python3 scripts/gen_xcodeproj.py` 重生成 pbxproj | 生成器报错=工程脚本问题，报告 Lead |
| `Validate generated project structure` | 跑 `scripts/validate_project.py` 自检 | 结构不合规，日志里会说哪一项 |
| `List schemes` | `xcodebuild -list` 确认有 `AIKeyboard` scheme | 报"没有 scheme AIKeyboard" |
| `Build unsigned archive` | `xcodebuild -project ios/AIKeyboard.xcodeproj -scheme AIKeyboard -sdk iphoneos ... archive`，带 `CODE_SIGNING_ALLOWED=NO` | 编译错误直接红叉，去日志搜 `error:` |
| `Package unsigned IPA` | 组 `Payload/AIKeyboard.app` 并用 `ditto` 打成 `.ipa` | — |
| **校验 `Payload/AIKeyboard.app/PlugIns/AIKeyboardExtension.appex` 存在** | 防止键盘扩展被漏打包 | 校验失败=流水线故意报错（见第 4.4 节） |
| `actions/upload-artifact@v4` | 上传 `AIKeyboard-unsigned-ipa`（保留 7 天） | 到 Actions 页面下载 |

### 2.2 推代码的三种方式（选一种）

**方式 1：GitHub Desktop（推荐小白）**

1. 打开 GitHub Desktop → **File › Add local repository** → 选中 `C:\...\输入法`
2. 若无仓库会提示 "create a repository" → 点 **create a repository**
3. 左下角填 Summary（如 `墨语 v1.0`）→ **Commit to main**
4. 上方 **Publish repository** → **取消勾选** "Keep this code private"？ **不要取消**，保持 Private → Publish

**方式 2：Git 命令行**

```powershell
cd "C:\你的路径\输入法"
git init
git add .
git commit -m "墨语 iOS 输入法 v1.0"
git branch -M main
git remote add origin https://github.com/<你的用户名>/ximake-keyboard.git
git push -u origin main
```

> 第一次 `git push` 会弹浏览器要求登录 GitHub 授权（Git Credential Manager），按提示点授权即可。

**方式 3：网页直接上传（最笨但可行）**

GitHub 仓库页 → **Add file › Upload files** → 把整个文件夹拖进去。**注意**：网页上传**不支持 `.github` 这类隐藏目录**，workflow 会丢，**不推荐**。

> **你会看到什么**：推送成功后，仓库页面文件列表出现 `ios/ design/ docs/ .github/`。
> **出错怎么办**：`error: failed to push some refs` → 通常是因为建仓库时勾了 README，先 `git pull --rebase origin main` 再 push。

## 3. 路线 A · 第 3 步：在 GitHub 上跑云端编译

### 3.1 触发编译

| 情况 | 怎么触发 |
|---|---|
| 刚推送代码 | **自动触发**（workflow 监听 `push` 到 `main`，且只改了 `ios/**`、`scripts/gen_xcodeproj.py`、`scripts/validate_project.py`、`.github/workflows/build.yml` 时触发） |
| 想手动重跑 | 仓库页 → **Actions** 标签 → 左侧 **`Build Unsigned IPA`** → 右上 **Run workflow** → 选 `Release`（默认）→ 绿色 **Run workflow** |
| 只改文档想重跑 | 文档改动不在触发路径里，必须用上面「手动重跑」 |

### 3.2 等它跑完

- 打开仓库页 → **Actions** 标签 → 点进最新一次运行
- 左侧会看到一串步骤（本仓库 `build.yml` 实际步骤名）：

  ```text
  Set up job
  Checkout
  Show Xcode version
  Preflight - extension sources exist        ← 检查键盘扩展有没有源码
  Preflight - shared sources exist
  Preflight - shell script syntax
  Regenerate Xcode project from source tree  ← 按磁盘文件重生成 pbxproj
  Validate generated project structure
  Validate pbxproj OpenStep plist syntax     ← 词法校验，防「工程文件打不开」
  List schemes
  Build unsigned archive                     ← 真正编译，最慢
  Package unsigned IPA                       ← 校验 PlugIns 里有没有 .appex
  Verify IPA contents
  Upload IPA artifact
  (失败时) Upload build logs on failure
  ```

- **总耗时通常 1～3 分钟**（`macos-14` runner 冷启动会多花一点；实测从 push 到出包约 **1 分钟**）
- 绿色 ✓ = 成功；红色 ✗ = 失败

**它到底跑了什么命令**（想知道细节就看这段，不想看可跳过）：

```bash
# 1) 先按磁盘上真实存在的 .swift 重新生成工程（所以你加文件忘了重跑生成器也没关系，云端会补）
python3 scripts/gen_xcodeproj.py
python3 scripts/validate_project.py

# 2) 编译成未签名 archive（注意是 -project，不是 -workspace：本项目零第三方依赖）
xcodebuild -project ios/AIKeyboard.xcodeproj \
           -scheme AIKeyboard \
           -configuration Release \
           -sdk iphoneos \
           -derivedDataPath build/dd \
           -archivePath build/App.xcarchive \
           CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO \
           CODE_SIGN_IDENTITY="" CODE_SIGN_ENTITLEMENTS="" \
           DEVELOPMENT_TEAM="" ENABLE_BITCODE=NO \
           archive

# 3) 组 Payload 打成 ipa，并强制校验扩展在不在
ditto -c -k --sequesterRsrc --keepParent Payload AIKeyboard-unsigned.ipa
```

> 工程侧的全部细节（生成器原理、pbxproj 打不开时的兜底方案、必须手填的 Build Settings 清单、
> 改完源码后要重跑生成器）见 **[`docs/ios/README-构建.md`](./ios/README-构建.md)**。
> 本文只讲「你要做什么」，那份文档讲「工程为什么这么配」。

**你会看到什么（成功时）**：运行详情页底部 **Artifacts** 区域有一个可下载的包，名字就是 **`AIKeyboard-unsigned-ipa`**，解压后 ipa 约 **2.6 MB**（实测 2,740,059 字节）。

> 为什么这么小：本项目零第三方依赖，App 本体只有一个可执行文件 + 图标；最大的一块是 `Assets.car`（约 418 KB）。词库（`base_dict.tsv` 136 KB / `phrases.tsv` 21 KB）在扩展的 `Resources/dict/` 里随包分发。

### 3.3 下载 IPA 到 Windows

1. 在 Artifacts 区域点 **`AIKeyboard-unsigned-ipa`** → 浏览器下载一个 **`.zip`**（Artifact 下载下来永远是 zip，即使里面只有一个 ipa）
2. 解压 → 里面是一个 **`.ipa`** 文件：**`AIKeyboard-unsigned.ipa`**
3. 把它放到一个好找的地方，例如 `C:\你的下载目录\AIKeyboard-unsigned.ipa`

> ⚠️ **Artifact 只保留 7 天**（workflow 里 `retention-days: 7`，和免费签名有效期一致）。过期就要重新跑一次编译。
> ⚠️ **必须登录 GitHub 才能下载 Private 仓库的 Artifact**。未登录点下载会 404。

### 3.4 编译失败了怎么办（对照日志找原因）

| 日志里的关键字 | 含义 | 你该做什么 |
|---|---|---|
| `error: unable to find utility "xcodebuild"` | runner 镜像选错 | 在 `build.yml` 里确认 `runs-on: macos-14`（或 `macos-latest`）；这属于工程问题，报告给 Lead |
| `error: The project named "AIKeyboard" does not contain a scheme named "AIKeyboard"` | 缺 **shared scheme** | 工程被生成时没勾 Shared。报告 Lead / 工程负责人补 `xcshareddata/xcschemes/AIKeyboard.xcscheme` |
| `::error::目录 ios/AIKeyboardExtension 不存在` / `下没有任何 .swift 文件` | **Preflight 拦截**：键盘扩展还没写完 | 这是工程未完成，不是你的操作问题。等 Lead 说"代码已落盘"再重跑 |
| `::error::…里没有找到 KeyboardViewController 类` | 扩展主类名字不对（`Extension-Info.plist` 的 `NSExtensionPrincipalClass` 指向它） | 报告 Lead，改了会启动即崩溃 |
| `::error::IPA 里缺少 PlugIns/AIKeyboardExtension.appex` | 打包没带扩展（Embed App Extensions 阶段丢了） | 报告 Lead：检查 App target 的 Copy Files 阶段 `dstSubfolderSpec = 13` |
| `::error::IPA 只有 N 字节，明显不正常` | 没把 `.app` 打进 Payload | 报告 Lead，通常是打包步骤路径变化 |
| `error: No such file or directory: .../Config/App-Info.plist` | 路径错 / 文件没提交 | 检查 `ios/Config/` 是否都推上去了（`.gitignore` 有没有误伤） |
| `error: invalid bundle identifier` / `Signing for "AIKeyboard" requires a development team` | 云端仍在尝试签名 | workflow 应带 `CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO`；缺了就报告 Lead |
| `Validation failed: …` （来自 `validate_project.py`） | 生成出来的工程结构不合规 | 看日志里点名的文件/target，报告 Lead |
| `This request has been automatically failed because it uses a deprecated version of actions/upload-artifact` | 用了 v3 | 报告 Lead 改为 `@v4` |
| 红色 `✗` 但有 "The job was canceled" | 你连推了两次，`concurrency` 取消了旧的那次 | 正常。看最新那次运行 |

> **关键认知**：云端这一步**只负责编译**，产出的是**未签名 IPA**。真正的「签名 + 装进 iPhone」在你自己 Windows 上做（第 4 章）。

## 4. 路线 A · 第 4 步：Windows 上用 Sideloadly 签名并安装

这一步是整个流程里**最容易卡住**的地方，请一步一步来。

### 4.1 装三个软件（详见下表，按需装、不必强求顺序）

| 优先级 | 软件 | 下载地址 | 说明 |
|---|---|---|---|
| ① **必装** | **Sideloadly** | <https://sideloadly.io> → 下载 Windows 版（`.exe`） | 免费工具，本地用你的 Apple ID 重签名。⚠️ **别用 winget 装**：winget 清单钉的是旧版 0.60.0 的哈希，而官网这个固定地址现在提供的是新版，会报「安装程序哈希不匹配」——直接从官网下即可 |
| ② 先试试有没有 | **USB 驱动** | 装上 Sideloadly 后先插手机试一次 | 很多机器（装过 Apple 相关软件、或 Win10/11 自带）**已经有 `Apple Mobile Device Service` 在跑**，不需要额外装任何东西。先试，认不出设备再装③ |
| ③ 认不出设备才装 | **iTunes**（**必须用微软商店版**） | 微软商店搜 `iTunes` → 安装 | ⚠️ **不要装 Apple 官网的 exe 版**：它不带需要的驱动组件，Sideloadly 常报「Unable to connect to device」 |
| ④ 可选 | **iCloud**（微软商店版） | 微软商店搜 `iCloud` | 提供部分额外驱动；不装通常也能用，装了更稳 |

> **怎么判断「驱动够不够」**：插上手机后，在 PowerShell 里跑 `Get-PnpDevice -Class PortableDevice`。
> 能列出你的 iPhone → 驱动没问题，直接进 4.2；列表为空或报错 → 装 ③（iTunes 商店版），重启电脑，再试。
> **Sideloadly 的安装位置**（想用命令行启动时用得上）：`C:\Users\<你的用户名>\AppData\Local\Sideloadly\sideloadly.exe`。

### 4.2 连接 iPhone 并信任电脑

| 步骤 | 操作 | 你会看到什么 |
|---|---|---|
| 1 | 用**数据线**把 iPhone 连到 Windows（**别用充电线/劣质线**，一定要能传数据的线） | Windows 提示「已连接设备」 |
| 2 | iPhone 屏幕弹「要信任此电脑吗？」→ 点 **信任** → 输入锁屏密码 | 弹窗消失 |
| 3 | 打开 **Sideloadly**，看 **Device** 下拉里有没有你的 iPhone（显示设备名和 iOS 版本） | 有 → 驱动正常 ✓（装了 iTunes 的话也可以打开它，能看到设备信息同理） |
| 4 | （iPhone 端）设置 › 隐私与安全性 › **开发者模式** → 打开 → 重启 iPhone → 重启后再确认一次 | iOS 16+ 必须开，否则装了也起不来 |

> **如果你在 iPhone 上看不到「开发者模式」**：说明还没装过任何开发版 App。先跳过，装完第一次 Sideloadly（会报错）后它会出现在设置里；或者直接进行 4.3，Sideloadly 提示时再去开。

### 4.3 在 Sideloadly 里签名安装

```text
┌──────────────────────────────────────────────────────────┐
│  Sideloadly                                              │
│                                                          │
│  IPA:      [ C:\Users\...\AIKeyboard-unsigned.ipa ][ ... ] │
│  Apple ID: [ 你的 Apple ID 邮箱                 ]        │
│                                                          │
│  [x] Sideload with Apple ID      ← 关键：必须勾          │
│  [ ] Use Anisette Authentication                        │
│                                                          │
│  Device:   [ iPhone (你的设备) ▼ ]                       │
│                                                          │
│                        [  Start  ]                       │
└──────────────────────────────────────────────────────────┘
```

| 步骤 | 操作 | 你会看到什么 |
|---|---|---|
| 1 | 双击打开 Sideloadly | 主界面如上 |
| 2 | **IPA** 行点 `...`，选中第 3.3 步下载的 `.ipa` | 路径填好 |
| 3 | **Apple ID** 填你的 Apple ID 邮箱（就是登录 App Store 那个） | — |
| 4 | 勾选 **Sideload with Apple ID** | 必须勾。不勾就是「只用已有证书」，你没证书会失败 |
| 5 | 确认 **Device** 下拉里选中你的 iPhone（显示设备名和 iOS 版本） | 没显示 → 回 4.2 检查驱动 |
| 6 | 点 **Start** | 日志区开始滚动 |
| 7 | 第一次会弹窗要 **Apple ID 密码** → 输入 | — |
| 8 | 若开了双重认证，会弹窗要 **6 位验证码** → 在 iPhone 上「设置」顶部弹窗或短信里拿 | 输进去继续 |
| 9 | 等待 `Installing...` → `Done` | 出现绿色 **Done**，iPhone 桌面出现「墨语」图标 |

> **界面长得不太一样？** Sideloadly 每个小版本的排版都会变（实测 0.71.0），但**四样东西永远是同一个**：
> ①一个填 **IPA 路径**的输入框（旁边有 `...` 浏览按钮）②一个填 **Apple ID** 的输入框
> ③一个 **Sideload with Apple ID** 的勾选框（有的版本是下拉菜单选 `Apple ID`）④**Device** 下拉 + 右下角 **Start**。
> 找齐这四样就能继续，别的按钮都不用碰。第一次点 Start 之后如果弹出「**Advanced Options**」，
> 直接点 **OK/继续**，**不要改任何选项**（尤其不要改 Bundle ID——改了会和扩展对不上）。

**Sideloadly 日志里你会看到的关键行（正常）**：

```text
Connecting to device...
Generating certificate...
Signing IPA...
  -> Signing Payload/AIKeyboard.app
  -> Signing Payload/AIKeyboard.app/PlugIns/AIKeyboardExtension.appex   ← 这一行必须有！
Installing...
Done.
```

> 🔴 **重点看 `PlugIns/AIKeyboardExtension.appex` 那一行**。Sideloadly 会**自动把 IPA 里的 PlugIns 里的扩展一并重签**——但如果 IPA 打包时就丢了 PlugIns 目录，Sideloadly 也无能为力，装上去的 App 里就没有键盘扩展，**键盘列表里永远不出现「墨语」**。如何确认 IPA 里有 PlugIns，见 4.4。

### 4.4 【必做】确认 IPA 里有键盘扩展（PlugIns）

> 这是「装好了但键盘列表里没有墨语」的 **第一大原因**。花 30 秒验一下，能省你两小时。

**方法一：Windows 资源管理器看（最简单）**

1. 把 `AIKeyboard-unsigned.ipa` **复制**一份，改名为 `AIKeyboard-unsigned.zip`
2. 右键 → **全部解压缩**
3. 进解压出的文件夹，逐层展开，**必须看到这个完整路径**：

```text
Payload\
└── AIKeyboard.app\
    ├── AIKeyboard                  ← 主程序
    ├── Info.plist
    └── PlugIns\                    ← 这个文件夹必须在！
        └── AIKeyboardExtension.appex\
            ├── AIKeyboardExtension ← 扩展主程序
            └── Info.plist
```

**方法二：PowerShell 一条命令**

```powershell
cd "C:\你的下载目录"
Copy-Item AIKeyboard-unsigned.ipa AIKeyboard-unsigned.zip -Force
Expand-Archive AIKeyboard-unsigned.zip -DestinationPath ipa_check -Force
Test-Path "ipa_check\Payload\AIKeyboard.app\PlugIns\AIKeyboardExtension.appex"
# 必须输出 True
Get-ChildItem "ipa_check\Payload\AIKeyboard.app\PlugIns" -ErrorAction SilentlyContinue
```

| 结果 | 含义 | 怎么办 |
|---|---|---|
| 输出 `True`，`PlugIns` 下有 `.appex` | ✅ IPA 正常，可以继续 4.5 | — |
| 输出 `False`，没有 `PlugIns` 文件夹 | ❌ **IPA 打包漏了扩展**。装上去键盘一定不出现 | 报告 Lead：workflow 的打包步骤没保留 `PlugIns`。**不要自己硬装**，装了也是白装 |
| 有 `.appex` 但里面没有 `Info.plist` | ❌ 打包损坏 | 报告 Lead 重新编译 |

> 免费 Apple ID 的**硬限制**：键盘扩展 `.appex` **必须和宿主 App 用同一张描述文件（provisioning profile）重签**，否则系统会拒绝加载扩展。Sideloadly 对 IPA 内的嵌套 appex 会自动这样处理——所以**必须让它处理到 PlugIns**，这就是为什么要先验 4.4。

### 5.3 键盘不显示？按这个树排查

```text
「设置 › 通用 › 键盘 › 键盘」列表里找不到「墨语」
│
├─ ① 有没有「添加新键盘…」里也找不到？
```

### 5.4 键盘显示了但空白 / 闪退 / 一直转圈

| 现象 | 最可能原因 | 解决 |
|---|---|---|
| 键盘区一片白，什么都不显示 | 扩展崩溃（常见于 Swift 版本/内存） | 杀掉宿主 App，重新切一次键盘；仍不行看 Console 日志（需 Mac）或报告 Lead |
| 点键盘立即闪退回系统键盘 | 扩展 `Info.plist` 的 `NSExtensionPrincipalClass` 写错 | 工程问题，报告 Lead（应为 `$(PRODUCT_MODULE_NAME).KeyboardViewController`） |
| AI 一直转圈不返回 | **完全访问没开** 或 **Key 没配** 或 **网络问题** | ①回 5.1 第 7 步开完全访问；②App 里配 Key；③换网络试 |
| 打字时键盘高度突然跳变 | 扩展内存告警 | 关掉其他 App 释放内存后重试 |

## 6. 路线 A · 第 6 步：配置 AI 服务商

### 6.1 在宿主 App 里配

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 打开桌面上的 **墨语** App | 首次进入是引导页 |
| 2 | 进入 **键盘 / AI 设置** → **服务商** → **添加** | 有 9 家内置预设（DeepSeek、OpenAI、通义、Kimi、GLM、火山方舟、OpenRouter、硅基流动等） |
| 3 | 选一家 → 填 **API Key** | baseURL 和模型名预设已填好，一般只需填 Key |
| 4 | 若用**自建中转站** → 选「自定义 / OpenAI 兼容」→ 自己填 **baseURL**（到 `/v1` 结尾通常即可，尾斜杠会自动归一化）、**模型名**、Key | — |
| 5 | 点 **测试连接** | 成功会显示「连接正常」+ 延迟毫秒 |
| 6 | 回上一页 → 点 **同步到键盘** | 见 6.2 |

**Key 存在哪？** 只存在你 iPhone 的 **Keychain（钥匙串）** 里，本地加密存储；本项目**没有任何服务器、没有账号、没有埋点**。App 被删除时 Keychain 项一般也会被清掉。

### 6.2 「同步到键盘」是怎么工作的（为什么必须按这个按钮）

因为**免费签名没有 App Group**，App 和键盘扩展是两个独立的沙盒，**不能直接读同一份配置**。本项目的降级方案是：

```text
① 在 App 里配好服务商 → 点「同步到键盘」
        │
        ▼
② App 把配置（不含 API Key 明文，Key 走另一条通道）
   序列化成一段 JSON，写入一个"具名剪贴板"
        │
        ▼
③ 切到墨语键盘 → 点工具条最右 ⚙️ 设置 → 点「从剪贴板导入」
        │
        ▼
④ 键盘扩展读取该剪贴板 → 解析 → 存进自己的 UserDefaults
        │
        ▼
⑤ 之后 AI 功能可用（Key 仍需在键盘设置里单独填一次，或在 App 里允许包含 Key 再同步）
```

| 常见疑问 | 答案 |
|---|---|
| 每次改配置都要同步吗？ | **是**。改了 baseURL / 模型 / Key 后都要再点一次「同步到键盘」 |
| 剪贴板里会有我的 Key 吗？ | 默认**不包含** Key（`PasteboardBridge.export(includeAPIKeys: false)`）。Key 需要你在键盘 ⚙️ 设置里单独输入一次；也可以选择「包含 Key 同步」（如果 App 里给了这个开关） |
| 会不会污染我的剪贴板？ | 用的是**具名剪贴板**（`com.moyu.config`），不会覆盖你复制的普通内容 |
| 每次粘贴都弹「允许粘贴」？ | iOS 16 起读取剪贴板会弹系统提示，点「允许」即可；这是系统行为，无法绕过 |
| 有 App Group 会怎样？ | 那就不需要同步按钮了，改配置立刻生效。但那需要 $99/年账号。**这就是免费方案的代价** |

## 8. 免费签名 vs 付费账号：你必须知道的限制

| 能力 | 免费 Apple ID | $99/年 开发者账号 |
|---|---|---|
| App 有效期 | **7 天**（到期需重签） | **1 年** |
| 可签 App 数量 | 最多 **3 个 App ID**（同一时间） | 几乎不限 |
| 设备数量 | 最多 **10 台/年** | 100 台 |
| App Group（App↔键盘共享数据） | ❌ **不支持** | ✅ 支持 |
| iCloud / Push | ❌ 不支持 | ✅ 支持 |
| TestFlight 分发 | ❌ 不支持 | ✅ 支持 |
| 分发给朋友 | ❌ 只能用自己的 ID 签给自己 | ✅ 可 TestFlight 邀请 |
| 上架 App Store | ❌ 不能 | ✅ 可以 |
| 配置迁移 | 需「同步到键盘」手动搬 | App Group 自动共享 |

### 8.1 没有 App Group 的现实影响

| 影响 | 表现 | 我们的降级方案 |
|---|---|---|
| App 和键盘配置不同步 | App 里加了服务商，键盘里看不到 | 点「同步到键盘」→ 键盘 ⚙️ → 从剪贴板导入 |
| API Key 要填两次 | App 填一次、键盘填一次 | 同上（或在 App 里勾选「同步时包含 Key」） |
| 用户词库不共享 | 键盘学的词，App 里看不到 | 词库本来就只在键盘侧用，影响很小 |
| 剪贴板历史不共享 | 同上 | 仅键盘侧用 |

> **为什么不能硬开 App Group？**
> 免费 Apple ID **无法签发** `com.apple.security.application-groups` 这个 entitlement。工程里如果保留它，签名阶段会直接失败（报 `Provisioning profile doesn't include the application-groups entitlement`）。所以：
> - `ios/Config/AIKeyboard.entitlements` 默认是**空的**
> - 同目录留了 `AIKeyboard.entitlements.appgroup.sample` 作为「以后有付费账号时怎么开」的参考，**不要直接改名使用**

## 9. 7 天续签：三种方式对比

免费签名的 App **7 天后必然失效**（点开闪退、提示「无法验证 App」）。到期前或到期后重做一次即可，**App 里的配置和 Key 不会丢**（Keychain 不清、UserDefaults 不清）。

| 方式 | 频率 | 需要什么 | 优点 | 缺点 | 推荐度 |
|---|---|---|---|---|---|
| **① Sideloadly 手动重签**（本文路线） | 每 7 天 1 次，约 5～10 分钟 | Windows + 数据线 + IPA | 免费、可控、无额外软件常驻 | 要记得手动做；每次要连电脑 | ⭐⭐⭐⭐⭐ **首选** |
| **② AltStore + AltServer** | 自动，后台每 7 天刷 | Windows 装 AltServer，且**电脑常开 + 与 iPhone 同一 Wi-Fi** | 装一次后面基本不用管 | AltServer 必须常驻（托盘）；同一 Wi-Fi；Windows 上偶发连不上；**还要在 iPhone 装 AltStore（需先用 AltServer 装一次）** | ⭐⭐⭐ |
| **③ Xcode 重新 Run**（有 Mac 时） | 每 7 天 1 次 | Mac + Xcode + 数据线 | 最稳，编译+装一步到位 | 必须有 Mac | ⭐⭐⭐⭐（有 Mac 就是最优） |

### 9.1 为什么本文推荐 Sideloadly 而不是 AltStore

| 对比点 | Sideloadly | AltStore |
|---|---|---|
| 额外常驻程序 | 无（用完就关） | **AltServer 必须常驻**，且要与手机同 Wi-Fi |
| Windows 稳定性 | 高（本地签名，直连 USB） | 中（依赖 Wi-Fi 发现 + 后台服务） |
| 首次配置 | 装 3 个软件，5 分钟 | 装 AltServer + 在 iPhone 装 AltStore + 登录 + 信任，约 20 分钟 |
| 续签体验 | 手动，但 5 分钟搞定 | 全自动，但你得保证电脑 7 天内一直开着 |
| 失败排查 | 日志直白 | 网络发现失败时基本无解 |
| 结论 | **推荐**：不依赖电脑常开，出差/关机也不影响（只要记得到期重签） | 适合「电脑 24 小时开机 + 固定 Wi-Fi」的人 |

> **不推荐 AltStore 的核心原因**：它要求 **Windows 上 AltServer 服务常驻 + iPhone 与电脑同一 Wi-Fi**。一旦你换网络、关机、休眠，自动刷新就断，反而更容易在第 8 天突然失效。

### 9.2 续签操作步骤（Sideloadly，5 分钟）

```text
① 到期表现：点开「墨语」图标 → 闪退 / 提示「无法验证 App」/ 图标变灰
② 打开 Windows 上的 Sideloadly（IPA 路径还在，一般不用重选）
③ iPhone 用数据线连电脑 → 手机上点「信任」
④ Sideloadly 点 Start → 输 Apple ID 密码 → 输 2FA 验证码
⑤ 等 Done → iPhone 上图标恢复
⑥ 若提示「不受信任的开发者」→ 设置 › 通用 › VPN与设备管理 → 信任
⑦ 打开 App 确认能进 → 切到墨语键盘打几个字确认正常
```

> **不需要重新下载 IPA**（同一个文件可以反复签）。但如果你**改了代码**，必须回第 3 章重新跑 GitHub Actions 拿新 IPA。

## 10. 报错对照表（16 条，含 Windows 特有）

| # | 报错 / 现象 | 出现位置 | 原因 | 解决办法 |
|---|---|---|---|---|
| 1 | `Untrusted Developer`（不受信任的开发者） | iPhone 打开 App 时 | 新装的开发版 App 需要手动信任 | 设置 › 通用 › VPN与设备管理 › 开发者App → 点你的 Apple ID → **信任** |
| 2 | `Unable to install "墨语"` / 安装到一半失败 | Sideloadly / iPhone | ①7 天证书过期 ②Bundle ID 冲突 ③设备上已有同 ID 的旧版本 | ①重新签名 ②改 Bundle ID ③先在 iPhone 上删掉旧「墨语」再装 |
| 3 | `Provision.cpp:150`（Sideloadly 弹窗） | Sideloadly | Apple ID 认证/证书生成失败。常见于密码错、2FA 未完成、Apple 服务临时故障 | ①确认 Apple ID 密码正确 ②重开 Sideloadly 重试 ③换网络（关代理/VPN）④确认 Apple ID 已开启双重认证 |
| 4 | `Unable to connect to device` / 设备列表为空 | Sideloadly | iTunes 驱动没装好（尤其装了 Apple 官网 exe 版 iTunes） | 卸载 iTunes → 从**微软商店**重装 iTunes + iCloud → 重启电脑 → 重新插线 → iPhone 点「信任」 |
| 5 | `Failed to install: device not found` | Sideloadly 日志 | 手机锁屏 / 数据线只能充电 / 驱动掉了 | 解锁手机、换原装或认证数据线、换 USB 口（直插主板，别用前置 HUB）、重开 iTunes 确认能识别 |
| 6 | `AMFI: code signature invalid` / 装完闪退 | iPhone Console / 闪退 | 签名不完整（常见于 IPA 里扩展没被重签，或用了别人的证书） | 确认 Sideloadly 日志里有 `Signing ... PlugIns/...appex`；重新完整签一次 |
| 7 | `No signing certificate "iOS Development" found` | Xcode | 没登录 Apple ID / 没选 Team | Xcode › Settings › Accounts 登录 Apple ID → target 的 Signing 里选 Personal Team → 勾 Automatically manage signing |
| 8 | `App ID cannot be registered` / `Failed to register bundle identifier` | Xcode | Bundle ID 被占用了（免费账号全球唯一） | 换成更独特的，例如 `com.你的名字拼音.moyu2026`；两个 target 一起改 |
| 9 | `The maximum number of apps for free development profiles has been reached` / `Your maximum App ID limit has been reached` | Sideloadly / Xcode | 免费账号同时最多 **3 个 App ID**，你签过太多 App 了 | ①去 <https://developer.apple.com/account> 删掉不用的 App ID（免费账号也能删）②或换一个 Apple ID |
| 10 | `The maximum number of devices ... has been reached` | Sideloadly | 免费账号一年最多 **10 台设备** | 换 Apple ID，或等年度重置 |
| 11 | 键盘列表里**找不到「墨语」** | 设置 › 通用 › 键盘 › 键盘 | ①IPA 里没 PlugIns（打包漏扩展）②扩展 Info.plist 的 `NSExtensionPointIdentifier` 错 ③没重启手机 | ①按 4.4 验证 IPA ②工程问题报告 Lead ③重启 iPhone 再看 |
| 12 | 键盘列表有「墨语」但切过去**白屏/闪退** | 打字时 | 扩展崩溃：`NSExtensionPrincipalClass` 错、内存超限、Swift 版本不匹配 | 先重启手机；仍不行 → 工程问题，报告 Lead 并附上 Console 日志 |
| 13 | AI **一直转圈 / 提示需要完全访问** | 键盘 AI 面板 | ①「允许完全访问」没开 ②Key 没配 ③网络不通 | ①设置 › 通用 › 键盘 › 键盘 › 墨语 › 开「允许完全访问」②App 里配 Key 并「同步到键盘」③换 Wi-Fi/4G 试 |

| 15 | `Provisioning profile doesn't include the application-groups entitlement` | Xcode 签名 | 免费账号不能开 App Group，但工程里加了 | 移除 entitlements 里的 App Group（本项目默认已空）；见第 8 章 |

## 11. 常见疑问速答（详细见 `docs/05-常见问题.md`）

| 问题 | 一句话答案 |
|---|---|
| 7 天到期会怎样？ | App 打不开、键盘失效，但**数据不丢**；重签一次即可（第 9 章） |
| 换手机怎么办？ | 新手机重新走第 4～6 章；配置可以重配，或在旧 App 里「同步到键盘」后把那段 JSON 复制出来 |
| 能给朋友装吗？ | **不能**（免费账号只能签给自己，且 App ID 绑定你的账号）。想给朋友装需要他的 Apple ID 自己签，或 $99 账号 + TestFlight |
| 一定要开完全访问吗？ | **打字不用**，**AI 必须开**（联网权限） |
| 会不会偷我 Key？ | 不会。纯本地，Key 只在你 iPhone Keychain 里（见第 6 章 + docs/05） |
| 会不会上架 App Store？ | 不会，个人自用项目，也不满足上架条件（无开发者账号） |
| 有没有更省事的路？ | 有：买 $99/年账号 → 1 年不用管，还能 TestFlight 给朋友。但项目定位是「零成本自用」 |
