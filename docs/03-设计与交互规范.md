## 1. 产品与视觉定位

**一句话**：墨语是一个**看起来像 iOS 自带的**输入法——它不该让你觉得「装了个第三方 App」，而该让你觉得「系统键盘更新了」。

| 维度 | 我们的选择 | 反例（明确禁止） |
|---|---|---|
| 语言 | iOS 17–26 系统语言：大标题、分组卡片、胶囊按钮、玻璃材质 | Material Design 的悬浮按钮（FAB）、涟漪、抽屉 |
| 色彩 | 中性灰 + **一个** accent 蓝（`#0A84FF`，即 iOS 系统蓝） | 彩虹渐变、霓虹色、多主色、品牌紫 |
| 层级 | 用**留白和材质**分层，不用粗边框和重投影 | 1px 灰边框 + 大阴影的「卡片套卡片」 |
| 动效 | 只用物理感的 spring，位移克制（≤ 一个屏高） | 弹跳、旋转、缩放超过 1.05、炫技过渡 |
| 图标 | SF Symbols（主 App）/ Unicode 几何符号 + emoji（键盘内） | 自绘线性图标集、彩色插画、emoji 当主图标用在大标题 |
| 字体 | 系统字体（PingFang SC 中文 / SF Pro 数字英文） | 网络字体、书法字体、字重超过 3 种 |

**同框判据（验收时用）**：把墨语的截图和 iMessage、微信的截图并排放在一张画布上——
1. 圆角半径是否同一量级（16 / 24，不是 4 也不是 40）？
2. 分隔线是否是**半透明 0.5pt**（`#3C3C434D`），而不是 1pt 纯灰？
3. 主色是否只有一处蓝？
4. 字重是否只用 regular / medium / semibold 三档？
5. 有没有任何元素「跳出来」比系统控件更抢眼？

五条全过才算合格。任何一条不过，先删装饰，不要加装饰。

## 2. 设计原则（五条，冲突时的裁决依据）

1. **键盘是主角，AI 是能力不是入口。**
   键盘 258pt 的每一 pt 都属于打字。AI 能力以 40pt 的**工具条**形式寄生在候选栏下方，不额外占一行、不弹全屏。用户不点 AI 时，它应该「几乎不存在」。
   *推论*：任何让键盘常态高度超过 258 的想法都要被否决；AI 面板只能是「展开态」，不能是「默认态」。

2. **文字优先于图形。**
   AI 的结果是文字，就要让它舒服地读。结果卡片正文 `result` 16/24（行长 ≤ 34 个汉字时最佳），按钮是文字不是图标，流式光标 1pt 宽而不是闪烁方块。
   *推论*：宁可少一个图标，也不要把按钮做成纯 icon（除返回/关闭/复制这三个系统级语义）。

3. **系统一致性 > 品牌个性。**
   能用系统组件（`List`、`Form`、`.navigationTitle`、`Toggle`、`Picker`）就用。自定义只在系统做不好的地方：键帽、候选栏、AI 工具条、结果卡片。
   *推论*：主 App 的设置页应该长得像「设置.app」，不是像「某 App 的设置」。

4. **深色不是反色，是重新配色。**
   深色模式不是把浅色乘 -1，而是独立一套（`color.dark` 36 键独立取值）。深色下**降低饱和度、抬高背景亮度**（`bg.surface #1C1C1E` 而不是 `#000000`），避免纯黑纯白的高对比刺痛。
   *推论*：每个新颜色键都必须同时给 light 和 dark 两个值，缺一个就是 P1。

5. **免费签名下的性能就是体验。**
   扩展内存 40–60MB、7 天续签、无 App Group。这意味着：不加载大图、不用复杂模糊层叠、动画不超过 2 层同时进行、启动不做网络预热。
   *推论*：`.ultraThinMaterial` 全键盘最多 2 处（AIBar 与结果卡头部）；emoji 页纯 Unicode 不用图片资源。

## 3. iOS 17–26 语言 & iOS 16 降级（部署目标 16.0，必须双轨）

我们的**设计语言按 iOS 17–26 画**（大标题、分组卡片、胶囊、玻璃），但**代码必须能在 iOS 16 跑**。做法不是「降级设计」，而是「**同一设计，两种材质实现**」。

### 3.1 三个层次

| 层次 | iOS 17–26 表现 | iOS 16 降级 | 用户感知差异 |
|---|---|---|---|
| **布局层** | 大标题 + 分组卡片 + 胶囊全用 | **完全一样**（这些 API iOS 16 都有） | 无 |
| **材质层** | `.ultraThinMaterial` 真实毛玻璃（实时采样背后内容） | `surface.opacity(0.94)` 不透明覆盖 + 0.5pt `separator` 描边 | 有，但只在滚动时能看出「背后不模糊」 |
| **动效层** | `spring(response:dampingFraction:)` 全用 | **一样**（`spring` 从 iOS 13 就有） | 无 |
| **新 API 层** | `.scrollTargetBehavior`、`.symbolEffect`、`.contentTransition(.numericText())`、`.rect(cornerRadius:)` | **一律不用**，见 3.3 替代 | 无（替代方案观感等价） |

### 3.2 材质降级的确切写法

唯一允许出现 `.ultraThinMaterial` 的地方是 `GlassSurface`（见 `design/组件库.md` §L0）。它必须内部判断：

```swift
// 伪代码，实际实现见 ios/AIKeyboard/Components/GlassSurface.swift
@Environment(\.accessibilityReduceTransparency) private var reduceTransparency

var body: some View {
    content
        .background {
            if reduceTransparency || !isIOS17OrLater {
                Theme.surface.opacity(0.94)
            } else {
                Rectangle().fill(.ultraThinMaterial)   // 注意：用 Rectangle().fill()，
                                                       // 不要用 .background(.ultraThinMaterial, in: .rect(...))
                                                       // —— .rect(cornerRadius:) 是 iOS 17 API
                    .overlay(Rectangle().strokeBorder(Theme.separator, lineWidth: 0.5))
            }
        }
}
```

**三条红线**：
1. 除 `GlassSurface.swift` 外，**任何文件出现 `.ultraThinMaterial` 即 P1**。
2. **禁止 `.rect(cornerRadius:)` / `.rect(topLeadingRadius:...)`**（iOS 17）。圆角一律用 `.clipShape(RoundedRectangle(cornerRadius: Theme.Radius.x, style: .continuous))`。
3. **禁止 `.symbolEffect` / `.contentTransition(.numericText())` / `.scrollTargetBehavior` / `.scrollPosition` / `PhaseAnimator`**（均 iOS 17+）。替代：`withAnimation` + `.opacity` / `ScrollViewReader.scrollTo(_:anchor:)`。

### 3.3 新 API → 替代方案对照

| iOS 17+ API | 想做的事 | iOS 16 替代 |
|---|---|---|
| `.scrollTargetBehavior(.viewAligned)` | 候选栏吸附对齐 | `ScrollViewReader` + `scrollTo(id, anchor: .leading)`，在 `onChange(of: selectedIndex)` 里调 |
| `.symbolEffect(.bounce)` | 点 AI 能力时图标弹一下 | `scaleEffect(pressed ? 0.92 : 1)` + `withAnimation(.spring(response: 0.2, dampingFraction: 0.6))` |
| `.contentTransition(.numericText())` | 生图「已等待 N 秒」数字翻动 | 直接 `Text("\(n)")`，数字变化本身足够；不要做 `.transition(.opacity)`（会闪） |
| `.rect(cornerRadius:)` | 局部圆角 | `RoundedRectangle` + `.clipShape`；需要单边圆角时用 `UnevenRoundedRectangle`（**也是 iOS 17**）→ 改为叠两个 `RoundedRectangle` |
| `.containerRelativeFrame` | 按容器比例定尺寸 | `GeometryReader` + 显式乘系数 |
| `.background(.regularMaterial, in: shape)` | 形状内材质 | `GlassSurface { ... }` 包一层 |

## 4. 颜色语义表（不要记 hex，记语义）

**唯一真相**：`design/tokens.json` 的 `color.light` / `color.dark`（各 36 键，键集完全一致）。
**唯一入口**：`Theme.*`（`ios/Shared/Theme/Theme.swift` 已实现全部 36×2 键）。
**红线**：**任何 View 里出现 `Color(hex:)` 或 `#RRGGBB` 字面量 = P1**（QA 脚本已校验，当前 `hardcoded_hex=0`，别打破它）。

### 4.1 语义分组（按「什么时候用」记）

| 语义组 | 键名 | 什么时候用 | 禁忌 |
|---|---|---|---|
| **键盘底与键** | `bg.keyboard` `bg.key` `bg.key.function` `bg.key.pressed` `bg.key.function.pressed` | 只在键盘扩展里 | 主 App 里**不要**用 `bg.keyboard` |
| **面与卡片** | `bg.surface` `bg.surfaceElevated` `bg.surfaceGrouped` `bg.glassTint` | 主 App 的页面底 / 卡片 / 分组底 / 玻璃叠加色 | 键盘里用 `bg.surface` 会显得脏 |
| **文字** | `text.primary` `text.secondary` `text.tertiary` `text.placeholder` `text.onAccent` | 三级递进，第四级 only 占位符 | 不要用 `.opacity()` 造灰色文字，用 `text.secondary` |
| **强调** | `accent` `accent.soft` `accent.pressed` | 首候选、主按钮、选中态、返回键 | **一屏只能有一处实心 accent 面积 > 44×44** |
| **状态** | `success` `warning` `danger` + `.soft` 变体 | 连接成功点、警告条、错误文案 | `.soft` 只用于底色，不用于文字 |
| **分隔** | `separator` `separator.opaque` `candidate.separator` | 0.5pt 半透明 / 需要确定可见时 / 候选栏内 | 分隔线粗细只允许 0.5 或 1 |
| **候选栏** | `candidate.bar` `candidate.selected` `candidate.separator` | 候选栏背景 / 选中项底 / 项间线 | — |
| **胶囊** | `chip.bg` `chip.bg.pressed` `chip.text` `chip.border` | AI 工具条、语气选择、标签 | 胶囊底色必须半透明（依赖背后材质） |
| **其他** | `keyShadow` `keyboardTopShadow` `overlayScrim` `ai.glow` | 键帽投影 / 键盘顶部投影 / 模态遮罩 / AI 辉光 | `ai.glow` 只用于生图进度环，**不得**用于按钮发光 |

### 4.2 颜色的三条硬规则

1. **半透明颜色必须先合成再测对比度。** `chip.bg` 是 `#FFFFFF1F`（12% 白），它的实际观感取决于背后的 `bg.keyboard`。直接拿 `#FFFFFF1F` 算对比度会得到荒谬的 1.00。规则：**半透明色只用于底色，文字一律用不透明色**（`chip.text` 是 `#FFFFFF`）。
2. **深色下不增面积，只降饱和。** 深色的 accent 用 `#0A84FF`（同浅色），但 `accent.soft` 从 `#0A84FF1A`(10%) 提到 `#0A84FF33`(20%)，因为深色底上 10% 看不见。
3. **`bg.keyboard` 是键盘的「地面」，永远不透明。** 它必须能盖住背后的宿主 App，否则用户会看到穿透的聊天内容。

## 5. 字号阶梯表

**规则差异（重要）**：
- **键盘域**（扩展内一切文字）：**固定字号，不随 Dynamic Type 缩放**。理由：键盘高度锁死 258pt，字号放大必然撑破布局；iOS 原生键盘也是这么做的。
- **主 App 域**：跟随 Dynamic Type 缩放，但用 `.dynamicTypeSize(...DynamicTypeSize.accessibility2)` 限幅，防止极端字号把设置页撑烂。

| 令牌 | 字号/字重/行高 | 用在哪 | 域 |
|---|---|---|---|
| `largeTitle` | 34 / bold / 41 | 主 App 大标题（「设置」「AI 试验场」） | 主 App |
| `title` | 20 / semibold / 25 | 导航标题、Sheet 标题、区块大标题 | 两域 |
| `headline` | 17 / semibold / 22 | 列表项主文字、按钮文字 | 两域 |
| `button` | 17 / semibold / 22 | `PrimaryButton` / `SecondaryButton` 的中号 | 两域 |
| `candidate` | 17 / regular / 22 | **候选栏候选词**（首候选改 semibold） | 键盘 |
| `key` | 22 / regular / 26 | **键帽字母** | 键盘 |
| `result` | 16 / regular / 24 | **AI 结果卡正文**（流式文字） | 键盘 |
| `body` | 15 / regular / 20 | 正文、输入框、设置项副标题 | 两域 |
| `monoDigit` | 16 / medium / 20 | 生图「已等待 8 秒」等数字（等宽，防跳动） | 两域 |
| `chip` | 13 / medium / 18 | **AI 工具条 chip 文字**、语气胶囊 | 键盘 |
| `footnote` | 13 / regular / 18 | 说明文字、隐私提示 | 主 App |
| `caption` | 12 / regular / 16 | 最小的辅助文字（键帽「空格」、分页提示） | 两域 |

**禁止**：`.system(size:)` 直接写字号（QA 会判 `magic_font`，当前为 0）；自定义字重超过 regular/medium/semibold/bold 四档；在键盘里用 `.dynamicTypeSize`。

## 6. 间距与圆角刻度表

**只允许用刻度上的值。** 需要 10pt 就选 8 或 12，不要写 10。

### 6.1 间距（`spacing`）

| 令牌 | 值 | 典型用途 |
|---|---:|---|
| `xs` | 2 | 图标与文字之间的微调、分隔线内缩 |
| `sm` | 4 | chip 内部左右、小图标外边距 |
| `md` | 8 | **最常用**：卡片内元素间距、按钮组间距、AIBar 内边距 |
| `lg` | 12 | 卡片内边距、列表项上下 |
| `xl` | 16 | **屏幕左右边距**（= `screenMargin`）、卡片外边距 |
| `xxl` | 24 | 分组之间、Sheet 顶部 |
| `xxxl` | 32 | 大区块之间、空状态上下 |
| `screenMargin` | 16 | 主 App 所有内容的左右边距（唯一值） |
| `sectionGap` | 28 | 两个 `SectionHeader` 分组之间 |
| `rowMinHeight` | 44 | 所有可点击行的最小高度（= `minTapTarget`） |

### 6.2 圆角（`radius`）——iOS 用 `.continuous`（superellipse），不是普通圆弧

| 令牌 | 值 | 用在哪 | 备注 |
|---|---:|---|---|
| `small` | 6 | 小标签、缩略图角标 | 少用 |
| `key` | 8 | **键帽** | 键帽必须连续曲率 |
| `control` | 10 | 小按钮、分段控件内块 | |
| `thumbnail` | 12 | 81×81 缩略图 | |
| `chip` | 14 | **胶囊 chip**（高 30 → 15 才是真胶囊，这里用 14 是有意的近胶囊） | 若高度变化，用 `capsule` |
| `card` | 16 | **卡片**（主 App 卡片、AI 结果卡） | 最常用 |
| `sheet` | 24 | Sheet 顶部、键盘内面板 | |
| `capsule` | 999 | **真正的胶囊**（`Capsule()`），按钮、候选选中底 | 值只是占位，实现用 `Capsule()` |

**红线**：`.cornerRadius(x)` 已废弃且不支持连续曲率 → **必须** `.clipShape(RoundedRectangle(cornerRadius: x, style: .continuous))`。

## 7. 材质与 iOS 16 降级

`design/tokens.json` 的 `material` 组定义了 4 种材质，**全部通过 `GlassSurface(level:)` 使用**：

| 级别 | SwiftUI | 模糊半径 | 用在哪 | 背后必须有内容 |
|---|---|---:|---|---|
| `.bar` | `.ultraThinMaterial` | 20 | **AI 工具条**、候选栏顶边、键盘顶边 | 是（能看到宿主 App） |
| `.card` | `.thinMaterial` | 24 | 主 App 卡片、结果卡头部 | 是 |
| `.sheet` | `.regularMaterial` | 30 | 键盘内设置面板、主 App Sheet | 是 |
| `highlight` | 线性渐变 `#FFFFFF40 → #FFFFFF00`，高 45% | — | 键帽顶部、卡片顶部高光 | 否（叠加层） |

**iOS 16 / 降低透明度降级**：`GlassSurface` 内部自动改用 `Theme.surface.opacity(0.94)` + 0.5pt `Theme.separator` 描边（`alpha` 参数见 tokens：`.bar` = 0.94，`.card` / `.sheet` = 1.0）。**业务代码零改动**。

**性能预算（免费签名扩展的内存红线）**：同一时刻屏幕上**最多 2 个** `GlassSurface`。键盘字母页只有 AIBar 一个；结果态是 AIBar + 结果卡头部两个。三层材质叠加（如 Sheet 里再放卡片再放 chip）**禁止**。

## 8. 组件清单（详规见 `design/组件库.md`）

**命名归一是硬契约**——两个 UI 智能体必须用同一套名字，否则会出现两套实现。

| 组件 | 域 | 一句话职责 | 关键约束 |
|---|---|---|---|
| `GlassSurface` | 两域 | **唯一**允许出现 material 的容器 | 3 个 level，自动降级 |
| `PillChip` | 两域 | **唯一**胶囊 | 3 种 style：`.tool`(AIBar) / `.tone`(语气) / `.tag`(标签) |
| `PrimaryButton` / `SecondaryButton` | 两域 | 主/次按钮 | 3 个 size：large 50 / medium 44 / small 36 |

## 10. 动效与触感

### 10.1 动效表

| 场景 | 曲线 | 时长 | 实现 | Reduce Motion |
|---|---|---|---:|---|
| 键帽按下 | `easeOut` | 0.08 | `ButtonStyle` 内 `scaleEffect(0.96)` + 背景色变 `pressed` | 保留（极短，无眩晕） |
| **键盘展开（258→426）** | `spring(response: 0.35, dampingFraction: 0.82)` | 0.35 | **`UIViewPropertyAnimator` + `heightAnchor`**（见下） | 高度直接切换 |
| **键盘收起（426→258）** | `spring(response: 0.28, dampingFraction: 0.9)` | 0.28 | 同上 | 直接切换 |
| 页面（候选栏）切换 | `easeInOut` | 0.25 | `.animation(_, value: page)` | 交叉淡入 |
| 候选栏滚动跟随 | `easeOut` | 0.15 | `withAnimation` + `scrollTo` | 直接跳 |
| 流式光标呼吸 | `easeInOut.repeatForever` | 0.9 | `.opacity` 0.15→1.0 | **不呼吸**（静态 1.0） |
| Toast 出现/消失 | `spring(0.25, 0.85)` | 0.25 / 停留 2.0 | `.transition(.move(edge: .bottom).combined(with: .opacity))` | 淡入淡出 |
| 生图进度环 | `linear` | 随进度 | `Circle().trim(from:to:)` | 保留（信息性动画） |

**⚠️ 键盘高度动画的铁律**：**绝对不要**用 SwiftUI 的 `.animation(_, value: keyboardHeight)` 驱动键盘高度。键盘扩展的容器高度由 `inputView` 的 frame 决定，必须用 `UIViewPropertyAnimator` 改 `heightAnchor.constant`，并在 `viewDidLayoutSubviews` 里同步给 SwiftUI。用 SwiftUI 驱动会出现「抖动 / 高度跳变 / 候选栏上下漂移」——这是 docs/02 §4.7 明令禁止的。

```swift
// KeyboardViewController 内（示意）
func setKeyboardHeight(_ target: CGFloat, animated: Bool) {
    guard abs(heightConstraint.constant - target) > 0.5 else { return }
    heightConstraint.constant = target
    guard animated, !UIAccessibility.isReduceMotionEnabled else {
        view.layoutIfNeeded(); return
    }
    let isExpand = target > oldHeight
    UIViewPropertyAnimator(
        duration: isExpand ? Theme.Motion.expandDuration : Theme.Motion.collapseDuration,
        dampingRatio: isExpand ? 0.82 : 0.90
    ) { self.view.layoutIfNeeded() }.startAnimation()
}
```

## 11. 中文文案语气

### 11.1 四条规则

1. **第二人称、动词开头、不用「您」。** 「开启完全访问」不是「请您开启完全访问权限」。
2. **说清楚「为什么」和「怎么办」，不解释技术原理。** 「需要开启完全访问，AI 才能联网」而不是「键盘扩展默认沙盒禁止网络访问」。
3. **不用感叹号，不用 emoji 当标点。** 例外：`AIResultCard` 的生图失败态可以有一个 🎨（信息性）。
4. **数字与英文之间加空格**（`iOS 16`、`5–20 秒`、`8 秒`），中文标点用全角。

### 11.2 关键文案基线（**逐字照抄，不要改写**）

| 场景 | 文案 |
|---|---|
| 未配置 Provider | `还没有配置 AI 服务 · 点此设置` |
| 无完全访问权限 | `需要在"设置 › 键盘"中开启"允许完全访问"，AI 才能联网` |
| AIBar 禁用（无权限） | `开启完全访问后可用 AI ›` |
| AIBar 禁用（离线） | `网络未连接` |
| 生图进行中 | `绘制中…` + `已等待 8 秒 · 预计 5–20 秒` |
| 生图超时（>20s） | `仍在绘制，可继续等待` |
| 生图被拒 | `描述可能被服务端拒绝，换个说法试试` |
| 无候选 | `无匹配 · 长按退格清空` |
| 结果卡按钮 | `插入` `复制` `编辑` `重试` `关闭` |
| 语气选项 | `自然` `简洁` `礼貌` `正式` `热情` |
| 隐私说明 | `API Key 只存在本机钥匙串，不上传任何服务器` |
| 签名到期 | `签名剩余 6 天` |

### 11.3 AI 结果卡的语言气质

AI 生成的文字**不加工**（不自动加「以下是润色后的内容：」这类前缀）。用户点「润色」，结果卡里就该只有润色后的那段话本身——多一个字都是噪音。同理，「回复建议」给出的是**三种不同语气的完整回复文本**，不是「建议 1 / 建议 2 / 建议 3」标签。

## 12. 状态矩阵索引（完整 12 行见 `design/键盘布局规范.md` §5）

**任何 AI 相关组件必须处理全部 12 态，缺一即 P1。**

| # | 状态 | 触发 | 界面表现 | 谁能发请求 |
|---:|---|---|---|---|
| 1 | 空闲 | 默认 | AIBar 正常，6 个 chip 全亮 | — |
| 2 | 输入中 | 有拼音 | 候选栏出词，AIBar 不变化 | — |
| 3 | 加载中 | 请求已发未回 | AIBar chip 显示转圈，其余禁用 | 是 |
| 4 | 流式生成中 | 收到首个 delta | 结果卡 `StreamingText` + 光标 | 是 |
| 5 | 成功（文本） | 流结束 | `插入/复制/编辑/重试/关闭` | — |
| 6 | 成功（生图） | 图片到手 | 81×81 缩略图 + `复制图片` | — |
| 7 | **生图绘制中** | 生图请求发出 | **48pt 进度环 + 已等待 N 秒 + 预计 5–20 秒 + 取消** | 是 |
| 8 | 错误 | 4xx/5xx/超时 | `ErrorBanner` + `重试`；401 → `去设置` | 否 |
| 9 | **无完全访问权限** | 扩展未开全访问 | AIBar 整条禁用 + `开启完全访问后可用 AI ›` | **否（不发请求）** |
| 10 | **未配置 Provider** | 无有效配置 | AIBar 禁用 + `还没有配置 AI 服务 · 点此设置` | **否** |
| 11 | 离线 | 无网络 | AIBar 禁用 + `网络未连接` | **否** |
| 12 | 无候选 | 无匹配 | 候选栏显示 `无匹配 · 长按退格清空` | — |

**优先级**：`9 > 10 > 11 > 1`。即：没权限时**先提示开权限**，不要说「没配置」（用户会去配了 Provider 还是用不了，白折腾）。

**生图进度态的实现要点**（用户明确要求，最容易做错）：
- 用 `TimelineView(.periodic(from: .now, by: 1))` 每秒刷新「已等待 N 秒」，**不要**用 `Timer` + `@State`（扩展内存敏感）。
- 计时从**请求发出**开始，不是从收到响应开始。
- 进度环用 `expected: 5...20` 做**伪进度**（不是真实下载进度），到 20s 后停在 100% 但继续转，文案切「仍在绘制，可继续等待」。
- **必须有取消按钮**（用户可能等不及）。取消要真的 `URLSessionTask.cancel()`，不能只关 UI。
- 数字用 `monoDigit`（等宽），否则秒数变化时文字宽度跳变。
