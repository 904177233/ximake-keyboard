# 13 · 语音输入真机验证协议

> **适用**：墨语 iOS 输入法 · 真机 iPhone 14 Pro / iOS 27.0 · 免费 Apple ID 侧载（iloader 2.4.0 / Sideloadly）
> **目的**：用一张照着做就行的表，在 30 分钟内回答**唯一一个问题** —— iOS 到底让不让键盘扩展拿麦克风。
> **前提**：代码侧已全部就位（见 §5），本协议**只做平台放行与否的判定，不改任何代码**。
> **平台证据**：[`docs/08-AI输入法能力调研报告.md`](08-AI输入法能力调研报告.md) §5.1 ｜ **能力边界**：[`docs/09-iOS键盘扩展能力边界技术约束清单.md`](09-iOS键盘扩展能力边界技术约束清单.md) §1

## 0. 为什么要验证

一句话：**代码写完、静态检查全绿、Xcode 编译通过，都不等于 iOS 运行时愿意把麦克风交给一个键盘扩展进程。**

| 层 | 谁说了算 | 现状 |
|---|---|---|
| ① 代码（录音 + 端侧转写 + 面板 + 入口） | 我们 | ✅ 已完成 |
| ② Info.plist 权限声明（两个 usage description） | 我们 | ✅ 已在扩展 plist 顶层 |
| ③ **运行时是否放行（沙盒 + 扩展宿主）** | **iOS，我们控制不了** | ❓ **只有真机能证明** |

第 ③ 层的分歧：2014 年官方文档写「custom keyboards have **no access to the device microphone**」；但现网五家上架输入法都在键盘内做语音手势、开源 OSGKeyboard 的扩展 plist 直接声明了麦克风键、open access 文档的开发者责任段还把「voice data」与击键并列。**文档说不能，现网说能，只能实测。** 本协议只有两种结局：🟢 **放行** → 键盘内语音保留，进体验打磨；🔴 **不放行** → 按 §4 走「宿主 App 录音 + 剪贴板上屏」，键盘内只留引导卡片。

## 2. 六个验证步骤

> 每步固定三段：**做什么 → 预期看到什么 → 看到什么说明什么**。边做边在 §6 打勾；失败时把**屏幕上的中文文案原样抄下来** —— 那是判定分支的唯一依据。

### 步骤 1｜把键盘加进来并打开完全访问

**做什么**：设置 › 通用 › 键盘 › 键盘 › 键盘 › **添加新键盘…** › 选「墨语」→ 同页点「墨语」进详情 → 打开 **允许完全访问** → 弹窗点 **允许**。

**预期看到什么**：语言列表里出现「墨语」（带图标）；详情页「允许完全访问」由灰变绿；返回后键盘列表里「墨语」下方显示「完全访问已开启」。

**看到什么说明什么**
- ✅ 三项都对 → 前置条件 3/4/5 通过，进步骤 2
- ❌ 列表里根本没有「墨语」→ **扩展没装上**（IPA 丢了 `PlugIns/AIKeyboardExtension.appex`，或签名时扩展被裁掉）→ 回 [`docs/04`](04-安装与续签指南.md):419 排查树，**本协议中止**
- ❌ 有「墨语」但**没有「允许完全访问」这一项** → `RequestsOpenAccess` 没生效（plist 被覆盖 / 用错 target）→ 报 QA，中止
- ❌ 弹「允许完全访问」点了取消 → **必须**点允许，重做

### 步骤 2｜进任意聊天框，切到墨语

**做什么**：打开微信 / 备忘录 / 短信任选其一，点输入框唤起键盘 → 长按地球键 🌐 切到「墨语」。

**预期看到什么**：键盘变成墨语 26 键（或上次选的 9 键）；候选栏上方出现 AI 工具条 `✨润色` `💬扩写` `🌐翻译` `🧠回复` `🎨生图` `⚙️设置`；**工具条最右侧多出一个 `🎙️ 语音` 胶囊**（[`ios/AIKeyboardExtension/Views/AIBar.swift`](../ios/AIKeyboardExtension/Views/AIBar.swift):156-164）。

**看到什么说明什么**
- ✅ 看到 `🎙️ 语音` → `canUseVoiceInput == true`，进步骤 3
- ⚠️ **看不到胶囊** → `canUseVoiceInput == false`，依次查：①完全访问真的开了吗（没开时工具条是灰的并提示「需要完全访问」）②是否正在生成 AI 内容（`.busy` 时隐藏入口）③设备/地区是否支持语音识别（`SFSpeechRecognizer.isAvailable == false`，多见于模拟器与部分区域）。三条都排除仍不显示 → **报 QA（代码问题）**
- ❌ 工具条是灰的、只有一句「需要在设置›键盘中开启允许完全访问」→ 回步骤 1

### 步骤 3｜点麦克风按钮

**做什么**：在 AI 工具条上点 **`🎙️ 语音`** 胶囊 → 观察键盘变化。

**预期看到什么**：键盘整体变高（与 AI 对话页同高 438pt，[`ios/AIKeyboardExtension/Theme/KMLayout.swift`](../ios/AIKeyboardExtension/Theme/KMLayout.swift):336），候选栏与工具条被标题条替代；标题「**语音输入**」+ 左上角 ✕；中间 64pt 圆形麦克风按钮（🎤）+ 灰色 `0.0 s`；底部主按钮显示「**正在请求权限…**」。

**看到什么说明什么**
- ✅ 进入语音页 → 页面与入口接线正常，进步骤 4
- ⚠️ 点了只弹 Toast → 看文案：「当前环境不支持键盘内语音，可以到「墨语」App 里用语音」= `canUseVoiceInput == false`（回步骤 2 三条排查）；弹「完全访问」引导卡片 = 完全访问没开（回步骤 1）
- ❌ 键盘闪退 → 记下崩溃前最后动作，报 QA（P0）

### 步骤 4｜看有没有弹麦克风授权弹窗

**做什么**：进入语音页后**不要点任何东西**，静等 1–3 秒，观察屏幕中央是否出现系统授权弹窗。

**预期看到什么（两种都算正常）**
- **A（首次）**：弹「「墨语」想要访问麦克风」+ 用途说明 → 点 **允许** → 可能再弹「想要访问语音识别」→ 点 **允许**
- **B（已授权过）**：不弹窗，直接开始录音（麦克风按钮变红 ⏹，外圈三圈音量环随声音脉动）

**看到什么说明什么**
- ✅ **弹窗出现** → **最强证据：键盘扩展进程真的拿到了麦克风权限请求通道**。进步骤 5
- ✅ **不弹窗但直接进录音态** → 同样说明放行（之前已授权）。进步骤 5
- 🔴 **不弹窗，1–3 秒后直接失败**，文案「**无法启动麦克风（键盘扩展内常被限制）。请到宿主 App 里使用语音输入**」→ **平台拒绝 `AVAudioSession`**（`beginRecording()` 的 `setCategory` 抛错，[`ios/AIKeyboardExtension/Support/KMVoiceInput.swift`](../ios/AIKeyboardExtension/Support/KMVoiceInput.swift):206-217，`isPlatformUnsupported: false`）→ 判定表第 4 行 → 走 §4
- 🔴 **不弹窗，立刻失败**，文案「**当前系统不支持键盘内语音，可以到「墨语」App 里用语音输入再回来粘贴**」→ `isPlatformSupported == false`（同文件 :126，`isPlatformUnsupported: true`）→ 判定表第 5 行 → 走 §4
- 🔴 文案「**语音识别不可用**」→ 识别器不可用（:220）→ 先换语言包/换机复测；仍在 → 走 §4

> 💡 **关键区分技巧**：`isPlatformUnsupported: true` 的两条文案（:126 / :220）会在界面底部**额外显示一张黄色备选卡片**「先在 App 里用语音」（[`ios/AIKeyboardExtension/Views/KMVoicePanel.swift`](../ios/AIKeyboardExtension/Views/KMVoicePanel.swift):208-224，由 :181 的 `if showsUnsupportedFallback` 控制显示）。看到卡片 = 代码认为**平台不支持**；只有红字没卡片 = 代码认为**是临时错误**（权限/会话/网络）。

### 步骤 5｜说一句话

**做什么**：正常音量说一句 5–10 个字的中文，例如「今天下午三点开会」→ 观察屏幕中央的文字。

**预期看到什么**：音量环随说话变大；计时器从 `0.0 s` 往上走（最长 60 秒自动停，`KMVoiceInput.swift`:74）；麦克风按钮下方出现**逐字增长的灰色文字**（`shouldReportPartialResults = true`）；状态行从「请允许麦克风与语音识别权限」变「正在录音 x.x 秒 · 最长 60 秒」（`KMVoicePanel.swift`:259-260）。

**看到什么说明什么**
- ✅ **有逐字增长的文字** → 识别链路在工作。点 ⏹ 停止 → 步骤 6
- ⚠️ 音量环在跳但**文字一直不出** → 麦克风通了、识别没通（端侧模型没下载 / 语言包缺失 / 无网）。再等 3 秒；仍空则点停止看是否有「语音识别失败：…」（`KMVoiceInput.swift`:327）→ 判定表第 2 行
- 🔴 **音量环完全不动**（一直 0）→ 录音开始了但拿不到音频帧（`installTap` 在扩展里被静音，:238）→ 判定表第 2 行，报告里注明「权限给了但音频静音」
- 🔴 只说一句就自己停了 → 60 秒超时（`scheduleAutoStop`，:291）或识别器提前 final，重试一次即可

### 步骤 6｜看文字有没有上屏

**做什么**：点麦克风按钮 ⏹ 结束录音（或等自动结束）→ 等 1–3 秒看主按钮是否变「**完成并上屏**」→ 点它。

**预期看到什么**：状态行先「正在把你的话转成文字…」再「识别完成，点「完成并上屏」插入到输入框」；点按钮后键盘回字母页，**刚说的话已出现在聊天框光标处**，伴随轻微触感反馈。

**看到什么说明什么**
- ✅ **文字成功上屏** → 🟢 **平台放行，验证通过**。把步骤 4 的组合填进 §3
- ⚠️ 结果为空（点按钮没上屏，或提示「没有识别到内容，再说一次」）→ 判定表第 3 行
- ⚠️ 文字对了但**没进输入框** → 代码问题（`insertText` 或 `proxy` 为空），报 QA，不是平台问题
- ❌ 点「完成并上屏」后卡住 / 闪退 → 报 QA（P0）

## 4. 备选路径：宿主 App 录音 + 剪贴板上屏

**触发条件**：§3 判定为第 4 / 5 / 6 行（平台不放行，或识别链路在扩展内不可用）。

**为什么这条路一定能走**：宿主 App 是普通前台 App，麦克风与语音识别的权限**没有任何平台争议**。限制只有两条：①扩展**不能拉起宿主 App**（App Review 4.4.1「Launch other apps besides Settings」，扩展里 `UIApplication.shared` 也不可用）→ 只能用户手动切；②免费签名**没有 App Group** → 两进程不能共享 `UserDefaults`，唯一通道是**剪贴板**。

### 4.1 需要补的两处（现在还没有）

| 缺什么 | 位置 | 内容 |
|---|---|---|
| 宿主 App 的两个 usage description | [`ios/Config/App-Info.plist`](../ios/Config/App-Info.plist)（当前只有 `NSPhotoLibraryAddUsageDescription`:74，**缺麦克风与语音识别**） | 补 `NSMicrophoneUsageDescription` / `NSSpeechRecognitionUsageDescription`，文案与扩展 plist :78-82 一致即可 |
| 宿主 App 的录音页 | 建议新增一个独立视图 + 一个 `@MainActor` 控制器 | 见 §4.2 伪代码 |

### 4.2 伪代码（宿主 App 侧，iOS 16+ 可直接用）

```swift
// ① 权限（与扩展里同一套 API，App 内没有平台争议）
let mic = await AVAudioApplication.requestRecordPermission()   // iOS 17+；iOS 16 走 AVAudioSession
let speech = await SFSpeechRecognizer.requestAuthorization()   // 需 .authorized

// ② 录音 + 识别（结构与扩展里的 KMVoiceInput 完全一致，可直接复用其实现）
let recognizer = SFSpeechRecognizer(locale: Locale(identifier: "zh-CN"))
let engine = AVAudioEngine()
let request = SFSpeechAudioBufferRecognitionRequest()
request.shouldReportPartialResults = true
if recognizer.supportsOnDeviceRecognition { request.requiresOnDeviceRecognition = true }

try AVAudioSession.sharedInstance().setCategory(.record, mode: .measurement)
try AVAudioSession.sharedInstance().setActive(true)
let input = engine.inputNode
input.installTap(onBus: 0, bufferSize: 1024, format: input.outputFormat(forBus: 0)) { buf, _ in
    request.append(buf)                                        // 只 append，不缓存 PCM
}
_ = recognizer.recognitionTask(with: request) { result, error in
    if let result { partial = result.bestTranscription.formattedString }
    if result?.isFinal == true || error != nil { finish(partial) }
}
engine.prepare(); try engine.start()

// ③ 上屏：写剪贴板（这是唯一跨进程通道）
func finish(_ text: String) {
    let cleaned = text.trimmingCharacters(in: .whitespacesAndNewlines)
    UIPasteboard.general.string = cleaned                       // 通用剪贴板，最稳
    // 可选：同时写具名剪贴板，减少污染普通剪贴板
    UIPasteboard(name: UIPasteboard.Name("com.moyu.voice"), create: true).string = cleaned
    showToast("已复制到剪贴板，回到聊天框长按 → 粘贴")
}
```

### 4.3 键盘侧的配套文案（已经写好，不用改）

备选卡片已落地在 [`ios/AIKeyboardExtension/Views/KMVoicePanel.swift`](../ios/AIKeyboardExtension/Views/KMVoicePanel.swift):209-224，原文：

> **先在 App 里用语音**
> 键盘扩展内无法录音时，可以到「墨语」App 的语音页说一句话，复制结果，回到这里长按输入框粘贴。

这句话正好匹配上面的方案，**落地时无需改文案**，只要保证宿主 App 里真有那个「语音页」。

### 4.4 用户体验上的三个已知代价（写进 FAQ，不要隐瞒）

1. **要手动切 App 再切回来** —— 至少 4 次点击，比键盘内直录差一截；
2. **读剪贴板会弹「允许粘贴」**（iOS 16+ 系统行为，扩展无法绕过）；
3. **免费签名下无法用 App Group 自动回传** —— 剪贴板是唯一通道（[`docs/09`](09-iOS键盘扩展能力边界技术约束清单.md) §2 已写明）。

### 5.5 三个如实说明（别在验收时当成缺陷）

1. **`commitVoiceText(_:)` 当前没被调用**：面板的 `onCommit` 直接走 `model.insertText(text)`（`KeyboardRootView.swift`:216）。功能正常，属可清理的小冗余。
2. **宿主 App 里还没有语音页**：`ios/AIKeyboard` 下目前 0 处语音相关代码，`App-Info.plist` 也没有那两个 usage 键 → §4 的备选路径**若要启用必须先补**。
3. **`design/tokens.json` 没有 voice 令牌**：64 / 96 / 18 三个尺寸用 `// TOKEN:` 注释豁免，与全项目的硬编码检查兼容。
4. **没走 iOS 26 的 `SpeechAnalyzer` / `DictationTranscriber`**：这台 Windows 机器没有 Xcode 与 iOS 26 SDK，凭记忆写新 API 签名会在云端编译直接报错，所以统一走 iOS 10+ 就存在、iOS 26 依然可用的 `SFSpeechRecognizer` + `AVAudioEngine`（理由写在 `KMVoiceInput.swift`:7-12）。**这不影响本次验证结论**：麦克风能不能开、扩展让不让录音，与用哪套识别 API 无关；若验证通过、后续要用新 API，只需替换 `beginRecording()` 与转写回调两处。
5. **`isPlatformSupported` 的语义比设计稿宽松**：设计稿要求「iOS < 26 一律返回 false」，实现改成了「识别器可用即视为支持」（`KMVoiceInput.swift`:110-113）。代价是 iOS < 26 上也可能出现 `🎙️ 语音` 胶囊并尝试失败；好处是**旧系统上也能拿到一条「扩展里到底行不行」的实测数据**，不会因为系统版本被静默藏掉入口。若你要的是严格门禁，改这一处即可，`canUseVoiceInput` 与 UI 都不用动。
