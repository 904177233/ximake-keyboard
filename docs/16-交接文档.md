## 改掉的毛病

- 九宫格是假的：按 ABC 只打出 a。现在是真九宫格，左栏选拼音。
- 符号页没有入口，打不出逗号句号。现在主键盘有逗号句号，上滑问号叹号；字母键上滑打数字和符号。
- 打不了英文：所有字母都进拼音。现在有中/英键，Shift 能打大写。
- 长句只能整句选，错一个字要删光。现在选一个词，剩下的拼音接着转换。
- 回车在打字时把拼音和换行一起发出去。现在先确认原文，不会把半截拼音发出去。
- 润色结果接在原文后面，变成两段。现在是替换原文。
- 面板内容不更新：第一次读到的文字会一直用下去。现在每次打开都重读。
- 回复功能在输入框为空时报错，可那正是要回复的时候。现在先让你读复制的那句话。
- 翻译永远翻成英文。现在按原文判断方向，也能手选语言。
- 候选栏的箭头是收起候选，看不到更多候选。现在箭头是展开，工具入口另外给。
- 按键之间有死区，快打丢字。现在最近的键接住每次触摸，第二根手指落下时第一个键立刻出字。

都是用得少或者说不清用处的，要的话可以加回来：

- 对话里说「画一张」触发画图：现在 AI 面板有「画图」页签。

## 3.0.9 改了什么（第七轮反馈：设置页卡、App 和键盘不同步、纠错、颜色）

用户反馈：键盘设置页卡顿甚至卡死；键盘和 App 还是不能交流，改动不生效；希望纠错更强（打 nihaohaoma 能纠成你还好吗）；3.0.8 的键盘颜色不好看。

- **设置页卡顿（根因）**：每次重画都去钥匙串查每家服务有没有填 Key（首页那一行查一次，服务列表每家查一次），十来家服务就是二三十次 `SecItemCopyMatching`，全在主线程上。`KeychainStore` 现在把读过的结果缓存在内存里，写和删时更新缓存，键盘弹出、App 回到前台时清掉重读。
- **App 和键盘不同步（根因）**：以前两边各自判断走哪条路：有 App Group 就只写 App Group，没有就只写钥匙串（`SharedStore.setData` 和 `SharedBlob`）。只要两边判断得不一样（比如签名工具只给 App 开了 App Group），一边写的地方另一边根本不读。现在（`Storage/SharedSync.swift`）：
  - 写：同一份数据同时写进本地（有 App Group 时就是 App Group）、钥匙串访问组、系统通知状态值，每份带写的时间（毫秒）。
  - 读：每条路上各拿一份，用时间最新的；时间一样（旧版写的没带时间）时，有 App Group 信 App Group，否则信钥匙串，和以前一样。
  - 系统通知这条路不需要任何权限，App 和键盘一定都能读写，但别的 App 理论上也能读，所以只放键盘偏好、AI 对话偏好、服务列表（服务里有自定义请求头时不放），压缩后不超过 6000 字节。重启手机后清空，打开一次 App 又会写上。
  - API Key：App Group 打通时也存一份在 App Group 里（`moyu.apikey.<id>`），钥匙串共享没打通也能过去。两条都不通时 Key 只能在键盘里再填一次。
  - `SyncStatus`：App 和键盘各自把「App Group 能不能用、钥匙串能不能用、版本」写进系统通知，App 首页和键盘设置的「App 和键盘」一段同时显示两边的情况和最后走哪条路。**真机上还不同步时，先截这一段。**
- **纠错**：纠成三个字以上的现成短语时，每多一个字少扣 1 分（`longPhraseDiscount`）。`nihaohaoma` 本身能打成「你好好嘛」（−2.28），纠成「你还好吗」以前是 −3.51 出不来，现在 −1.51，排第二，标「纠错」。排第一的门槛从 2 提到 2.5。`tools/dict/typo_eval.py`：182 句打错一处的 102 句纠对排第一、16 句排第二；225 条打对的里 5 条出了纠错候选、1 条排第一。
- **颜色**：3.0.7、3.0.8 默认「背景跟随系统」，3.0.8 又把功能键改成系统那种中性灰，Claude 橙的暖色没了，用户说不好看。默认改回主题自己的底色；「背景跟随系统」留着，默认关。存储名字换成 `systemBackground309`，以前存下来的「开」不再生效。

## 3.0.8 改了什么（外观和打字逻辑整体过一遍）

用户说「把输入法全部优化一下，包括键盘美观和交互逻辑」。把键区绘制、触摸、顶栏和 `KeyboardSession` 的按键处理从头读了一遍，改了下面这些。浅色、深色都在模拟器里截图看过。

**外观**

- 背景透明时（3.0.7 起的默认），功能键以前还是主题自己的暖灰，放在系统的冷灰底上发脏。`MoyuPalette(theme:dark:translucent:)` 新增 `translucent`：功能键用中性的半透明色，深色下字母键也用半透明白，跟系统键盘一个路子。不透明的那套颜色还在（设置里关掉「背景跟随系统」时用）。
- 半透明的键不画下沿（下沿是垫在键下面的一整块，会透上来把键染暗）。气泡、语音面板单独用不透明的 `palette.popup`。
- 工具栏、候选栏右边缘渐隐（`EdgeFadeView`），滑出去的图标和候选不再被一刀切掉。
- 英文模式空格上写 English。数字页的窄空格不画小形象（宽度门槛 100：主键盘空格 114，数字页 81）。
- **深色跟不上（模拟器实测发现）**：键盘开着时系统切到深色，底变黑了，键盘还是白键。`textDocumentProxy.keyboardAppearance` 是开始输入那一刻的值，中途不变（实测一直报 2 也就是浅色）。现在只信它明说的「深色」，其余看 `traitCollection`，并用 `registerForTraitChanges` 监听。

**打字逻辑**

- 中文模式按了 Shift：没在组字时直接上屏大写字母，不进拼音（A 股、T 恤、OK）。
- 标点按前文调整（`IMECore/SmartPunctuation.swift`，有测试）：数字后的「。」是小数点、「：」是半角冒号；引号自动配对（前面有没配上的「“」再打就是「”」，换段后重新算）。
- 打了标点、符号或空格后清掉上一轮联想。以前打完逗号，候选栏还留着整句后面给的「，」「。」。
- 点英文补全会自动加空格；紧接着打 `. , ! ?` 这类标点时先把空格去掉。
- 组字中（或在对话、设置项里打字时）滑空格不再进「移动光标」状态。那时候移不了光标，只会把键盘盖住。
- 长按回车换行只在回车是「发送 / 搜索」这类时生效。以前回车本来就是换行时长按，会往普通文字里塞一个 `\r`。
- 上滑打数字符号的门槛从 16 点提到键高的 45%（至少 20 点），而且要主要是往上。快打时手指往上蹭、斜着滑去上一排的键，不再误出数字。
- 九宫格：每个键上滑或长按打对应的数字；1 键没在打字时是「符号」（进符号面板的标点页），打字时是「分词」。以前没在打字时按 1 是打一个 `'`。

**测试和模拟器**

- imecheck 加标点 8 项。
- 模拟器实测 20 步（加了九宫格、九宫格打字、数字页、符号页），截 44 张，后一半用 `simctl ui appearance dark` 切深色。绿色小字只在每一步的后半段显示，前半段截到的图是干净的，README 的图从这里取。小字最后一段是「外观 输入框报的/系统的/键盘用的」。
- `scripts/qa/static_check.py` 把 `UITraitUserInterfaceStyle` 当成了没定义的类型（它是 iOS 17 的系统类型），已加进白名单。跑检查时别用 `grep && git commit` 这种写法，grep 成功会把检查的失败盖掉。

## 3.0.6 改了什么（第五轮反馈：ü、分词、整句联想、纠错）

用户反馈：v 和 ü 会被自动分词，有些自动分词逻辑有问题；打一整句后联想差；基本没有纠错。

- **ü**：词库里 ü 统一写 v（lv、lve、nve），打 `lue`、`nue` 对不上，被切成 lu'e（路呃）。现在构建词库时给含 lve/nve 的词各加一份 lue/nue 写法（344 条）。`lve` 以前被切成 lv'e（绿萼）：这串字母本身就是一个音节时，切成两个音节的词不再加多音节奖励（Swift `qwertyTiles` 和 Python `Eval` 同步）。`lv` 首选从「率」改成「绿」（`extra_words.tsv`）。
- **古音污染分词（根因）**：单字的其它读音以前用 pypinyin 的全部读音，按默认读音词频的 12% 给，最高 3000。「不 fu」「被 pi」「还 fu」都到了 3000，比「皮」「付」还高，整句里到处是它们（pinan -> 副男）。现在用 rime-ice 的 8105 字表（GPL-3.0，`tools/dict/.cache/rime-ice/8105.dict.yaml`）按每个读音的真实字频分，占比不到 1% 的读音不收；字表里没有的字上限 200。
  下载：`curl -L -o tools/dict/.cache/rime-ice/8105.dict.yaml https://raw.githubusercontent.com/iDvel/rime-ice/main/cn_dicts/8105.dict.yaml`
- **简拼抢全拼**：整句都能切成完整拼音时，中间几个字母当简拼要多扣 6 分（bang 不再是 ba + ng「那个」）；简拼里每有一个 a/e/o 扣 4 分（hap 不再是「海岸炮」）。
- **纠错（重写）**：以前只在末尾 5 个字母里换相邻键，而且只排第二。现在整句 DP 分两层，允许一块词里打错一处（相邻键 5 分、交换 4 分、多打 5 分、少打 5.5 分，少打只补 aeiouhgn），纠完的整句比原来高 2 分以上排第一，否则排第二，都标「纠错」。`tools/dict/typo_eval.py`：182 句打错一处的，100 句纠对排第一、15 句排第二；225 条打对的句子和简拼里 0 条被纠错排第一。没有韵母的输入（wbzd）不纠。
- **整句联想**：以前按上屏内容的最后一个字补全词（我今天很忙 -> 碌），整句后面没有标点。现在：整句后先给标点（吗/呢结尾给「？」，啊/呀给「！」，其它给「，」「。」）；按这次上屏的最后一个词找下一个词，也按它记「后面常跟什么」（以前记在整句上，下次永远对不上）；单字补全只在只上屏一个字时用。`next.tsv` 加第四列：把 rime-ice 的多字短语切成词，数前后两个词的搭配（书面味重，只在前面不够 8 个时补 4 个）。`next_words.tsv` 加了 33 个聊天词（忙、到家、睡觉……）。
- **整句准确率**：HOLDOUT 40/45、UNSEEN 42/50（和 3.0.5 一样）；新加的 47 句切分歧义句 41 句全对，错的是 xian（先/西安）、qie（且/企鹅）这类本来就要打分隔符的。
- **imecheck**：加 ü 9 条、古音 2 条、bang 分词、5 条纠错排第一、4 条打对不纠、3 条联想，以及带纠错的长句耗时（不超过 40 毫秒）。

## 3.0.5 改了什么（第四轮反馈）

- **高度（模拟器实测确认）**：直接给 view 加高度约束，系统始终只给 216；在 view 里放一根上下贴边的竖条（`heightSpacer`），改它的高度，系统就按要的给，变高变矮都跟（242/261/288/388 实测）。以前三轮的「拖不动」「下面被切」都是这个原因。
- **简拼**：Swift 引擎在全拼前缀对不上时直接 `break`，多字母简拼（wbzd、wcgl）一次都没试过，只能一个字母一个字地拼。改成继续试到 6 个字母。简拼每段试 3 个词、每多一个字母 +3 分、前后字连成常用词 +2 分（Python `Eval` 同步）。简拼按打的字母也记进个人词库（`recordTyped`），选过一次下次排第一。单打 m/n 先给常用字。
- **词库**：并入 rime-ice 的 base.dict.yaml（GPL-3.0，16.6 MB，放 `tools/dict/.cache/rime-ice/`，不进仓库），新词门槛 1000，27.5 万词，`moyu.dict` 14.5 MB。HOLDOUT 40/45、UNSEEN 42/50（之前 39、40）；简拼测试 43 句全对 28 句（之前 24）。**注意 GPL-3.0：安装包里带了它的数据，对外发布要按 GPL 处理。**
  下载：`curl -L -o tools/dict/.cache/rime-ice/base.dict.yaml https://raw.githubusercontent.com/iDvel/rime-ice/main/cn_dicts/base.dict.yaml`
- **同步**：`SharedStore` 以前用「写一下再读一下」判断 App Group，没有权限时也能在本进程读写，误判成打通，于是谁都不往钥匙串里写。改用 `containerURL(forSecurityApplicationGroupIdentifier:)` 判断，并读 SideStore/AltStore 写的 `ALTAppGroups`。CI 另出 `AIKeyboard-appgroup-unsigned.ipa`（ad-hoc 签上 `ios/Config/Sideload-AppGroup.entitlements`）。App 首页和键盘设置显示实际打通情况。
- **语音结果**：另走系统通知的状态值（`NotifyChannel`，每个通知名 8 字节，拼起来传），不需要任何共享权限。
- **长按回车**：插入 CR LF（`\r\n`）。微信这类 App 只把单独的换行（`\n`）当发送，收到 CR LF 只换行。
- **画图**：可以只用选定的模型（`onlyConfiguredModel`），没额度时明说。
- **联网搜索**：`WebSearch` 抓必应结果页（cn.bing.com，不行再 www），关/自动/总是。网页结构变了会搜不到，这时按不联网回答。
- **CI**：apicheck 30 项（加画图单模型、没额度、必应解析、通知通道）；imecheck 加 m、wbzd、简拼学习。

## 3.0.3 改了什么（第二轮真机反馈）

用户反馈：即梦画不了、麦克风说系统不让录音、高度的 bug 还在、AI 对话用不了。

**键盘高度（模拟器实测确认的结论）。** 新增 `.github/workflows/sim-check.yml`：在 GitHub 的 `xcode-27` 机器上用 iOS 27 模拟器真的弹出墨语键盘，按 `MOYU_SIM_CHECK` 写好的顺序走各个页面，每隔几秒截图。键盘左上角的绿字是「要 / 给 / 可用 / 窗」四个高度。实测结果：

- 无论约束优先级是 999 还是 required、开不开 `allowsSelfSizing`、删掉约束重加，要 261、288、340、400，系统**都只给 216**。显示中改高度系统不理。
- 关掉 view 的 `translatesAutoresizingMaskIntoConstraints` 会让键盘整块变空白，不要用。
- 之前真机上下面的键被切掉，是因为我们按「要的」高度画，比系统给的窗口高。

所以现在：高度只在弹出前定一次（`lockedHeight`），显示中不再改；键区按实际可用高度排，不够就压缩；对话页不靠长高，在「打字」（输入行 + 键区）和「看回答」（消息占满）之间切换。改「低、标准、高」要收起键盘再打开才生效，真机上系统给不给还要看。设置页最下面有「键盘高度情况」一行，真机有问题时截这一行。

在模拟器里切到自己的键盘：实测版用私有的 `UIKeyboardInputModeController.setCurrentInputMode:`，只在 `MOYU_SIM_CHECK` 编译时存在，不进安装包。取截图用 `scripts/lead` 以外的临时脚本下载 artifact `sim-shots-xcode-27`。

**语音。** 苹果的文档写明自定义键盘不能用麦克风。现在点麦克风会用 `moyu://voice` 跳到 App 录音（App 开了后台音频，可以回到原来的 App 接着说），结果通过 `ios/Shared/Voice/VoiceBridge.swift` 回到键盘：打通时走共享存储（能看到实时文字、能点「说完了」），没打通时走带标记的剪贴板，键盘下次弹出自动放进输入框。真机上没验证过。

**即梦。** 默认模型改成 `doubao-seedream-5-0-pro-260628`，失败时按 用户选的 → 上次成功的 → 5.0 Pro → 5.0 Lite → 4.5 → 4.0 → 3.0 逐个试；4.5 和 5.0 Lite 用 `2K`。保存时用空提示词探测：401 是 Key 错，404/403 是没开通，400 说缺提示词就是能用，不出图不收费。没用真 Key 跑过。

**AI 对话。** 模型 400/403/404 时自动换一个能用的模型重发并存下来；403 不再一律说「Key 无效」；默认服务没 Key 而别的服务有 Key 时用有 Key 的；App 和键盘没打通时提示里说清楚。

## 词库怎么改

想让某个词排得更靠前：在 `tools/dict/extra_words.tsv` 加一行 `词<TAB>词频`，然后：

```
python tools/dict/build_binary.py --eval
```

`--eval` 会打印常见句子的整句转换结果。整句转换目前没有上下文模型，只靠词频和规则，同音字选错是预期内的，点候选能改，选过之后会记住。要进一步提高，需要更好的词频数据或者二元语言模型，这两样都得联网取数据。
