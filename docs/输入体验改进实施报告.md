# 墨语 3.0.10 输入体验改进实施报告

本次按 `docs/输入体验改进建议.md` 的四批顺序完成实现，改动直接保留在 `ime-experience` 工作区，没有提交、推送或切换分支。实现版本号未改。

本机是 Windows，没有 Swift 编译器和 iPhone。Python 评测、工程检查和 Swift 静态检查已在本机完成，Swift 编译、键盘扩展内存和逐键热态延迟仍需在 macOS CI 与真机复核。

## 评测口径

- 改前取当前分支改动前的 `moyu.dict`、`next.tsv` 和对应代码基线，Python 解码器保持同一打分口径。
- HOLDOUT 为 45 条，UNSEEN 为 50 条。长句盲集为冻结的 `tools/dict/long_sentence_blind.tsv`，共 27 条，中文长度 16–20 字，覆盖 18 条全拼、3 条简拼、3 条九宫格和 3 条中途选词后的余串。
- 长句逐字准确率按首选结果与目标字符串的同位置字符数比较，分母为目标字符总数。
- 续词评测来自 HOLDOUT 与 UNSEEN 的 317 个真实词段位置，分别报告“最后一个真实词”和“整段前缀”两种调用方式的前三命中。
- “修回旧错”表示改前首选错误、改后首选正确，“引入新错”表示改前首选正确、改后首选错误。

## 第一批

### 已实现

- `tools/dict/build_binary.py` 读取雾凇 base 的显式逐字音节，在连续拼音相同的情况下校正旧词表的边界，共修正 148 条。`可能`、`蛋糕`、`西安`、`反感` 的分隔分别回到 `ke'neng`、`dan'gao`、`xi'an`、`fan'gan`。
- 重新生成 `ios/Shared/dict/moyu.dict` 和 `ios/Shared/dict/dict_meta.json`。新词条 274,161 条，拼音键 210,285 个，二进制大小 14,498,026 字节。
- 九宫格在跨拼音键取候选后统一按词频、学习值和上下文重新排序，最多合并 48 个拼音键，并继续应用锁音和手动分隔过滤。
- `PhraseSuggestionIndex` 从最长触发后缀开始查询，命中“最近忙吗”时优先使用完整触发词。
- `IMEQuery` 增加可选 `leftContext`。`KeyboardSession` 组装余串时传入刚确认的真实末词，`PinyinEngine` 将它用于首块整句路径、余串首批候选和同音词排序。`bayaoshi` 先选“把”后，余串首选为“钥匙”。
- 全拼精确词条每键保留 40 条，简拼保留最多 60 个拼音键、每键 3 条，九宫格整句保留最多 48 个拼音键。候选合并按分数完成，减少提前截断造成的召回损失。

## 第二批

### 已实现

- 离线联想改为按词内补全、继续一句、句子已结束三类来源竞争。标点只在足够长的句子或问句、感叹句场景参与排序，不再固定占用前两位。
- `next.tsv` 保留真实词对次数和来源标记。`tN` 表示 Tatoeba 真实观测次数，`rN` 表示从雾凇短语推导的证据。`NextWordIndex` 以最长尾部词为锚点读取这些证据。
- 本人续写通过 `PinyinEngine.predictions` 直接走本地索引，不依赖 AI Key 或联网。AI 调度仍调用 `includeTemplates: false`，避免把回复别人的模板放到本人刚写完的文本后面。
- 整句候选通过 `IMEWordSegment` 保留真实词段和每段消费长度。学习、首词、末词和跨次词对均使用真实首末词。
- `KeyboardSession` 在已选段中保存锁音和分隔，退格恢复该段时一并恢复，余串重算时继续使用剩余锁和分隔。
- 九宫格回归从“包含喜欢或候选非空”改为实际名次断言，要求“喜欢”进入前 24 位。

## 第三批

### 已实现

- 动态规划在相同输入位置保留按前词区分的少量状态，最终输出最多 3 条文本不同的整句候选。句末“吗、吧、呢、啊”等语气词作为路径特征参与竞争，不再在解码完成后无条件改写。
- 新增 Python 实验脚本 `tools/dict/calibrate_bigram.py`。模型使用随包词库的整数词 ID，边使用 8 位量化权重，文件按排序后的边用 `mmap` 查询。
- 新增冻结开发集 `tools/dict/long_sentence_dev.tsv` 和独立盲集 `tools/dict/long_sentence_blind.tsv`，脚本对两份文件做 SHA-256 固定校验，防止校准后改动盲集。

### 开发集校准与独立盲集对比

开发集共 28 条。相同打分的多候选基线为首选 `9/28`、前三 `12/28`、逐字 `481/563`。选择二元权重 `0.125` 后为首选 `8/28`、前三 `12/28`、逐字 `481/563`，并引入 1 条回退。

盲集共 27 条。旧版首选 `6/27`、前三 `6/27`、逐字 `326/490`。只增加多候选后为首选 `7/27`、前三 `8/27`、逐字 `375/490`，修回旧错 1 条、引入新错 0 条。二元权重 `0.125` 的试验为首选 `6/27`、前三 `7/27`、逐字 `356/490`，相对多候选基线引入 1 条回退，净收益不为正。

### 未启用项

二元模型没有进入 Swift 或安装包。当前只启用多候选路径。`dict_meta.json` 和 `THIRD_PARTY_NOTICES.md` 已记录实验来源为雾凇 base 词典、许可证为 GPL-3.0、源摘要和未随包分发状态。这样模型数据和仓库 GPL-3.0 兼容，同时避免把没有盲集收益的重排带给用户。

## 第四批

### 已实现

- `UserLearningStore` 为词频、个人词和词对保存最近更新时间，读取时按 30 天半衰期懒计算衰减值。
- 显式点选使用强度为 1.0，空格或标点自动接受使用强度为 0.2。用户手动添加的词通过 pinned 标记保持优先，不受普通统计排序影响。
