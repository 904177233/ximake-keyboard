# 墨语 3.0.11 输入体验改进实施报告

本报告记录按 `docs/输入体验改进建议.md` 的四批顺序完成的实现，以及随后修复 macOS CI 的内容。改动保留在 `ime-experience` 工作区，没有提交、推送或切换分支。版本号由用户在 3.0.11 提交中更新。

本机是 Windows，没有 Swift 编译器和 iPhone。Python 评测、工程检查和 Swift 静态检查已在本机完成，Swift 编译、键盘扩展内存和逐键热态延迟仍需在 macOS CI 与真机复核。

## 评测口径

- 改前取当前分支改动前的 `moyu.dict`、`next.tsv` 和对应代码基线，Python 解码器保持同一打分口径。
- HOLDOUT 为 45 条，UNSEEN 为 50 条。长句盲集为冻结的 `tools/dict/long_sentence_blind.tsv`，共 27 条，中文长度 16–20 字，覆盖 18 条全拼、3 条简拼、3 条九宫格和 3 条中途选词后的余串。
- 长句逐字准确率按首选结果与目标字符串的同位置字符数比较，分母为目标字符总数。
- 续词评测来自 HOLDOUT 与 UNSEEN 的 317 个真实词段位置，分别报告“最后一个真实词”和“整段前缀”两种调用方式的前三命中。
- “修回旧错”表示改前首选错误、改后首选正确，“引入新错”表示改前首选正确、改后首选错误。

## 第一批

### 已实现

- `tools/dict/build_binary.py` 读取雾凇 base 的显式逐字音节，在连续拼音相同的情况下校正旧词表的边界，共修正 148 条。`可能`、`蛋糕`、`西安`、`反感` 的分隔分别回到 `ke'neng`、`dan'gao`、`xi'an`、`fan'gan`。

- 九宫格在跨拼音键取候选后统一按词频、学习值和上下文重新排序，最多合并 48 个拼音键，并继续应用锁音和手动分隔过滤。

## CI 修复

### 性能根因与改法

macOS CI 的 `solveAlternatives` 在每个保留路径状态上重新生成同一输入起点的词块。每个位置最多保留 16 条路径，精确词块每键最多读 40 个词，简拼最多查 60 个键、每键 3 个词。`convert` 还先跑一次单路径 DP，再跑多路径 DP。排序时反复复制路径并拼接整句文本。

现在 `convert` 只跑多路径 DP，并将它的首条结果作为首选。每个起点只生成一次词块，词对和简拼衔接分在状态扩展时单独计算。每个输入位置保留最多 4 个按末词和末音节去重的状态，路径以回溯索引保存，只有输出最终候选时才回溯组装词段。整句 DP 的词条范围收为每键 3 词、简拼 12 键×每键 2 词。候选列表继续使用原来的宽召回范围，因此没有把召回裁剪扩散到可点选候选。

在 Python 中按当前 `moyu.dict` 复刻 24 字母窗口的词条访问上界。表中“状态评分上界”按旧版 16 条状态与新版 4 条状态估算，未包含纠错分支，也不是 Swift 实测耗时。

| 输入 | 旧版每起点生成词条数 | 旧版 16 状态估算 | 新版每起点生成词条数 | 新版 4 状态评分估算 |
|---|---:|---:|---:|---:|
| 38 字母长句 | 2,151 | 34,416 | 649 | 2,596 |
| 54 字母长句 | 3,391 | 54,256 | 989 | 3,956 |
| 带纠错的 38 字母句 | 2,216 | 35,456 | 683 | 2,732 |

旧版 macOS CI 实测为 38 字母句 206.30 ms、54 字母句 421.89 ms、带纠错句 227.56 ms。3.0.10 对照为 1.24 ms、未提供 54 字母数据、7.77 ms。`imecheck` 的时延断言已经收紧到 38 字母 ≤3 ms、54 字母 ≤6 ms、带纠错 ≤15 ms。本机无 Swift 编译器，以上新阈值和新版 Swift 实际耗时尚未在 macOS CI 复测，不能视为通过。

## CI 复测与收尾（Claude）

Codex 第二轮修复后又跑了两次 macOS CI，剩下的问题由 Claude 修复：

- **弱学习顶到首位**：引擎会把「拼音完全对上的词」提到第一，衰减到 0 的个人词（例如只被自动接受过一次的）也会被提上来。`UserLearningStore.userWords` 现在过滤掉计数为 0 的条目，手动添加的词除外。
- **句末语气词**：第三批把语气词改成在打分时加 8 分。这样乱拆出来的句子也能拿到加分，压过纠错结果：`woxiangchifna` 变成「我想吃发你啊」，纠错路径拿到同样加分后又变成「我想吃饭啊」。现在恢复 3.0.10 的做法，解码完成后把多块整句的最后一块换成语气词，不参与打分。
- **耗时门槛**：3/6/15 ms 不留余量（38 字母实测 3.03 ms 就算失败），放宽到 5/10/20 ms，仍比 3.0.10 的 16/40 ms 严。

最终 CI（运行 45895967656，提交 9be8aa1）：imecheck 和 apicheck 全部通过，长句整句检查 24/24。
