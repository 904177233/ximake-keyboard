# 在线词库包

> 一句话：词库不再"装一次就定格"，而是一份**可以更新的静态词表**——只下载词表文件，**永不上传你输入的任何内容**。

## 0. 先说清楚「在线词库」的两种做法

「有没有联网词库」这个问题，行业里其实是两条完全不同的路：

| | **云候选**（搜狗 / 百度 / 微信开拼写 Plus 后） | **在线词库包**（本文实现的做法） |
|---|---|---|
| 上传什么 | **你正在输入的每个字**（含密码框、验证码、私聊内容） | **什么都不上传** |
| 下载什么 | 每次按键的候选结果 | 一份静态词表文件（约 0.8 MB） |
| 延迟 | 300–800 ms（等云端回来时本地候选早就显示完了，算力白花） | 0（本地查表） |
| 断网影响 | 云端候选不可用 | 完全不影响，回落到已下载的词库 |
| 需要后端 | 需要自建服务 + 带宽成本 | 到静态文件托管（GitHub + jsDelivr CDN） |

**墨语选后者。** 原因不是做不了云候选，而是：
输入法是最不该把内容传出去的 App——它能看到你在所有 App 里打的每一个字。为了几个百分点的候选命中率把这条底线交出去，不值。

代价也要说清楚：**在线词库包解决的是「词库太老/太少」，不是「猜你下一句」**。后者靠的是本地联想 + 你自己配置的 AI（那部分请求只发给你填的服务商，不经过我们）。

## 1. 它是怎么工作的

```
GitHub 仓库 ios/Shared/dict/
├── dict_manifest.json     ← 清单：版本、每个文件的 sha256 与字节数
├── base_dict.tsv          ← 基础词库（拼音 \t 词 \t 词频 \t flags）
├── chat_priority.tsv      ← 聊天高频词权重
└── dict_meta.json         ← 元信息（version / count / sha256）

        ↓ jsDelivr CDN（国内可达）
        ↓ https://cdn.jsdelivr.net/gh/904177233/ximake-keyboard@main/ios/Shared/dict/

键盘扩展启动 → 距上次检查 > 24h → 下载清单
            → 版本一致？结束
            → 版本不同 → 下载 3 个文件到 MoyuDict.staging
                       → 三层校验
                       → 全部通过才原子替换到 MoyuDict/
                       → KMInputEngine.reload() 重建内核（约 40–60 ms）
```

### 1.1 为什么下载发生在**键盘里**，不在宿主 App 里

这是免费签名带来的硬约束，也是很多人会踩的坑：

> **免费 Apple ID 签名没有 App Group。**
> 宿主 App 和键盘扩展是两个独立沙盒，各自有自己的 `Documents` / `Application Support`。
> 宿主 App 下载到自己的容器里，**扩展物理上读不到**。

所以真正生效的下载只有一条路：**在键盘扩展的进程里下载**，落在扩展自己的
`Library/Application Support/MoyuDict/`。而扩展只有在**开了「允许完全访问」之后才有网络权限**。

宿主 App 里那个页面（设置 › 语气与外观 › 在线词库包）下载的那份只用来看状态和手动触发，
**它不会、也没法让键盘用上**——页面脚注里写明了这一点，不误导人。

开了完全访问之后就一切正常；付费开发者账号启用 App Groups 后，两边会自动共享同一份。

### 1.2 为什么"改用设置页手动下载"不解决问题

因为扩展读不到宿主 App 的沙盒。哪怕是用户手动点的，文件也落在宿主的容器里。
唯一的绕法是 `UIPasteboard` 搬运河（把 0.8 MB 的词表塞进剪贴板）——这会污染用户剪贴板、
触发粘贴权限弹窗、且大文件会失败，**不做**。

## 2. 三层校验（宁可更新失败，也不能让用户开不了键盘）

每个文件必须同时通过：

1. **字节数**：和清单里 `bytes` 完全一致（挡住半截响应、被中间层改写的内容）
2. **SHA-256**：和清单里 `sha256` 完全一致（挡住篡改、截断、内容替换）
3. **词条数**：解析 `base_dict.tsv` 的实际行数与清单 `entryCount` 一致（挡住"哈希对但内容语义坏了"）

任何一层不过 → **整体放弃**，旧词库原样保留，键盘继续可用。这条是硬要求：
词库损坏会让用户"打不出字"，比"少了几个新词"严重得多。

### 2.1 原子替换

先全部下载到 `MoyuDict.staging/`，三层校验通过后才：
`删 MoyuDict/` → `staging rename 成 MoyuDict/`。
中途断网/断电，要么是旧的完整词库，要么是新的完整词库，不会出现半个。

## 3. 代码地图

| 文件 | 职责 |
|---|---|
| `ios/Shared/IMECore/DictionaryPack.swift` | 清单模型 `DictionaryPackManifest`、错误 `DictionaryPackError`（12 个 case，全中文）、`DictionaryPackStore`（检查/下载/校验/安装/回滚） |
| `ios/Shared/IMECore/PinyinDictionary.swift` | `candidateURLs()` 把 `DictionaryPackStore.shared.userDictionaryPath` 排在**最前**，没有就回落安装包内置 |
| `ios/Shared/IMECore/ChatPriority.swift` | 同上，`userChatPriorityPath` 优先 |
| `ios/AIKeyboardExtension/IME/KMInputEngine.swift` | 新增 `reload()`：丢掉 `IMEKit` 重新加载（词库是内存快照，不重建不生效） |
| `ios/AIKeyboardExtension/ViewModel/KeyboardViewModel+Dictionary.swift` | `scheduleDictionaryPackCheck()`：启动后静默检查，成功后 `reload()` |
| `ios/AIKeyboard/Settings/DictionaryPackView.swift` | 宿主 App 页面：来源 / 版本 / 条数 / 上次检查 / 手动检查 / 自动开关 / 清单地址 / 回滚 |
| `tools/dict/make_manifest.py` | 生成 `dict_manifest.json`（sha256 + bytes + entryCount） |

### 3.1 自动检查的三个必须点

```swift
func scheduleDictionaryPackCheck() {
    Task { [weak self] in
        let didCheck = await DictionaryPackStore.shared.autoCheckIfNeeded()
        guard didCheck else { return }
        await MainActor.run { [weak self] in
            self?.engine.reload()
            self?.dictionarySummary = self?.engine.diagnosticsSummary ?? ""
        }
    }
}
```

1. **不 `await` 挡首帧** —— 键盘扩展最硬的指标是"快得让用户无感"，任何网络请求都不能挡渲染。
2. **失败完全静默** —— 词库更新失败不影响打字，弹任何东西都是打扰。
3. **24 小时节流** —— `autoCheckIfNeeded()` 内部判断，所以每次唤起键盘调用它是安全的。

## 4. 发一个新版本词库（维护者操作）

```bash
# 1. 改词库（tools/dict/ 下的管线）
python tools/dict/build_dict.py

# 2. 重新生成清单（会打印新的 sha256 / 字节数 / 条数）
python tools/dict/make_manifest.py

# 3. 提交推送（jsDelivr 会按 @main 自动同步，几分钟内生效）
git add ios/Shared/dict && git commit -m "dict: vX.Y.Z" && git push
```

**注意**：`dict_meta.json` 的 `version` 必须改（如 `1.1.0` → `1.2.0`），否则客户端判断"已是最新"就跳过。
客户端比较的就是这个版本号。

### 4.1 自建词库服务器

页面里"清单地址"可以改成任意 `https://…/dict_manifest.json`。
清单里的 `url` 字段既可以写相对文件名（拼接清单所在目录），也可以写 `https://` 绝对地址。
**必须是 https**——App 没有开任何 ATS 例外。

## 5. 已知限制

1. **需要完全访问**：不开的话扩展没有网络，词库包永远停在安装包内置的那份。这是平台限制，不是 bug。
2. **首版清单与包内词库版本相同**（都是 `1.1.0`），所以装完第一次检查会说"已是最新"——这是正确行为；
   等维护者发 `1.2.0` 才会真的下载。
3. **jsDelivr 偶发不可达**：已内置 GitHub raw 兜底地址，依次尝试。
4. **不支持增量 diff**：三个文件合计约 0.83 MB，全量下载比实现 diff 的复杂度更划算。
5. **双端各下一份**：开完全访问后键盘自己会下载；宿主 App 那份不影响键盘（见 §1.1）。
