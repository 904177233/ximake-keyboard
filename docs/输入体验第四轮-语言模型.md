## 裁剪与复现

原始文件有 270,714 个一元项、4,789,953 个二元项和 2,189,434 个三元项。构建时取 ARPA 与当前词典中文词条的交集，另保留上游未知词。以 UTF-8 文本指纹排序后的下标作为两端共用的词 ID，构建时验证指纹唯一。相同词的不同读音共享 ID，热更新词或个人词查不到时退到未知词。词典自身的拼音、读音权重和用户学习数据继续生效。

剪枝依据估计的历史概率、该项的条件概率、删除后与低阶回退之间的绝对对数概率差。二、三元分别排序取预算，结果按历史词 ID 分行。条件概率与回退权重均用有符号 8 位量化，每格为 1/16 个 log₁₀ 单位。查不到三元时，先累加保留的历史二元回退权重，再查后两个词的二元概率。查不到二元时，累加一元回退权重和目标词的一元概率。被剪掉的历史没有单独保留回退权重。

## 解码与首位决策

- **全拼与九宫格。** 第三轮每个拼音键在全拼整句中仅保留前三个词，九宫格通常只取一个。新模型在全拼每键前八、九宫格每键前三中选词，每个位置仍最多保留四条路径。每个词块查一次 ID，不同前驱共用。路径扩展时同时考虑前两词。旧的常用词对固定加分和跨词拼字加分只供缺模型时回退。个人选择、词频、音节长度、简拼和单处编辑代价继续参与打分。句末语气词保留现有输出约定。[解码器](../ios/Shared/IMECore/PinyinEngine.swift) · [映射与回退查询](../ios/Shared/IMECore/LibimeLanguageModel.swift)
- **余串。** 用户已选词作为第一步的历史，系数 4，后续由引擎推断的历史系数 3。分数取条件概率相对一元概率的增量，正向增量封顶 2.5，再混入四分之一的一元先验，避免重复计算词典已有的词频。整键同音候选也读同一个模型。模型可用时，旧联想表不再把第一个命中的搭配无条件提首。用户显式选择仍有最高优先级。[首块与候选排序](../ios/Shared/IMECore/PinyinEngine.swift)
- **简拼。** 聊天简拼模型继续提供候选，将通用三元模型用于最终最多 24 条路径的重排，并保留口语模型的自然备选。整串一次命中一个简拼短语且该路径在词典搜索中胜出时，先给这个短语。例如 `wzdl` 得到「我知道了」。需要拼多个词时，聊天模型仍能给出「你在干什么」和「你吃饭了吗」。英文候选和个人显式改选沿用各自的首位规则。[简拼解码](../ios/Shared/IMECore/ChatInitialsModel.swift)
- **纠错。** 原串和改一处按键的路径共用语言模型与词块打分。整键精确命中、手动分隔和锁继续受保护。能切全拼、无整词命中、至多 18 个字母时允许比较，纠错路径须领先超过 2.5 分才可排第一，微弱正收益放在第四。含简拼碎块的原路径允许较低门槛，避免「和部门啊那个」一类拆法压过「很忙」。`xiexienu` 和 `taihaoke` 在 Python 中均纠对并排首选。`nihaohaoma` 保留自然前三，「你还好吗」仍可在第四位选到。[纠错比较](../ios/Shared/IMECore/PinyinEngine.swift)

## 内存、性能与待验证项

随包文件为 **10,927,756 字节（10.42 MiB）**，含 158,762 个词 ID（含未知词）、100 万二元项和 23 万三元项。Swift 通过只读 mmap 在排序数组上二分，不构造常驻词串表。按每页 16 KiB 追踪 Python 查询触及的去重文件页，38 字母、54 字母、带错键三条分别是 218、240、257 页，折合约 **3.41、3.75、4.02 MiB**。这是单次样例的模型页工作集估计，未计系统预读、已有词库、候选分配和跨多次输入累积驻留。文件页最多约 10.42 MiB，真机看扩展整体 footprint 及峰值。

- **macOS 日志**重点看各类首选是否全部达到 build 84，尤其是原先未过的正确全拼合计、四组错键，以及冻结长句首选、前三和逐字。查看干扰四项是否均为 0、三项时间是否守住 **5/10/20 ms**。上轮 Swift 热循环实测为 **0.94/1.21/7.24 ms**，本轮 Windows 无 Swift 编译器。
- **iPhone**重点看首次调起键盘后第一次输入与连续逐键的 P95、重复退格重输时的峰值内存，以及键盘是否因内存压力重载。CI 现有的三个时间门槛测的是多次转换的平均耗时。
