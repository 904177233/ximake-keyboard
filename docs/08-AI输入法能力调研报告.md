# 墨语 AI 输入法 · 能力缺口调研报告

> 调研时间：2026-10-25　｜　调研人：Lead　｜　版本：v1.0（只调研，不含代码改动）
> 调研问题：**作为一个 AI 输入法，墨语还缺什么？**

---

## 0. 一页速读（老板版）

**结论：墨语在「AI 能力」上已经超出市面 90% 的同类产品，但在「输入法本体」上有三处硬伤，其中一处会直接决定用户是否愿意长期用下去。**

| | 结论 | 一句话 |
|---|---|---|
| 🔴 **最该做的** | **语音输入（端侧听写）** | iOS 26 起 Apple **已经允许**键盘扩展调用麦克风了（2025 年之前是硬禁止）。这是输入法第一大刚需，而搜狗/百度/讯飞的差评里"语音识别不准"常年占榜首。**市场留了一个 1 年左右的窗口期**，先做的人吃红利。 |
| 🔴 **最该修的** | **AI 不要接管基础候选** | 搜狗 844 万评分的差评第一高频词就是「**越智能越不好用**」「AI 接管词库反而打错更多」。墨语的「智能联想」必须默认**只做增量、不动基础候选**，且**一键可关**。这条不做，功能越多骂得越狠。 |
| 🟠 **最该补的** | **云端词库 / 长尾词** | 墨语现在 5,276 条基础词 + 755 条短语。搜狗/百度是**千万级**。日常聊天够用，但一旦涉及专业词、人名、地名就会频繁打不出。这是「能不能当主力输入法」的分水岭。 |
| 🟢 **加分项** | 端侧 AI（Apple Foundation Models）、剪贴板技能、皮肤/高度自定义 | 有则更好，没有也不致命。 |

**一句话策略**：**先把"输入法"做好，再谈"AI"**。当前墨语的 AI 部分已经是长板，短板全在打字本身 —— 词库规模、语音输入、候选准确率。

- ❌ **语音输入 / 听写**（最大缺口，详见 §5.1）
- ❌ 九宫格 T9 的「词库级」联想（9 键布局有，但词库深度远不及大厂）

- ❌ 皮肤 / 主题商店 / 按键音 / 动效定制
- ❌ 手写输入 / 笔画输入 / 五笔
- ❌ 滑行输入（Glide Typing）
- ❌ 剪贴板「技能」（自动识别待办、日程、地址）
- ❌ 端侧 AI 调用（Apple Foundation Models 完全没用）
- ❌ 多语言（只有中文 + 英文基础）

## 4. 真实用户差评分析（最有价值的一手资料）

抓取每家 100 条最新评论，人工归类后得到 6 类高频痛点，**按出现频次排序**：

### 4.1 🔴 「AI 接管词库，反而越打越错」（搜狗差评第一）

> 原文摘录：
> - 「越智能越不好用……打一句话二十来个字里边能有 6、7 个错别字，且这几个错别字根本不是我拼音拼出来打错的，而是**智能联想优化后蹦出来的**」
> - 「**为什么要让 AI 接管我的输入法？**……10 个字里一半都是错的……就不能让客户自主选择是否接受 AI 吗」
> - 「nanyong 打出来第一个词条是男用」
> - 「以前打的都有记忆，现在和智障一样」（常用词记忆丢失）

**对墨语的启示（P0 级）**：
1. **基础候选永远不能被动**。AI 只能在候选栏**右侧的独立区域**给联想，不能插进拼音候选里。
2. **必须有一键关闭**（墨语已有：键盘设置里的「模糊音」开关是范例，联想也应该有独立开关）。
3. **AI 联想失败必须完全静默**（墨语已做到，规范里写死了）。
4. 墨语当前设计**恰好是对的** —— 联想胶囊在候选栏尾部独立展示，不污染 `candidates[]`。这条要点写进报告是为了**守住底线，别在后续迭代里被"优化"掉**。

### 4.2 🔴 键盘弹不出来 / 弹出来卡住（4 家全有）

> 「老是弹不出来打字窗口」「弹半天弹出来，有时候刚弹出来还不能点」「频繁闪退」

**对墨语的启示**：这正是我们刚修的两个 P0（无限递归闪退 + 布局溢出）。**键盘扩展的启动速度和内存必须当成一等指标**：
- 大厂的做法（OSGKeyboard 实测源码）：**键盘启动时按需加载引擎，键入过程中持续采样内存，在 40 MiB / 48 MiB 阈值主动释放**中文引擎、英文词库与在飞任务；正在拼字时推迟重度释放。
- iOS 26 起可接 **MetricKit**，把键盘扩展的**内存回收（`0xdead10cc`）**、崩溃、卡顿记在本机诊断页 —— 这类问题在 App Store Connect 里**不会显示为崩溃**，不看就永远不知道。
- 墨语当前没有内存采样、没有 MetricKit 接入。

### 4.3 🟠 键盘上方卡出一大片空白（搜狗/讯飞都有）

> 「键盘上方卡 bug，卡出一大片空白，有圆边」「输入框上方半个屏幕空白，空白半年多了」
> 讯飞官方回应：「**iOS 缺失：光标搭子、发照片**（系统限制）」

**对墨语的启示**：这正是我们刚修的对话面板高度 bug（438 vs 340）。**高度必须严格等于 `KMLayout.keyboardHeight`，任何多出来的 1pt 都会被用户看成"空白 bug"**。已在 `design/04` §3.11 写死四段分区，后续改动必须过 `ipa_layout_check` + 视觉验收。

### 4.4 🟠 iOS 27「液态玻璃」不适配（搜狗差评）

> 「什么时候工具栏能和百度输入法一样适配液态玻璃效果，现在除了默认皮肤其他个性皮肤工具栏上都有一道横杠」

**对墨语的启示**：iOS 26 引入 Liquid Glass 后，**键盘作为系统 UI 的一部分，用户会拿它和系统键盘对比**。墨语目前用的是自定义 `KMGlassSurface`（`.ultraThinMaterial`），在 iOS 26+ 上观感会和系统键盘有差异。**属于中期优化项，不急**。

### 4.5 🟠 广告 / 内置内容引反感（讯飞/百度）

> 「一个输入法打开竟然有各种广告…半夜突然出声」「一个输入法内还内置视频内容，有病」

**对墨语的启示**：**这是墨语最大的差异化机会** —— 零广告、零后端、不收集数据。这个卖点要在 App 首页和引导里**说三遍**，因为用户被大厂伤透了。

### 4.6 🟢 细节体验缺失（长按空格移光标、滑行输入、单手模式）

多家的差评里都有「长按空格移动光标缺失」「滑动输入缺失」。这些是**输入法基本功**，实现成本不高但感知强。墨语目前都没有。

## 5. 技术边界（Apple 到底允许键盘扩展做什么）

### 5.1 ⭐ 最重要发现：iOS 26 起，键盘扩展**可以**用麦克风了

**历史结论（2014 年 Apple 文档原文）**：
> "Custom keyboards, like all app extensions in iOS 8.0, have **no access to the device microphone**, so dictation input is not possible."

**2026 年现状（开源项目 OSGKeyboard 源码实证）**：
```xml
<!-- OSGKeyboardExt/Info.plist -->
<key>NSMicrophoneUsageDescription</key>
<string>OSGKeyboard uses the microphone for voice dictation...</string>
<key>NSSpeechRecognitionUsageDescription</key>
<string>OSGKeyboard uses speech recognition to transcribe your voice...</string>
<key>RequestsOpenAccess</key><true/>
```
并且它已经在 App Store 上线（iOS/iPadOS **26+**），默认用 **Apple `SpeechAnalyzer` + `DictationTranscriber` 端侧识别**，音频默认不出设备。

**这条路技术上完全可行，而且给了墨语一个罕见的时间窗口**：
- 大厂（搜狗/百度/讯飞）在 iOS 上做语音，一直受"键盘不能录音"限制，只能跳转 App。
- 端侧识别 + 键盘内直接上屏，是**体验上的代差**。
- 中文端侧识别质量：Apple 的 `DictationTranscriber` 在 iOS 26 已支持中文，但专业词/长句不如云端。可做**端侧优先 + 云端可选**（用户自己填服务商）。

**实现要点**（从 OSGKeyboard 源码学到的最佳实践）：
1. **可用性要做成枚举，不是一句错误**：`hasCompletedOnboarding → appGroupAvailable → hasFullAccess → micDisabled → isPreparingSession → hostReady`，任一不满足都给具体原因（`.noFullAccess` / `.appGroupUnavailable` / `.hostNotReady` / `.preparingSession` / `.onboardingIncomplete`）。这样用户知道"为什么不能用"。
2. **完全访问是硬前提**（`RequestsOpenAccess` 必须为 true，且用户要在设置里打开）。
3. **App Group 必须可用**（这条对墨语是**致命的**：免费签名没有 App Group，见 §6.1）。

### 5.2 其它硬限制（2014 文档，至今仍有效）

| 限制 | 说明 | 对墨语的影响 |
|---|---|---|
| **不能选中文本** | "a custom keyboard can draw only within the primary view... **it cannot select text**" | 墨语的「润色/扩写」只能作用于**刚输入的文本**或用户手动粘贴的上下文，不能"选中一段话改写"。**这是行业共同限制**，须在 UI 上说明白。 |
| **安全输入框强制换回系统键盘** | `secureTextEntry` / `UIKeyboardTypePhonePad` / `NamePhonePad` | 密码框、电话框里墨语不可用 —— 正常，但引导里要提。 |
| **宿主 App 可禁用第三方键盘** | `application:shouldAllowExtensionPointIdentifier:` 返回 false | 银行/医疗类 App 里墨语不出现。这是**用户流失的隐性原因**，FAQ 里要写。 |
| **不能画到键盘主视图之外** | 候选栏、对话面板**必须都在键盘高度内** | 墨语已遵守（438 = 258+180，全在键盘内）。**"弹出式浮层"在这条限制下做不了**，只能内嵌。 |
| **必须提供切换键盘键** | `needsInputModeSwitchKey` 为 true 时必须给，调 `advanceToNextInputMode()` | 墨语已有 🌐 键。**无 API 能枚举或指定目标键盘** —— 所以"一键切回搜狗"做不到。 |
| **无按键预览** | 系统键盘长按弹出的大字预览做不到 | 墨语现在是长按候选，没有按键预览。可接受。 |
| **宽度由系统决定** | 永远等于屏幕宽 | 横屏布局必须自适应（墨语已做 200→340）。 |

### 5.3 完全访问（`RequestsOpenAccess`）能力对照（Apple Table 8-1）

| 能力 | 关闭（默认） | 开启 |
|---|---|---|
| 基础键盘 / `UILexicon` 公共词库 / 文本替换 | ✅ | ✅ |
| **与宿主 App 共享容器（App Group）** | ❌ | ✅ |
| 除自身容器外访问文件系统 | ❌ | ✅ |
| **把击键数据发到服务器处理** | ❌ | ✅ |
| 定位 / 通讯录（需授权） | ❌ | ✅ |
| 参与 iCloud / Game Center / IAP | ❌ | ✅ |
| **麦克风（iOS 26+）** | ❌ | ✅ |

**开发者责任（Apple Table 8-2，写进 App Store 审核要求）**：
- 不得把词库当非私有数据外传
- 不得存储击键/语音数据超出提供服务所需
- 不得把用户身份与网络热词关联
- 不得后台使用定位

> 墨语当前是"不给完全访问也能用"的设计 —— 这点很干净，但**代价是拿不到 App Group，也就拿不到语音、共享容器、扩展↔App 实时通信**。详见 §6.1。

### 5.4 Apple 端侧 AI 的可用版本（实测 `developer.apple.com` JSON）

| 框架 | 平台 | 能力 | 对墨语的价值 |
|---|---|---|---|
| **Foundation Models** | iOS 26.0+（已有 26.0–26.3 / 26.4 / 27.0 三个模型版本） | 摘要、实体抽取、文本图像理解、**改写**、对话、创意生成；`@Generable` 引导式生成、**工具调用**、动态档位、会话转写 | ⭐⭐⭐⭐ **润色/扩写/翻译可以完全端侧跑**，零 API Key、零延迟、零费用、绝对隐私。**取决于设备是否支持 Apple Intelligence**（不是所有 iPhone 都行）。 |
| **SpeechAnalyzer** | iOS 26.0+ | 模块化语音分析；`DictationTranscriber` 只做语音转文字；异步、需要先装 assets | ⭐⭐⭐⭐⭐ 语音输入的核心 |
| **MetricKit** | iOS 26+ 起支持键盘扩展 | 崩溃/卡顿/CPU/磁盘/**内存回收诊断** | ⭐⭐⭐ 诊断页升级 |

**建议**：Foundation Models 做「端侧优先，服务商兜底」的两级 AI —— 润色/翻译这种短任务先用端侧，失败了或用户配了更强模型再走云。这条能**同时做到零成本和绝对隐私**，是大厂做不到的（他们的模型在自家服务器）。

## 6. 关键风险（必须先解决的）

### 6.1 🔴 免费签名 = 没有 App Group = 语音功能做不了

这是**最硬的约束**，必须让用户知道：

| 能力 | 免费 Apple ID（当前） | 付费开发者账号（$99/年） |
|---|---|---|
| App ↔ 键盘扩展共享数据 | ❌（`SharedStore` 降级到 `UserDefaults.standard`，进程隔离） | ✅ |
| 扩展心跳/诊断上报给 App | ❌（App 侧永远显示"没有使用记录"） | ✅ |
| **键盘内语音输入**（需 App Group + 完全访问） | ❌ | ✅ |
| 键盘内配置（自己填 Key） | ✅（走扩展自己的 Keychain） | ✅ |
| 有效期 | **7 天**，必须重签 | 1 年 |

**结论**：**语音输入这个最大机会点，免费签名做不了**。要么让用户买开发者账号（$99/年），要么放弃语音。
> 这个决策**必须问用户**，不是技术能绕过的。

### 6.2 🟠 词库规模是"能不能当主力"的分水岭

墨语：5,276 条基础词 + 755 条短语 + 用户学习。
搜狗/百度：**千万级**（含网络热词、专业词、地名、人名）。

日常聊天够用，但：
- 打专业术语（"榫卯""拓扑排序""耦合"）大概率打不出
- 打人名/地名（"郫县""亳州""单县"）大概率打不出
- 打新词/网络梗（"班味""city不city"）肯定打不出

**建议**：从开源词库扩充到 **3–5 万条**（jieba 原始词典有 34.9 万条，可以做裁剪）。体积增加约 1 MB，成本极低，收益极高。**这是投入产出比最高的一项。**

### 6.3 🟠 「完全访问」是功能门槛，不是可选项

墨语现在设计成"不给完全访问也能打字 + 配 AI"，很干净。但要做语音、要做剪贴板全量、要做 AI 客户端直连，**必须**让用户开完全访问。
- 现状：`AI 可用性` 已被建模成 `AIAvailability` 枚举（`.noFullAccess` / `.notConfigured` / `.offline` / `.busy`），这是对的。
- 缺的是：**引导用户去开完全访问的具体路径**（现在只有一张提示卡，没有"怎么开"的图文）。

## 8. 不建议做的（明确的"不做"清单）

| 功能 | 为什么不做 |
|---|---|
| **云同步 / 账号体系** | 与"零后端、不收集数据"的核心卖点冲突；且免费签名没有 App Group，同步了也白同步 |
| **皮肤商店 / 付费皮肤** | 大厂靠这个赚钱，但墨语用户少、且会引入审核负担。极简就是差异化 |
| **内置视频 / 内容流** | 百度差评里"输入法里内置视频内容，有病" —— **这是负资产，不是功能** |
| **广告 / 会员** | 同上，且与"零后端"矛盾 |
| **自建大模型服务** | 需要 GPU 成本 + 合规，且用户已经能自己填服务商。**保持 BYOK 才是对的** |
| **替代系统键盘做"全局改写"** | iOS 不允许选中文本，做不到（行业共同限制） |

## 9. 建议路线图

### 第一步（1 周）：把"输入法"做扎实
1. 词库扩到 3–5 万条（P0-2）
2. 完全访问引导图文（P0-4）
3. 长按空格移光标（P1-3，半天就够）

### 第二步（2 周）：稳定性与诊断
4. 键盘内存采样 + 主动释放（P0-3）
5. MetricKit 接入诊断页
6. 真机长跑测试（连续打字 30 分钟不崩、不涨内存）

### 第三步（决策点）：语音输入
7. **先问用户：愿不愿意买 $99/年开发者账号？**
   - 愿意 → 做语音（P1-1），这是最大的差异化
   - 不愿意 → 跳过语音，转做端侧 AI（P1-2）+ 剪贴板技能（P1-4）

### 第四步（中期）
8. 端侧 AI 润色/翻译（若设备支持）
9. Liquid Glass 适配
10. 双拼方案

## 11. 一句话总结

> **墨语的 AI 已经是长板，短板全在"输入法"本身。**
> 最该做的不是再加 AI 功能，而是：**①把词库扩 10 倍 ②把键盘做稳 ③然后赌一把语音输入**。
> 语音这条路 iOS 26 才刚开门，大厂还没跟上，是墨语唯一可能"弯道超车"的机会 —— 但它需要 $99/年的开发者账号。**这个决定得你来拍。**
