# 墨语 · 模块化与开放接口设想

> 状态：**设想，还没开始做**。写于 2026-11-08，3.0.6 之后。这里记下想做成什么样、为什么这样设计、怎么分步做，方便以后实现和讨论。

## 想解决什么

现在墨语的功能都写死在代码里：工具栏的润色、翻译、回复、扩写、画图是固定的；主题只有内置的六套颜色；词库是构建时生成的一个文件。用户想加一个「改成周报格式」的按钮、换一套自己做的皮肤、加一份专业词库，都得改代码、重新编译、重新侧载。

目标：**用户不改代码、不重新编译，就能往输入法里加自己的工具、皮肤和词库，并且能把它们分享给别人。** 键盘里的 AI Agent 也能用这些工具。

## 先说限制

这几条决定了整个设计：

1. **键盘扩展不能下载并运行新代码。** 苹果的规则和系统机制都不允许（没有 JIT，也不能加载外部可执行代码）。所以扩展只能是「声明式」的：一份配置，加上可选的 HTTP 接口，由墨语自己的代码去解释执行。
2. **键盘扩展内存很少**（几十 MB）。词库不能整个读进内存，导入的词库也要先编译成和内置词库一样的内存映射格式。
3. **键盘扩展要「完全访问」才能联网。** 调用外部接口的工具在没开完全访问时不可用，要明确提示。
4. **App 和键盘之间共享数据不一定打通**（免费签名没有 App Group）。导入在宿主 App 里做，再经现有的共享通道（App Group / 钥匙串访问组 / `SharedBlob`）交给键盘。

声明式也是好事：一个扩展能做什么、会把文字发到哪个地址，全写在配置里，用户导入前能看见。

## 三类扩展

### 1. 工具（Tool）

工具出现在键盘的工具栏里，也能被 Agent 在对话中调用。

现有的 `PromptTemplate`（[ios/Shared/Prompts/PromptTemplate.swift](../ios/Shared/Prompts/PromptTemplate.swift)）已经是可序列化的「提示词 + 占位符」结构，工具会在它的基础上扩展。设想的格式：

```json
{
  "schema": "moyu.tool/1",
  "id": "com.example.weekly-report",
  "title": "改成周报",
  "icon": "doc.text",
  "input": "selection_or_before_cursor",
  "action": {
    "type": "llm",
    "system": "把用户的文字整理成周报：本周完成、问题、下周计划，每条一行。",
    "user": "{{text}}",
    "model": "default"
  },
  "output": "replace",
  "agent": {
    "description": "把一段工作记录整理成周报格式",
    "parameters": { "text": "要整理的文字" }
  }
}
```

- `input`：工具拿什么文字。光标前的文字、选中的文字、剪贴板，或者不拿。
- `action.type`：
  - `llm`：用用户配置的模型跑一段提示词（不需要额外接口，最常见）；
  - `http`：把文字发到用户自己的接口（自建知识库、查快递、内部系统），配置里写明地址和要带的字段；
  - `template`：不调 AI，纯文本模板替换（日期、签名、常用回复）。
- `output`：替换原文、插入到光标处、在面板里显示、复制到剪贴板。
- `agent`：可选。写了就会作为一个工具交给对话里的 Agent，Agent 自己决定什么时候调用。

`http` 类型的安全规则：

- 导入时列出这个工具会访问的所有域名，用户确认后才启用；
- 只允许 HTTPS；
- 工具拿不到 API Key 和其它工具的数据，只能拿到 `input` 声明的那部分文字；
- 每次调用在面板里显示「发往 example.com」。

### 2. 皮肤（Skin）

现在的颜色都来自 `MoyuPalette`（[ios/Shared/Theme/MoyuTheme.swift](../ios/Shared/Theme/MoyuTheme.swift)），键盘界面没有裸色值，这是做皮肤的基础。设想的格式：

```json
{
  "schema": "moyu.skin/1",
  "id": "com.example.sakura",
  "title": "樱花",
  "light": { "accent": "#E8A0B4", "background": "#FFF7F9", "key": "#FFFFFF", "keyText": "#3A2A30", "functionKey": "#F3DDE4" },
  "dark":  { "accent": "#E8A0B4", "background": "#1E1A1C", "key": "#2C2628", "keyText": "#F2E8EB", "functionKey": "#3A3134" },
  "keyShape": { "cornerRadius": 8, "gap": 6, "shadow": false },
  "font": "system-rounded",
  "mascot": "mascot.png"
}
```

皮肤包是一个 zip（配置 + 小形象图片）。只改外观，不改按键布局和行为。加载时检查对比度，看不清的颜色组合会提示。

### 3. 词库（Dictionary）

现在的词库是构建时生成的内存映射二进制文件（`MoyuDictionary`），用户自己选的词在 `UserLearningStore` 里。导入的词库：

- 支持简单的文本格式（`词<TAB>拼音<TAB>词频`），以及常见输入法的词库格式（例如 Rime 的 `.dict.yaml`）；
- 在宿主 App 里编译成和内置词库相同的二进制格式，键盘只读编译好的文件，不在键盘里解析文本；
- 可以单独开关、调权重（专业词库排在通用词前面还是后面）；
- 整句转换时和内置词库一起参与（多个词库按权重合并查询）。

## 怎么分享和导入

- 扩展打包成一个文件（`.moyu`，本质是 zip），在宿主 App 里通过「文件」导入、链接导入或扫码导入；
- App 显示扩展的说明：会读哪些文字、访问哪些域名、用哪个模型，用户确认后安装；
- 以后可以在本仓库里放一个社区扩展目录（一个 JSON 索引 + 每个扩展一个文件夹），用 PR 收录。

## 代码上要先做的拆分

1. **工具注册表**：把现在写死的润色、翻译、回复、扩写、画图改成「内置工具」，和用户工具走同一套注册、显示、执行流程。
2. **Agent 工具调用**：对话现在的联网搜索和画图是写死的判断（`WebSearch.looksTimeSensitive`、`looksLikeDrawing`）。改成把工具描述交给模型，用 function calling 让模型决定调用哪个；不支持 function calling 的服务商退回现在的规则判断。
3. **皮肤**：`MoyuPalette` 改成可以从配置构造，键盘读当前皮肤。
4. **词库层**：`MoyuDictionary` 外面包一层「多个词库按权重合并」的查询接口，引擎只认这一层。
5. **扩展存储**：在 `SharedStore` / `SharedBlob` 之上加一个扩展仓库，App 写、键盘读。

## 分几步做

| 阶段 | 内容 | 做完能干什么 |
|---|---|---|
| 1 | 工具注册表 + `llm` / `template` 两种工具，在 App 里用表单创建 | 用户自己加提示词工具 |
| 2 | 皮肤配置 + 导入导出 | 换皮肤、分享皮肤 |
| 3 | 文本词库导入 + 编译 + 多词库合并 | 加专业词库 |
| 4 | Agent 用 function calling 调用工具 | 对话里自动用用户的工具 |
| 5 | `http` 工具 + 域名授权 | 接自己的服务 |
| 6 | `.moyu` 打包格式 + 社区扩展目录 | 分享和收录扩展 |

每一步都要有对应的测试：工具配置的解析和执行进 `tools/apicheck`（假服务器），词库合并进 `tools/imecheck`。
