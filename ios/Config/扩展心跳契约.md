# 键盘扩展心跳键 · 跨模块接口契约

> 本文件由 **ios-skeleton** 维护，是 `ios/Config/` 里唯一的「运行时接口契约」（其余文件都是构建配置）。
> 它约束的是 **键盘扩展侧写入 / 宿主 App 侧读取** 的两个 `UserDefaults` 键，因为这条链路跨了两个 target
> 和两个智能体的代码，不写下来一定会对不上。
>
> 相关实现：
> - 写入端（扩展）：`ios/AIKeyboardExtension/ViewModel/KeyboardViewModel+Access.swift`
> - 读取端（App）：`ios/AIKeyboard/Support/SharedBridge.swift` 的 `enum ExtensionTelemetry`
> - App 侧说明：`ios/AIKeyboard/README.md` 的心跳表

---

## 1. 两个键

| 键名 | 类型 | 写入时机 | 语义 |
|---|---|---|---|
| `moyu.ext.lastActiveAt` | `Double`（Unix 秒，`timeIntervalSince1970`） | 键盘扩展**每次被唤起**（`KeyboardViewModel.activate()`，由 `KeyboardViewController.viewWillAppear` 触发） | 「键盘最近一次真的被打开过」 |
| `moyu.ext.lastNetworkOKAt` | `Double`（Unix 秒，`timeIntervalSince1970`） | 扩展内**任意一次 AI 请求成功返回**（文本生成完成 / 生图完成） | 「扩展最近一次联网成功」= 强证据「完全访问已开启」 |

两者都是**单调递增的绝对时间戳**，不是相对时间，也不是 Bool。读取端自己算「多久以前」。
值为 `0` 或键不存在 = **从未发生过**（读取端必须把它当作 `nil`，不能当作「1970 年用过」）。

---

## 2. 必须走 `SharedStore`，不要直接摸 `UserDefaults`

两侧都**必须**通过 `SharedStore.shared` 读写：

```swift
// 扩展侧（写）
SharedStore.shared.setDouble(Date().timeIntervalSince1970, forKey: "moyu.ext.lastActiveAt")

// App 侧（读）
let raw = SharedStore.shared.double(forKey: "moyu.ext.lastActiveAt", default: 0)
let date: Date? = raw > 0 ? Date(timeIntervalSince1970: raw) : nil
```

原因：`SharedStore` 在**没有 App Group**（免费账号的默认状态）时会给键自动加 `moyu.shared.` 前缀
来隔离命名空间。如果一边用 `SharedStore`、另一边直接 `UserDefaults.standard.set(..., forKey: "moyu.ext.lastActiveAt")`，
在「App Group 可用」的情况下碰巧能读到，在「App Group 不可用」的情况下**永远读不到**——
这种 bug 只在真机上暴露，非常难查。

`SharedStore` 的读写 API 见 `ios/Shared/Storage/SharedStore.swift`：
`set(_:forKey:)` / `setDouble(_:forKey:)` / `double(forKey:default:)` / `setBool` / `integer` / `data` 等。
键名不要写字面量，用常量（扩展侧 `KeyboardViewModel.heartbeatActiveKey` /
`heartbeatNetworkOKKey`，App 侧 `ExtensionTelemetry.heartbeatKey` / `networkOKKey`）。

## 3. ⚠️ 已知物理限制：没有 App Group 时，心跳跨不了进程

这是**平台限制**，不是代码 bug，必须让产品侧和诊断页的文案知道：

`SharedStore` 的三级降级策略是
① App Group → ② `UserDefaults.standard` → ③ 内存字典。
免费 Apple ID 签名**不支持 App Group**（见 `docs/01` §6），所以实际落到 ②：

- ② 的 `UserDefaults.standard` 是**按进程隔离**的沙盒文件。
- 键盘扩展进程写进去的 `moyu.ext.lastActiveAt`，**宿主 App 进程读不到**；
  反过来 App 写的心跳扩展也读不到。
- 结论：**在免费签名下，宿主 App 的诊断页永远会显示「还没有检测到使用记录」**，
  走的是「不确定就说不确定」的安全降级分支（这是 `ExtemsionTelemetry` 刻意的设计，不会崩溃、不会误报）。

### 什么时候这条链路才会打通

只有用户升级为付费 Apple Developer Program，并按
`ios/Config/AIKeyboard.entitlements.appgroup.sample` 打开 App Groups 之后，
`SharedStore` 才会自动升到 ①，心跳无需改任何代码即可跨进程生效。
（`gen_xcodeproj.py` 不需要改；只需把两个 entitlements 换成带 App Group 的版本。）

### 如果产品上非要让免费账号也能看到「用过」

唯一可行的替代路径是**命名剪贴板**（`UIPasteboard(name: "com.moyu.config", create: true)`，
见 `ios/Shared/Storage/PasteboardBridge.swift`）：扩展在 `viewWillAppear` 时把时间戳写进剪贴板的一个专用键，
App 侧读出来。代价是：

- 每次唤起键盘都要写一次剪贴板（有轻微开销，且会覆盖命名剪贴板里的其他内容）；
- 需要先定义信封格式并和 `PasteboardBridge` 的 `MOYU_CONFIG_V1` 信封共存/分流。

**当前结论：不做。** 免费签名下诊断页就诚实显示「无法确认」，并给「如何确认」的分步指引，
这比伪造一个可能出错的心跳更符合本项目「不糊弄用户」的基调。如果后续决定要做，
改动点是 `PasteboardBridge` 加一个 `heartbeat` 频道 + 两端读写，不涉及工程结构。

## 4. 改动这条契约时的检查清单

1. 改键名 = 改契约。必须同时改：扩展侧常量、App 侧 `ExtemsionTelemetry` 常量、
   `ios/AIKeyboard/README.md` 的心跳表、本文件。
2. 不要新增第三个心跳键而不更新本文件—— App 诊断页只读这两个。
3. 两侧都必须用 `SharedStore`，不许混用 `UserDefaults.standard` 字面量。
4. 改完之后跑 `python scripts/gen_xcodeproj.py`（源码变了就要重新生成工程），
   再跑 `python scripts/validate_project.py` 与 `python scripts/qa/project_check.py`。
5. 本文件不参与构建（只是一个 `.md`），不会进任何 target 的 Resources。
